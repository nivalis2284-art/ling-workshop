# 执行：自主解决问题，维持工程与文档一致

## 实施自主权

以任务目标、风险和验收条件为核心，自主选择步骤、技术方案、必要关联文件、工具与协作方式。无需拘泥于计划早期猜测的文件清单；普通技术调整无需反复请示。

重大产品取舍、超出授权范围、无法恢复的高影响操作须确认；尊重用户数据、密钥、现有未提交改动与远端状态。

## 验证与交付

视风险运行相关测试、静态检查、真实环境验证。说明已验证、未验证和残余风险，不伪造结果。逻辑清晰地提交，推送遵守授权与分支规则；避免无意义的机械提交。

## 文档联动（必须保证结果）

- **改了架构/入口**：更新 `docs/地图.md`。
- **阶段进度/验收变化**：更新 `docs/里程碑/当前里程碑.md`。
- **正式计划发生替换**：归档旧的 `docs/计划/计划.md` 后写入新计划。
- **正式审查轮次更换**：归档旧的 `docs/审查记录/审查.md` 后记录新审查。
- **长任务结束/交接状态实质变化**：更新 `docs/交接.md`。
- **里程碑完成**：按 `milestone` Skill 将相关历史整包归档。

更新的是相关信息，不要求每次提交都刷新全部文档。文档正文用中文、Markdown 标题与相对路径；避免机器特有绝对路径进入仓库。文档历史不得为了省事直接覆盖或删除。
