# 交接：怎么读、怎么写

## 它是什么

`docs/交接.md` 是「一页纸的最新交接」——让下一个 AI（或换工具之后）无缝接上。它**只保留最新一份、随时覆盖**，是「换 AI 不乱」的关键工具。

## 什么时候读（恢复流程）

1. 读 `docs/地图.md`（项目是什么）；
2. 读本文件（做到哪、下一步）；
3. 看一眼 `git status`——有没有上次留下的未提交改动；
4. 按「下一步」开工；有疑问先问所有者，别猜。

## 什么时候写（覆盖）

- 一轮工作结束时；
- 更换开发工具 / 模型前；
- 上下文即将超限、需要另起会话时；
- **预感要中断时提前写**——写一句话的时间，能省下一个会话的重猜。先保存、再建议换会话，不要等断线了才想写。

## 写的时候别漏（状态转储清单）

- **做到哪**：当前进展；关联的里程碑 / 阶段与状态；
- **下一步**：接下来该做什么，按优先级；
- **注意什么**：坑、边界、待确认事项；
- **已试与假设**（排查中 / 复杂工作时）：试过什么没成、当前猜测是什么；
- **未提交的改动**（若有）：写清去向，避免下一个会话误删误提交。

## 格式骨架

```markdown
# 交接

> 最新工作交接——只保留一份、随时覆盖。

## 做到哪
（当前进展；关联的里程碑 / 阶段与状态）

## 下一步
（接下来该做什么，按优先级）

## 注意什么
（坑、边界、待确认事项）

## 已试与假设
（可选：排查中 / 复杂工作时填写——试过什么、当前猜测）

## 事实证据
（最近的提交号、恢复点标签、关键命令）
```

## 写法要求

- **说人话、写事实**：提交号、命令、文件路径直接写。
- **不重复**：地图、里程碑里已有的信息用链接指向，不抄。
- **宁短勿长**：一屏能读完最好；细节留给对应文档。

## 检查清单

- [ ] 走的时机没错过（结束前 / 换工具前 / 将满前）
- [ ] 五样没漏：做到哪 / 下一步 / 注意什么 / 已试与假设 / 事实证据
- [ ] 未提交的改动有交代（若有）
