# 项目地图：怎么读、怎么写

## 它是什么

`docs/地图.md` 是整个项目的「结构地图」——回答「项目长什么样、东西在哪」。任何 AI 接手项目时（读完根目录 `AGENTS.md` 之后）先读它。它只在结构变化时更新，平时保持稳定。

## 什么时候读

- 接手项目的第一步（与 `docs/交接.md` 一起读）；
- 需要确认技术栈、代码结构、数据流、当前状态、关键入口时。

## 什么时候更新

- 项目结构变化：新增 / 移除代码模块、目录调整、入口变化、技术栈换代；
- 里程碑完成时：刷新「当前状态」一节（见 `.agents/skills/milestone/SKILL.md`）。

## 怎么收集信息（扫描维度）

维护地图时按这几维核对现状，**以代码为准**（不凭记忆、不抄旧文）：

1. **结构**：`src/lingnexus/` 与 `frontend/src/` 的目录与模块——有没有新增 / 消失的；
2. **入口**：后端组合根、HTTP 接口、桌面启动、数据库迁移、前端入口——逐一确认路径存在；
3. **依赖与版本**：`pyproject.toml`、`frontend/package.json`——版本以源文件为准；
4. **数据流**：从界面到存储的环节有没有变化（新增中间层、改路径等）。

## 格式骨架（`docs/地图.md`）

```markdown
# 项目地图

> 一句话说明 + 更新规则

## 一、项目是什么
（一段话；最高依据指向 `docs/愿景/`）

## 二、技术栈
（表格：层 / 技术 / 说明；版本以源文件为准）

## 三、系统数据流
（一段话：一次对话从界面到存储经过哪些环节）

## 四、代码结构
（模块速览表；末尾「从哪读起」列关键入口文件）

## 五、文档结构
（六类别说明 + 归档规则 + `.agents/skills/` 位置）

## 六、当前状态
（第一部分 / 第二部分状态；当前里程碑）

## 七、关键入口
（AGENTS.md、start.bat、.ling-data/ 等）
```

## 写法要求

- 只写「现在是什么」：历史、理由、计划都不写（那些属于里程碑与归档）；
- 尽量给链接，不复制别处内容（单一真源）；版本只写大版本，细节留给源文件；
- 保持精简、几分钟能读完；细节进对应文档，地图只留索引；
- 模块、入口用表格，不写长段散文；
- 技术债 / 待办不进地图（容易过期；缺口归交接与审查管）。

## 检查清单

- [ ] 七节结构完整；「当前状态」与里程碑文件一致
- [ ] 版本与入口逐条对照过源文件 / 实际路径
- [ ] 没有历史、计划、技术债内容混入
