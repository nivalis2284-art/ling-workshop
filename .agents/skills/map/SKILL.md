# 项目地图：当前系统的导航页

`docs/地图.md` 用于回答“项目是什么、结构在哪里、从哪开始读”。事实以实际源码与配置为准，地图只作索引。

## 文档格式

维持现有七个语义章节以兼容当前文档：

1. 项目是什么；2. 技术栈；3. 系统数据流；4. 代码结构；5. 文档结构；6. 当前状态；7. 关键入口。

可以在章节内自由组织表格、链接和简短文字，但不随意将计划/历史/审查正文复制进地图。源文件版本、关键入口及路径需要可核对。

## 更新时机

架构、目录、关键入口、技术栈或数据流有实质变化，以及里程碑完成时更新。小修小补不要求重写地图。更新文档结构时同步 `docs/` 索引与 `.agents/skills/` 的对应说明。

项目文档的固定六类：`地图.md`、`里程碑/`、`计划/`、`审查记录/`、`交接.md`、`愿景/`。日常工作沿用此结构；若产品需要新增类别，可向所有者说明理由并确认后调整，不因偶发任务随手新增顶级文档类别。
