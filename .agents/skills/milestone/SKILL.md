# 里程碑：自主推进，历史规范保存

## 当前文件与职责

- 当前里程碑：`docs/里程碑/当前里程碑.md`（文件名和所在目录以仓库现状为准）。
- 已完成里程碑：`docs/里程碑/已完成里程碑/<里程碑名>/`，作为长期开发史。
- 当前计划、当前审查及其历史目录分别由 `plan`、`review` Skill 维护。

## 当前里程碑文档格式

保持简洁 Markdown 结构：

1. **名称与状态**；
2. **目标**与“必须达成/可选”的可验证条件；
3. **阶段表**（阶段、内容、状态、主要提交或证据）；
4. **关键决策**及原因；
5. **未完成/待验收**事项与对应链接。

阶段数量、粒度、实施顺序与合理并行由 Codex 根据任务自行安排；重大产品承诺、验收口径调整仍交所有者决定。阶段状态必须反映事实，**实现完成不等于用户验收通过**。

## 归档生命周期（必须维持）

**替换当前计划或当前审查时即时归档旧文件**：分别保存在 `docs/计划/历史计划/`、`docs/审查记录/历史审查记录/`；不能堆多份在当前目录，更不能直接覆盖旧历史。

**里程碑完成且必需验收满足后整包归档**：

1. 核查必需验收和仍存在的缺口，未完成不得强行标为完成；
2. 保存可定位的 Git 提交或标签，必要时为完成点打标签；
3. 将已完成的 `当前里程碑.md`、本里程碑相关的当前/历史计划、当前/历史审查整理到 `docs/里程碑/已完成里程碑/<里程碑名>/`，保持相关材料完整可追溯；
4. 保证 `docs/计划/`、`docs/审查记录/` 的活动区仅保留真正当前的文件；为下一里程碑建立新的当前状态；
5. 更新 `docs/地图.md` 中的当前状态、相关链接，以及 `docs/交接.md`。

可按实际情况调整操作的内部顺序和文件组织，但**归档完整性、历史不丢、链接有效、活动区不混杂**不可省略。没有下一里程碑时可明确标记待定，不必伪造新计划。
