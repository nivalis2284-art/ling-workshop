# 计划：目标灵活，文档有序

## 适用与自主权

Codex 根据任务复杂度自主决定调研、拆分、技术方案和执行顺序。小任务无需额外创建计划；已获实施授权的任务不必为普通工程变更重复请示。仅要求讨论或规划的任务，不视作实施授权。

## 文档职责与固定位置

- 当前正式阶段计划：`docs/计划/计划.md`，**同一时间只保留当前一份**。
- 旧计划：`docs/计划/历史计划/`；发生新计划替换时，**先将旧计划以带里程碑和阶段标识的名字归档，再写入新计划**，禁止直接覆盖历史。
- 用户/Chat/Codex 的跨角色需求提案可以放在根目录 `HANDOFF.md`；它不能代替当前正式计划，也不构成自动实施授权。
- 历史计划是项目历史的一部分；里程碑完成后连同相关审查记录收进该里程碑档案，见 `milestone` Skill。

## 正式计划的内容格式

使用清晰 Markdown 标题；保持下列语义信息，允许根据实际复杂度调整章节细节：

1. **标题与元信息**：阶段名称、日期、状态、所属里程碑。
2. **目标与验收**：完成后应发生什么，可检查的成功条件。
3. **依据与现状**：关键事实、重要决定、未知与依赖；引用源文件避免重复。
4. **实施方向与范围**：拟采用方法、影响模块、关键边界；探索期可以使用候选范围，不必臆造精确路径。
5. **工作安排**：有意义的任务或阶段、先后依赖和验证方式；不限制任务数量。
6. **风险与恢复**：较高风险任务记录回退/备份策略；无实质风险可简述。

计划可迭代，方案调整后及时同步当前文件；不要求事前列齐全部文件、每项都填固定四栏或强制写“不改什么”。历史版本由 Git 保留，**替换整个阶段计划**才需要归档旧计划。

## 一致性

计划中不要把“暂缓”“当前实现选择”写成永久禁令；不要把未完成工作写成已完成。涉及阶段或里程碑重大目标变化时同步 `docs/里程碑/当前里程碑.md`。
