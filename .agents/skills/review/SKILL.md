# 审查：怎么查、怎么写

## 它是什么

审查 = **独立于执行者的复核**：对照计划的验收标准，逐条验证"是否真的完成"，并留下证据。

## 三级验证（核心方法）

对每个"已完成"的声明，逐级问：

1. **存在**：文件 / 功能真的在吗？（不是只在计划里）
2. **实质**：是真实现，不是空壳？（TODO / placeholder / 空函数 = 未完成）
3. **接线**：真的被调用 / 被装配 / 被使用了？（建了文件没接入 = 没完成）

绝大多数"做完了但没生效"的问题死在第 3 级。

## 格式骨架（`docs/审查记录/审查.md`）

````markdown
# 审查记录：<对象，如 阶段N>

> 审查对象：<计划链接> ｜ 日期 ｜ 审查者（独立于执行者）

## 验收项对照
| 验收标准 | 结果 | 证据 |
|---|---|---|
| （逐条） | 通过 / 不通过 | （命令输出、数字、文件路径） |

## 发现的问题
（分级：阻断——不修不能收 ／ 一般——该修、可带着走 ／ 建议）

## 结论
通过 / 有条件通过 / 驳回

## 回退点
（若有）
````

## 写法要求

- **贴证据**：命令与输出、数字、文件路径。不写"看起来没问题"。
- 没通过就不写"通过"；不确定标 `unknown`。
- 主动搜一遍存根迹象（TODO / FIXME / placeholder / "coming soon"），命中即登记。

## 归档

- 新一轮开始时：旧审查**改名**（`审查-<里程碑>-<阶段>.md`）移入 `docs/审查记录/历史审查记录/`。
- 里程碑完成时：随包收进里程碑档案（见 milestone 技能）。
