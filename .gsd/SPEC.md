# SPEC.md — Project Specification

> **Status**: `FINALIZED`

## Vision
彻底移除 LingNexus 系统中早期的过度工程化防御机制（交流情境 Scope 与历史级联作废链条），尊重接入的大语言模型原生理解力，从算法死板联动转向“人工显式纠偏”与“轻量定期反省”，使系统回归轻量、直观、可控的长期个人 AI 架构。

## Goals
1. **彻底拔除交流情境 (Scope / Real)**：从系统提示词、会话管理、记忆检索及底层接口中全面剥离 `scope` 约束，废除“防止虚构进入现实”的代码硬隔离。
2. **切断编辑与删除时的过度级联作废**：当用户修改或删除历史消息时，系统仅负责调整当前激活的上下文窗口，不再自动级联作废或破坏派生的长期记忆、知识与人设。
3. **长期记忆与知识人工手动纠错优先**：记忆作为独立的思考沉淀，支持用户在界面上直接查看、编辑与删除，算法不代劳连带破坏。
4. **前端界面与看板精简**：移除前端页面上与 `real` / `external` 相关的冗余下拉框与标识胶囊，简化记忆管理交互。
5. **测试用例重构与工程基准回归**：重构自动化测试用例，删除过时的假想防御性断言，确保全栈测试 100% 绿色通过并保持 0 TODO/FIXME。

## Non-Goals (Out of Scope)
- 不改变底层单进程 SQLite + FastAPI + React 19 的基础技术栈。
- 不引入外部向量数据库或重型 RAG 框架。
- 本里程碑暂不重写底层 HTTPX SSE 流式传输引擎与 Docker/Playwright 沙箱执行引擎。
- 阶段三具体的“定期反省思考”触发策略细节（主动指令/定时周期）留待 Phase 3 启动时专门讨论。

## Users
系统所有者（个人开发者/长期使用者），通过桌面端 Web 界面与「灵」进行长期的真实伴随交流与多步任务协作。

## Constraints
- Windows 10/11 64 位环境运行，保持单实例与本地优先。
- 零第三方 LLM SDK 依赖（纯 HTTPX）。
- 数据库结构升级平滑兼容现有 `ling.db` 历史记录（`025_drop_scope.sql` 迁移脚本）。
- 后端与前端类型检查（Pyright / TypeScript）必须维持 0 Error，代码静态检查（Ruff）维持 0 Warning。

## Success Criteria
- [ ] 系统 Prompt 中彻底不含 `当前交流情境：real` 字样。
- [ ] 会话创建、对话检索与记忆召回全面放开，不依赖 `scope` 过滤。
- [ ] 撤回/删除历史消息时，相关长期记忆与人设提案状态保持稳定，不发生级联作废。
- [ ] 数据库 025 迁移平滑运行，已有数据无损。
- [ ] 后端 Pytest 与前端 Vitest 测试套件 100% 通过。
- [ ] Ruff 与 Pyright 0 警告，前端构建无错误。
