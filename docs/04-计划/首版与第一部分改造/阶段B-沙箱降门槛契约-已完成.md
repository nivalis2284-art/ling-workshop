## 一、目标

**默认不依赖任何外部引擎即可跑编程任务。** 容器从"准入条件"降为"可选升级项"。

## 二、要做的事

### 2.1 统一的执行端口

定义一个执行接口，两种实现可互换：

| 档位 | 实现 | 说明 |
| :--- | :--- | :--- |
| **默认档（第 2 档）** | 本地受限执行器 | **本次新增** |
| **可选档（第 3 档）** | 容器执行器 | 现有的保留，不删 |

调用方（任务执行）只面向端口，不关心后面是哪一档。

### 2.2 默认档的组成

| 能力 | 做法 |
| :--- | :--- |
| 目录受限 | 只在任务工作副本内活动，复用已有的路径授权模型 |
| 无 shell | 参数列表，不经过系统命令行解释器（复用已有的受限进程原语） |
| 超时 | 已有 |
| 输出上限 | 已有 |
| **进程数上限** | 新增 |
| **内存上限** | 新增 |
| **CPU 时间上限** | 新增 |
| **退出时清理整棵进程树** | 新增，防止残留子进程 |

**技术前提（已探明）**：本机没有 `psutil`，也没有 `resource` 模块（Windows），但 `ctypes` 可用。**用 Windows 作业对象（Job Object）实现，不引入新的第三方依赖。**

> 若某项限制在本机确实做不到硬保证，**如实降级并在隔离等级说明里写明**，不得宣称做不到的能力。

### 2.3 档位选择

- 启动时**探测**容器引擎是否可用（命令行工具是否存在且可执行）。
- **默认用本地受限档**。
- 探测到引擎时，界面上**提示"可升级到容器隔离"**，由用户**显式选择**，**不自动切换**。
- 档位选择要**持久化**（设置项），重启后保持。
- 用户未选择时，永远落在默认档。

### 2.4 隔离等级对用户可见且诚实

对外要能回答三个问题：

1. **当前是哪一档？**
2. **它能防什么？**（例如：误删授权目录外的文件、进程失控占满内存、命令无限输出）
3. **它不能防什么？**（例如：未使用容器时，无法阻止被诱导后主动外传数据）

**不得在只做了路径校验的情况下宣称"已隔离"。**

### 2.5 依赖核实不再绑死容器

依赖版本的核实当前依赖容器。改为**按当前档位选择核实手段**；无容器时也能走完依赖审批流程，并如实说明核实方式。

### 2.6 镜像改为可配置

镜像当前在装配处**硬编码**，但说明文档写的是"由所有者配置"。二选一，让说法与行为一致——**改为可配置**（设置项或环境变量），并修正文档。

### 2.7 保留容器档

**不删除容器沙箱。** 隔离强度本身有价值，尤其一旦开放网页操作与外部资料。

## 四、验收标准

1. **无容器也能跑**：把档位强制为默认档（或屏蔽容器引擎），编程任务完整跑通。
2. **限制是真的**：写测试证明内存/CPU 时间/进程数超限会被真正终止，且退出后无残留进程。
3. **档位可持久化**：切换后重启保持。
4. **诚实声明**：对外接口与界面都能拿到"当前档位 + 防得住什么 + 防不住什么"。
5. **依赖审批在无容器时可用。**
6. **既有测试全绿**；新增针对沙箱档位的测试。
7. **容器档仍然可用**（不回归）。
