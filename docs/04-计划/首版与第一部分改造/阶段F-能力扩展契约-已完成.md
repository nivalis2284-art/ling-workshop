## 一、目标

第一部分现在能自己读文件、改文件、跑命令（C 阶段成果），但还缺两样：

1. **没有"别人给的说明书"可用**——内置知识之外，无法加载外部技能包。
2. **连不上外部能力生态**——MCP 已是事实标准，不接等于放弃整个外部工具生态。

F 阶段补这两块。两条约束**违反即失败**：

| # | 约束 | 含义 |
| :-- | :--- | :--- |
| 1 | **可选** | 一个技能都不装、一个 MCP 服务器都不配时，行为与现在**完全一致**。 |
| 2 | **不扩权** | 技能与 MCP **都不是权限来源**；它们发起的一切动作仍走既有的权限钩子与执行沙箱。 |

> 第 1 条是 Docker 那一课的直接教训：**不允许把新能力变成新的前置门槛。**

## 二、范围

### 2.1 技能包（"技能作为能力包"，不是"技能作为长期积累"）

依据：`docs/设计/2026-10-11-第一部分能力板块.md` 2.3 / 3.6。

- **形态**：一个文件夹 + 一份 `SKILL.md`（元数据 `name`/`description` + 正文），可选带 `references/`、`scripts/`、`assets/`。
- **三级渐进式披露**：
  1. **常驻**：只把 `name` + `description` 注入请求开头（每技能约 20–100 token）。
  2. **按需**：判断任务命中时，模型用工具读入正文。
  3. **自由**：参考文档按需读；脚本**直接执行**（脚本是给模型跑的，不是给模型读的）。
- **存放三处**：随项目内置 / 用户级 / 项目级。启动时扫描并建轻量索引。
  - 同名冲突：**以更具体者为准**（项目级 > 用户级 > 内置）。
- **内置那套要克制**：只放真正通用、不依赖外部服务的。
- **命名（重要）**：新模块为 `lingnexus.skillpacks`。
  **不得**复用 `lingnexus.skills`——那是第二部分的"技能长期积累"（版本/审批/stale），其服务已归档到 `part2_retired/`；边界测试把 `lingnexus.skills` 与 `Application.skills` 列为禁区，正是防止它复长。

### 2.2 MCP 最小集（可选客户端）

依据：`docs/设计/2026-10-11-第一部分能力板块.md` 4.3。

| 做 | 不做（暂） |
| :--- | :--- |
| 连接服务器（本地 stdio / 远程 http） | 交互界面扩展 |
| 列工具、调工具、回传结果 | 长任务扩展 |
| 协议版本协商 | 多轮往返请求 |
| —— | 订阅流 |

- 配置在 `settings`（键 `mcp.servers`，JSON）。**未配置即完全不启用。**
- 远程工具以 `mcp__<server>__<tool>` 声明进**同一个工具注册表**，与本地工具走同一条派发与钩子路径。

## 四、验收标准

1. **零影响**：不装技能、不配 MCP 时，既有后端测试全绿，行为与 C/D 阶段一致。
2. **技能可发现**：能扫描三处目录；同名以更具体者为准；注入内容只含 `name` + `description`（不含正文）。
3. **技能可按需读取**：`read_skill` 能取回正文，并给出该技能目录内的资源清单（供第三级按需读/执行）。
4. **技能读取受限**：资源读取不得越出技能目录、不得跟随符号链接、不得读取非技能文件。
5. **技能不扩权**：技能里的脚本仍只能经 `run_command` 在既有授权与沙箱档位下执行；技能声明本身不改变任何权限。
6. **MCP 零影响**：未配置服务器时不注册任何工具、不发起任何连接。
7. **MCP 可用**：配置后能连接、列工具、调工具、回传真实结果；协议版本不匹配时**如实报错**，不静默降级成"成功"。
8. **MCP 不绕权限**：远程工具调用同样经 `BEFORE_TOOL` 钩子（权限与副作用确认闸门都不被绕过）。
9. **边界不破**：`tests/test_boundary_part1.py` 仍绿；第一部分不依赖第二部分，`part2_retired` 也列入禁区。
10. **无新依赖**：技能与 MCP 均用标准库实现。

### 遗留与已知边界

- **MCP 远端工具已纳入副作用确认闸门**（2026-10-11 审查修复）：此前 `mcp__*` 被权限钩子放行，远端副作用不经所有者确认。现 `confirmation_hook` 按前缀闸住全部远端调用（`runtime/confirmations.py::is_gated`）——配置授权的是**连接**服务器，不是**逐次**调用；客户端无从知晓远端工具的副作用，故与 `run_command` 同等对待。MCP 调用同时移入线程池，不再阻塞事件循环。
- **MCP 只接对话循环**：任务循环（`tasks/execution.py`）是无钩子的旧路径，接入会让远端工具绕过权限与确认闸门，故有意不接。
- **旧 `lingnexus/skills/` 包仍在**（第二部分的技能长期积累，已被 `test_boundary_part1.py` 列为禁区）。F 用新模块 `skillpacks`，未做归档——归档操作在本机触发过工作区视图异常，故保留原样。
- **技能资源读取双重封堵**（同轮修复）：`_read_resource` 改经共享 `local_path` 校验字符串形态（拒绝盘符相对 `C:foo`、根相对 `\foo` 与 `/foo`、UNC），拼接后再以 `is_relative_to(skill.path)` 终检兜底；`search` 从路径类工具拆出（它没有 path 参数，按路径检查会导致对话循环内 100% 被拒）。

## 五、禁令

- 不改第二部分模块。
- **不新增第三方依赖**（技能与 MCP 都用标准库：`json` / `subprocess` / `urllib`）。
- **不把技能或 MCP 变成前置门槛**。
- 不让技能或 MCP 绕过权限钩子、副作用确认或执行沙箱。
- 不做内置计划清单、多 Agent 协作。
- **不实现"技能的自动积累与演化"**（属第二部分）。
- 不追 MCP 扩展（交互界面、长任务、多轮往返、订阅流）。
