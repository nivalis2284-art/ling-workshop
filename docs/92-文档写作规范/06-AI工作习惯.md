# AI 工作习惯（防「不报错地失败」）

> 本系列唯一约束「怎么干活」的一份——因为这三类问题**不会主动暴露**，出了事才找原因。与文档写法无关，但同样是产出质量的底线。

## 1. 先搜后读

读任何文件前，先搜索定位片段，判断值不值得整读。

- 反模式：「以防万一」整篇读——花掉的是后续任务要用的上下文预算。
- 反模式：重读已经理解过的文件——写摘要，引用摘要。
- 信号：读了多个文件仍找不到目标——停下来重估检索方法；问题通常在「怎么找」，不在「读得不够多」。

## 2. Shell 纪律

默认一次一条命令；每条命令的输出看一眼，再走下一条（链式写法（`&&`）在旧版 PowerShell 等环境不被支持，会直接失败）。

为什么：一次一条，每步的成败与输出都摆在明面上；环境差异带来的坑（如 `start.bat` 的 GBK 编码问题：cmd 解析 UTF-8 批处理会错行，报「不是内部或外部命令」），拆开跑才看得清。

## 3. 三振出局

同一问题反复失败、在原地打转（每次尝试都没有带来新信息）时：停下来，写下三样东西——已确认的事实、已排除的假设、新假设——然后考虑开新会话。

为什么：原地打转的上下文会重复自己已经失败的假设；AI 会爱上自己的第一个猜想，在旧上下文上加越多补丁，偏得越远。

## 与交接体系的配合

三振出局写下的三样东西，正是 [`../07-交接/`](../07-交接/2026-10-11-交接.md) 交接文档的核心内容——把「当前排查状态」落盘，新会话从事实出发，而不是从疲劳出发。
