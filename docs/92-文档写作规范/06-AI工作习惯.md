# AI 工作习惯（防「不报错地失败」）

> 本系列唯一约束「怎么干活」的一份——因为这三类失败**不报错**，出了事却找不到原因。与文档写法无关，但同样是产出质量的底线。

## 1. 先搜后读

读任何文件前，先搜索定位片段，判断值不值得整读。

- 反模式：「以防万一」整篇读——花掉的是后续任务要用的上下文预算。
- 反模式：重读已经理解过的文件——写摘要，引用摘要。
- 信号：需要同时读 5 个以上文件时，停下来重新想方法（通常是想错了方向）。

## 2. Shell 纪律

一条命令一次调用；不链 `&&`；每条命令的输出看一眼，再走下一条。

为什么：某些 shell（Windows PowerShell 5.1）会**拒绝解析**链式命令——命令看着执行了，其实根本没跑，而且不报错。这类「沉默失败」在 `start.bat` 的 GBK 编码问题上已经栽过一次（cmd 解析 UTF-8 批处理会错行，报「不是内部或外部命令」）。

## 3. 三振出局

同一问题排查连续失败 3 次：停下来，写下三样东西——已确认的事实、已排除的假设、新假设——然后建议开新会话。

为什么：失败 3 次的上下文会重复自己已经失败的假设；AI 会爱上自己的第一个猜想，在旧上下文上加越多补丁，偏得越远。

## 与交接体系的配合

三振出局写下的三样东西，正是 [`../07-交接/`](../07-交接/2026-10-11-交接.md) 交接文档的核心内容——把「当前排查状态」落盘，新会话从事实出发，而不是从疲劳出发。
