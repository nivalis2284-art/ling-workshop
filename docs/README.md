# 文档地图

> 本仓库的文档都在 `docs/` 下。本文件说明：**每个文件夹是干嘛的、新文档放哪、有哪些规矩。**
> 给 Agent 的执行规则在根目录 [`AGENTS.md`](../AGENTS.md)：AGENTS 管"怎么干活"，本文件管"东西放哪"。

## 文件夹一览

| 文件夹 | 职责（一句话） | 什么时候写 |
|---|---|---|
| [`愿景/`](愿景/) | 最高层长期依据（01-概念与原则、02-抽象需求），只读 | 罕见 |
| [`架构/`](架构/) | "现在是什么"：业务与能力全景、技术基线、沙箱、限制溯源 | 现实变化时 |
| [`路线图/`](路线图/) | "要做什么"：总览看板 + 各里程碑文档 | 状态变化随时 |
| [`计划/`](计划/) | 各阶段的计划（**开工前必写、所有者确认后执行**） | 每个阶段开工前 |
| [`执行记录/`](执行记录/) | 每个阶段"改了什么、结果如何" | 做完立刻写 |
| [`审查记录/`](审查记录/) | 每个阶段"验收对照、结论" | 每个阶段收尾 |
| [`交接/`](交接/) | 上下文过长时给接手者的交接文档（按日期） | 需要交接时 |
| [`模板/`](模板/) | 里程碑 / 计划 / 执行记录 / 审查记录 空白模板 | 罕见 |
| [`归档/`](归档/) | 完成内容的整包存档（按里程碑/时期分文件夹） | 里程碑完成时 |

另有两份特殊文档：`讨论笔记.md`（唯一允许随手覆盖的草稿区）和 `使用说明.md`（面向使用者的操作手册）。

## 新文档放哪

- 讲"现在是什么" → `架构/`；讲"要做什么" → `路线图/`；讲"这一步怎么做" → `计划/`；"做完的结果" → `执行记录/`；"验收结论" → `审查记录/`。
- 拿不准 → 先问所有者；不要新建计划外的文件夹。

## 命名规则

- 里程碑：`M1-短名`（如 `M1-加回第二部分`）；阶段：`阶段1-短名`。
- 交接文档：`2026-10-13-交接.md`（日期在前，按时间排序）。
- 同一里程碑的所有文档共用同一编号，一眼对应。

## 四条贯穿规则

1. **单一真源**：同一个信息只有一个"家"；其他地方放链接，不复制。
2. **完成即归档**：里程碑完成后，它的"里程碑文档 + 计划 + 执行 + 审查"整包移入 `归档/<里程碑>/`。
3. **实时维护**：代码与文档在同一次提交里一起改；不允许"以后再补"。
4. **路径一律相对**：文档与配置里的路径只用相对路径；禁止本机绝对路径（`H:/...`、`C:\...`、`file:///`）——仓库要能在任何机器（含虚拟机）上克隆即用。

## 谁写谁批

- 计划由 Agent 写、**所有者确认**后才执行；执行记录由执行者写；审查记录由独立审查者写；所有者是最终决策人。
