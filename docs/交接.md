## 注意什么

- 子 Agent 的“同一身份再次唤醒”是持久身份与合法后继阶段的连续性，不等于复活不可见思维链。旧 `archived` 不可翻回 queued；旧原生 checkpoint 不得为唤醒而重放。
- 普通模型回合完成不等于工作完成；业务完成、验证成功、交付应用是不同事实。unknown/pending/inflight/来源失效必须阻断自动继续与唤醒。
- 指导只有在下一步真实消费后才标 “consumed”；当前界面早报成功是待修复缺陷。任务/工作/run/归档的状态不可合并为一个“completed”。
- 权限：L4 只是取消产品内普通审批，不超越 OS、VM/容器、账号与网络；N0 不等于上下文不会发送给模型供应商。`full` 不能静默映射为 L4；旧配置需 legacy 或逐主体确认。
- 本地执行档没有真实文件/网络隔离；容器默认断网、只读根但不是 VM；stdio MCP 是宿主子进程，HTTP MCP 是直接请求；浏览器 exact-origin 只能证明部分 N1。任何“禁止联网”必须有通道级或出口级证据。
- 首版建议保留“一个主干运行 + 一个子 Agent 运行”，多个身份可休眠/排队；不为并发扩大共享写入与资源风险，除非取得新的隔离与性能证据。
- 归档经历入口应使用真实的 `work-live:<branch_id>`（或后端提供的经历 ID），不能将随机 `archive_id` 当经历 ID；前端 mock 要通过实际 API 链路验证。
- 保护全部用户既存改动：`docs/里程碑/已完成里程碑/M1-继续优化地基/00-README.md` 的排版改动、`.codex-remote-attachments/` 与生产 `.ling-data/` 不纳入本轮提交。临时前端联调文件也不提交。
