# 项目地图

> 「项目长什么样、东西在哪」——任何 AI 接手时，读完根目录 [`AGENTS.md`](../AGENTS.md) 后读本文件与 [`交接.md`](交接.md)。
> 更新时机：结构变化或里程碑完成时（写法见 `.agents/skills/map/SKILL.md`）。

## 一、项目是什么

LingNexus 是由所有者掌握发展方向的**长期个人 AI 系统**；「灵」是其中主要的 AI 个体。当前形态：Windows 本机后台 + 中文图形界面，云端模型驱动。最高长期依据见 [`愿景/`](愿景/)（除所有者明确指令外不修改）。

## 二、技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 后端 | Python 3.12 · FastAPI · SQLite | 模块化单体（`src/lingnexus/`） |
| 前端 | React 19 · TypeScript · Vite | 本机浏览器中文界面（`frontend/`） |
| 测试 | pytest（后端）· vitest（前端）· Playwright（端到端） | 后端冒烟层在 `tests/` |
| 打包 | PyInstaller | `packaging/`；本机运行入口 `start.bat` |
| 数据 | SQLite | 运行数据在 `.ling-data/`（不进 Git） |
| 依赖清单 | `pyproject.toml` · `frontend/package.json` | 版本以这两处为准 |

## 三、系统数据流

一次对话的大致流向：

界面 → HTTP 接口（`api/`）→ 对话循环（`runtime/`：组装上下文 → 调模型（`models/`）→ 按权限（`permissions/`）派发工具（`tools/`、`actions/`）→ 结果回填 → 循环）→ 持久化（`storage/`）。

普通对话的原生续接与副作用检查点在 `runtime/checkpoints.py`；命令会话在 `tools/sessions.py`，经 `tasks/sandbox.py` 绑定个体与运行、提供轮询和取消，HTTP入口为 `api/execution.py`。普通对话与任务共用 `common/verification.py` 的版本验证证据。检查点保留原生状态，不做上下文压缩。

两运行器的脱敏诊断共用 `common/diagnostics.py`；owner人工核对在 `runtime/reconciliation.py`，经 `/execution/recovery/` 接入，不解除unknown。部分写回剩余审阅在 `tasks/workspace.py`，经 `/tasks/{id}/application` 和 `/tasks/{id}/reconcile` 接入；共享界面为 `frontend/src/shared/RecoveryReview.tsx`。工作区指纹与副本扫描共用 `common/workspace_scan.py`，策略及排除范围有版本、资源有界。

后台维护任务（`maintenance/`、`background/`）独立于对话运行。

## 四、代码结构

仓库顶层：`src/`（后端）· `frontend/`（界面）· `docs/`（文档）· `tests/`（测试）· `packaging/`（打包）· `scripts/`（辅助脚本）· `.agents/`（开发技能）· `start.bat`（运行入口）。

**后端**（`src/lingnexus/`）：Python 3.12 · FastAPI · SQLite · 模块化单体。

| 模块 | 一句话 |
|---|---|
| `runtime/` | 对话运行主循环（模型调用、工具派发、暂停/恢复、确认闸门） |
| `conversations/` `context/` `content/` | 对话与分支、上下文组装、附件与内容理解 |
| `actions/` `tools/` `permissions/` | 工具目录与统一派发、执行原语（受限进程 / 工作区）、权限钩子 |
| `tasks/` `dependencies/` | 任务工作副本、依赖安装流程 |
| `models/` `configuration/` | 模型接入（三协议适配、主备切换）、设置与凭据缓存 |
| `skillpacks/` `mcp/` | 技能包（三级渐进披露）、MCP 客户端（可选） |
| `maintenance/` `background/` `storage/` `observability/` `common/` | 备份维护、后台驱动、数据库与迁移、记账与审计、公共工具 |
| `desktop/` `api/` | 本机启动器与托盘、HTTP 接口 |
| `part2_retired/` 及相关模块 | 已隔离的第二部分代码（不装配、不导入；边界由测试守护，随开发调整） |

**从哪读起**（关键入口）：

| 想读什么 | 从这里进 |
|---|---|
| 后端组合根（模块装配） | `src/lingnexus/app.py` |
| HTTP 接口层 | `src/lingnexus/api/` |
| 对话运行循环 | `src/lingnexus/runtime/` |
| 桌面启动 / 托盘 | `src/lingnexus/desktop/` |
| 数据库迁移（SQL） | `src/lingnexus/storage/migrations/` |
| 前端入口 | `frontend/src/main.tsx` |

**前端**（`frontend/`）：React · TypeScript · Vite；按 `app/`（框架与导航）、`features/`（chat / settings 等功能）、`shared/`（共享组件）组织。
**测试**：`tests/`（后端冒烟层）；**打包**：`packaging/`；**启动**：根目录 `start.bat`（唯一入口）。
真实编程对照控制端为 `scripts/evaluate_coding.py`，固定六类夹具位于 `tests/fixtures/coding_tasks/`；原始评测与费用账本位于被忽略的 `.artifacts/coding-eval/`，脱敏结论归入审查记录。

通用任务小探针为 `scripts/evaluate_agent.py`（默认离线，`--live`显式付费），与编程控制端共用原预算账本；目前覆盖信息整理、文件、多工具三类，完整五类真实矩阵未完成。

## 五、文档结构

- `docs/地图.md`（本文件）：项目全景；`docs/交接.md`：最新交接（开工先读）。
- `docs/里程碑/`：`当前里程碑.md` + `已完成里程碑/`（每个里程碑一个档案包，即开发史；当前包内为首版与第一部分改造的 43 份旧文档，仅查阅、不维护）。
- `docs/计划/`、`docs/审查记录/`：只留最新一份，旧的实时归档（各自 `历史` 子夹）。
- `docs/愿景/`：最高依据。
- 写法与工作方法：`.agents/skills/`（map / milestone / plan / execute / review / debug / handoff 七个技能，开发工具自动发现）。
