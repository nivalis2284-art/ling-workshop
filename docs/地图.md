# 项目地图

> 「项目长什么样、东西在哪」——任何 AI 接手时，读完根目录 [`AGENTS.md`](../AGENTS.md) 后读本文件与 [`交接.md`](交接.md)。
> 更新时机：结构变化或里程碑完成时（写法见 `.agents/skills/map/SKILL.md`）。

## 一、项目是什么

LingNexus 是由所有者掌握发展方向的**长期个人 AI 系统**；「灵」是其中主要的 AI 个体。当前形态：Windows 本机后台 + 中文图形界面，云端模型驱动。最高长期依据见 [`愿景/`](愿景/)（除所有者明确指令外不修改）。

## 二、技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 后端 | Python 3.12 · FastAPI · SQLite | 模块化单体（`src/lingnexus/`） |
| 前端 | React 19 · TypeScript · Vite | 本机浏览器中文界面（`frontend/`） |
| 测试 | pytest（后端）· vitest（前端）· Playwright（端到端） | 后端自动化与回归测试在 `tests/` |
| 打包 | PyInstaller | `packaging/`；本机运行入口 `start.bat` |
| 数据 | SQLite | 运行数据在 `.ling-data/`（不进 Git） |
| 依赖清单 | `pyproject.toml` · `frontend/package.json` | 版本以这两处为准 |

## 三、系统数据流

一次对话的大致流向：

界面 → HTTP 接口（`api/`）→ 对话循环（`runtime/`：组装上下文 → 调模型（`models/`）→ 按权限（`permissions/`）派发工具（`tools/`、`actions/`）→ 结果回填 → 循环）→ 持久化（`storage/`）。

普通对话的原生续接与副作用检查点在 `runtime/checkpoints.py`；进行中压缩在 `runtime/compaction.py`，只在工作分支的完整工具交换与安全边界建立新的上下文代际，旧私有状态封存，不跨代重放 opaque/signature，也不清零全局步骤或效果账。命令会话在 `tools/sessions.py`，经 `tasks/sandbox.py` 绑定个体与运行、提供轮询和取消，HTTP 入口为 `api/execution.py`。普通对话与任务共用 `common/verification.py` 的版本验证证据，写入类操作共用 `common/execution_leases.py` 的同机资源围栏。

连续主干、独立工作分支和经历来源在 `continuity/`；数据库 034 保存绑定、工作生命周期、回归 outbox、经历索引与依赖账，037 增加追加式任务状态、唤醒 episode 与分阶段归档经历，038 保存运行暂停意图；HTTP 入口为 `api/continuity.py`。工作使用独立 conversation，以明确锚点冻结必要主干背景；工作 branch 本身是稳定子 Agent，branch ID 不随唤醒变化。`BranchCoordinator` 在真实运行终态核验归档并幂等追加主干短报告；归档后用同一 branch 开启后继 episode，新 run 输入包含任务状态、未完成项和未消费指导，旧归档/私有 checkpoint/effect 不改写或重放。全文、来源权限和派生依赖留在权威消息/安全记录中，经历目录只保存索引与覆盖版本；撤回会投影为不可用并阻断后续无工具派生回答。

维护轮次统一了普通工作聊天与协调器的 run/episode 事务绑定；指导消费回执与原生 payload 检查点同事务落盘。工作历史 HTTP 接口默认读取最近 100 项并支持向前分页，域内调用保留全量兼容；任务状态历史继续追加保存。portable v4 同时携带来源版本账与附件关联版本，私有 checkpoint/effect、运行控制仍由完整备份保护。前端流式显示保持逐事件顺序，会话存储合并增量写入并在终态及页面离开时落盘。

定时反思在 `reflection/`：数据库 035 保存策略、日历槽、作业/租约、冻结快照、结构候选、调用与预算账；API 入口为 `api/reflection.py`，由 `background/Supervisor` 驱动。默认关闭；低阈值不调用模型，候选默认需所有者审阅，只有所有者记录符合冻结门槛的连接质量确认后才自动发布。经历 UI 位于 `frontend/src/features/continuity/`，主干与工作入口在对话页。`work_events/` 继续承接既有同会话闭合区间，投影先于原生回放、附件和预算，原消息与私有检查点分别保留。

两运行器的脱敏诊断共用 `common/diagnostics.py`；owner人工核对在 `runtime/reconciliation.py`，经 `/execution/recovery/` 接入，不解除unknown。部分写回剩余审阅在 `tasks/workspace.py`，经 `/tasks/{id}/application` 和 `/tasks/{id}/reconcile` 接入；共享界面为 `frontend/src/shared/RecoveryReview.tsx`。工作区指纹与副本扫描共用 `common/workspace_scan.py`，策略及排除范围有版本、资源有界。

后台维护任务（`maintenance/`、`background/`）独立于对话运行。

## 四、代码结构

仓库顶层：`src/`（后端）· `frontend/`（界面）· `docs/`（文档）· `tests/`（测试）· `packaging/`（打包）· `scripts/`（辅助脚本）· `.agents/`（开发技能）· `start.bat`（运行入口）。

**后端**（`src/lingnexus/`）：Python 3.12 · FastAPI · SQLite · 模块化单体。

| 模块 | 一句话 |
|---|---|
| `runtime/` | 对话运行主循环（模型调用、工具派发、暂停/恢复、确认闸门） |
| `conversations/` `context/` `content/` | 对话与分支、上下文组装、附件与内容理解 |
| `actions/` `tools/` `permissions/` | 工具目录与统一派发、执行原语（受限进程 / 工作区）、权限钩子 |
| `tasks/` `dependencies/` | 任务工作副本、依赖安装流程 |
| `models/` `configuration/` | 模型接入（三协议适配、主备切换）、设置与凭据缓存 |
| `skillpacks/` `mcp/` | 技能包（三级渐进披露）、MCP 客户端（可选） |
| `maintenance/` `background/` `storage/` `observability/` `common/` | 备份维护、后台驱动、数据库与迁移、记账与审计、公共工具 |
| `desktop/` `api/` | 本机启动器与托盘、HTTP 接口 |
| `part2_retired/` 及相关模块 | 已隔离的第二部分代码（不装配、不导入；边界由测试守护，随开发调整） |

**从哪读起**（关键入口）：

| 想读什么 | 从这里进 |
|---|---|
| 后端组合根（模块装配） | `src/lingnexus/app.py` |
| HTTP 接口层 | `src/lingnexus/api/` |
| 对话运行循环 | `src/lingnexus/runtime/` |
| 桌面启动 / 托盘 | `src/lingnexus/desktop/` |
| 数据库迁移（SQL） | `src/lingnexus/storage/migrations/` |
| 连续主干与独立工作 | `src/lingnexus/continuity/`、`src/lingnexus/api/continuity.py`、`frontend/src/features/continuity/` |
| 工作事件与只读回查 | `src/lingnexus/work_events/`、`src/lingnexus/api/work_events.py`、`frontend/src/features/workevents/` |
| 定时反思与事件候选 | `src/lingnexus/reflection/`、`src/lingnexus/api/reflection.py` |
| 上下文代际压缩 | `src/lingnexus/runtime/compaction.py`、迁移 036 |
| 前端入口 | `frontend/src/main.tsx` |

**前端**（`frontend/`）：React · TypeScript · Vite；按 `app/`（框架与导航）、`features/`（chat / workevents / settings 等功能）、`shared/`（共享组件）组织。
**测试**：`tests/`（后端自动化与回归测试）；**打包**：`packaging/`；**启动**：根目录 `start.bat`（唯一入口）。
真实编程对照控制端为 `scripts/evaluate_coding.py`，固定六类夹具位于 `tests/fixtures/coding_tasks/`；原始评测与费用账本位于被忽略的 `.artifacts/coding-eval/`，脱敏结论归入审查记录。

通用任务小探针为 `scripts/evaluate_agent.py`（默认离线，`--live`显式付费），与编程控制端共用原预算账本；覆盖信息整理、文件、多工具三类；`scripts/evaluate_acceptance.py` 是五类 10+8 控制矩阵（通用 Agent 验收控制端），支持既有 Chat Completions / Responses 协议，原始报告与 provider trace 在被忽略的 `.artifacts/m1-acceptance/`。矩阵第 4 次运行 18/18 完成、`accepted=true`，M1 据此收口；前三次失败与外部链路不稳定记录在归档审查。
