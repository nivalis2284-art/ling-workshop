### 2.1 两套机制的关键取舍

- **A**：主干只接收报告，完整过程留在工作分支。fork 冻结必要背景；主干追加不修改背景，编辑/删除/撤权则使依赖失效。回归只追加当前允许主干末端，唯一键/CAS/outbox 防重复和回退；发布顺序与事件时间分开。
- **A 的难点**：进行中压缩必须在完整工具交换边界，目标/待办/来源/效果账跨 epoch 保留；全局 step 和资源预算不重置。无法安全压缩则停止。主干上下文隔离还不等于文件隔离，同目录写入仍需副本或串行。
- **B**：先筛选安全闭合、足够旧、尚未覆盖的主干原文，再用本地安全正文字节闸门；低于阈值零模型调用、零覆盖推进。达到后由只读专用整理 Agent 做多个事件候选，精确覆盖本批来源，分别摘要并带原始发生时间。
- **共同来源**：回归文本、普通事件摘要、回读凭条及后续派生回答都进入撤回依赖；来源失效时不能从原始历史或缓存偷偷回退泄漏。人类展开零模型调用，模型只能有界目录→片段读取。

### 4.1 原生压缩不能与可读事件摘要混用

官方 [OpenAI compaction](https://developers.openai.com/api/docs/guides/compaction) 规定独立 compact 返回下一上下文整体，含不可解释的 encrypted compaction item；不能只摘取它或擅自再次裁剪，也不是可公开回读的经历。供应商能力须按实际 profile 和中转验证。

官方 [Anthropic context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)及[compaction overview](https://platform.claude.com/docs/en/build-with-claude/compaction)区分原生按需/阈值压缩、上下文编辑及客户端摘要，并提示 prefix 修改与后续 preserved thinking 的关联；尾部字节相同不足以保证签名继续有效。客户端新 epoch 必须明确为语义续做，旧私有快照封存，不冒充同一推理链。无适配证据的 profile 保持安全停止。

本轮仅核对文档及本地 gateway 能力，**未调用这些原生端点**。原生压缩还可能有额外费用、缓存变化和模型支持范围，不据文档宣称全部现有中转兼容。阶段一也必须保留可读原文和独立事件摘要，不能仅靠 opaque compaction 对象充当记忆。
