## 二、关键实现与复核

- **先修删除恢复漏洞**：`runtime/input_guard.py` 绑定用户锚点、ancestry 内容 hash、附件与授权；准入、模型调用、工具前后、完成前复核。旧无 guard 检查点私有保留但拒绝重放。`22fd1c5` 的 26 项恢复用例通过；此前独立工作树负向对照在修复前 `fcecb3c` 为 5 failed、21 passed，失败即新增缺口用例。
- **原文、事件、投影独立**：安全过滤后、预览截断前保存获准工具参数/结果、可见步骤与指导，64 KiB 分块，UTF-8 安全分页；不改原消息，不公开透传 opaque/signature/checkpoint。9 MiB 工具安全正文先保存，原生 checkpoint 超 8 MiB 明确失败；`replay_coverage` 不冒充原文完整性。
- **真实折叠**：先于附件、预算与原生回放整体替换闭合区间，历史位置一份概况；无效来源用失效提示，不能回退泄漏原文。关闭输入折叠恢复 raw 路径，仍受窗口约束。
- **安全回读与凭条**：`event_records` / `event_read` 限当前聊天 run，拒任务作用域。目录最多 20 项，正文默认 8 KiB/硬上限 16 KiB，每 run 正文 32 KiB/8 页；预算计最终 gateway body、双层 JSON 转义与 pending 结果，重复页返回引用。准入、读取、版本复验、记账在事务内完成。后续只读回查用有界凭条，mixed 写回合保留完整原生交换。
- **来源权限**：成员 digest、附件、任务来源逐次复验；新任务保存 `source_grants`，授权不明旧任务不能借关联重新授权。即使初始窗口未含事件概况，当前 run 新回读的来源也加入后续 HTTP 围栏。分支/删轮/授权变更沿原取消及命令清理路径处理，unknown 不解除。
- **可选整理**：独立 `EventSummaryRunner` 装配于 API 生命周期及 Supervisor，不恢复旧 learning worker。SQLite 去重、租约、最多三次尝试、并发 1、每作业全局 1～8 次调用；前台忙时让步。片段/输出有界，未遍历内容标 partial；仅引用实际提供来源。激活事务内同时复验来源、版本、租约。新 HTTP 前复验；最终 body 超窗或含当前整理模型凭据，零 HTTP 拒绝。
- **默认零额外整理调用**：默认禁用；即使选定并启用 profile，也仅显式点击生成才入队。结束事件立即用规则概况，不自动调用模型。取消/禁用可打断等待流；usage 缺失为 unknown，不记零。
- **最终复核修补**：DeepSeek 独立复核复现了 HTTP 前检查后 `sleep(0)` 期间撤回仍发送一次请求的竞态。现于 yield 后再次复验；正式负向回归在移除第二次复验时实际收到 1 次 HTTP 并失败，恢复后为 0 次且作业 stale、规则概况未改。runner 关闭新增主动 signal、等待当前任务、超时取消及停止领取新作业；直接关闭和 Supervisor→runner 关闭顺序的挂起流用例均在 2 秒断言内结束，注入 client 不被越权关闭。专项 **33 passed in 14.21s**；修补后全量回归通过，最终计数见下表。
- **维护恢复**：迁移 031～033；portable export v3 显式 base64 BLOB，旧 v1/v2 可导入。完整 DB 按自身 migration ledger 校验必需表，声明迁移而缺表拒绝；hash、字节数、块布局、归属损坏拒绝。完整备份保留私有围栏，与 portable export 承诺不同。
- **前端闭环**：原聊天开始/关闭、历史起点、事件卡、界面展开/收起与模型折叠独立、目录/片段、显式任务关联、预算、整理设置/用量/取消；丢弃换会话后的延迟响应。浏览器检查发现面板挤占输入框，修复独立滚动与高度限制后重新构建检查。

## 四、缺口、风险与体验验收

- **A12 与 A13 真实模型部分待验**：新增付费真实模型测试须另行授权；离线三协议通过不替代供应商互通、主动选证据及无据拒答验证。
- **历史边界范围**：起点到关闭时当前分支 head，可先选所需历史分支末端；不提供任意交错消息剔除、拆合或自然语言自动识别。旧缺采集保持 capture gap/raw；无授权快照旧任务拒绝关联，无批量迁移。
- **运行中窗口**：阶段一折叠已安全结束工作；单次 run 超窗仍安全终止，checkpoint 仍有 8 MiB 上限。阶段二未实施。
- **来源生命周期**：明确删除/撤回优先；缺资产停用投影及回读，未来新增清理器须遵守相同契约。已发送供应商内容不能追溯撤回。
- **生成可信度**：来源编号/结构校验不证明因果解释正确，文字保留生成/未核验标记；可人工编辑，修订不覆盖原文。
- **环境**：Windows 符号链接用例受本机权限限制而跳过；容器实机及生产升级未测，既有外部中转断连风险随 M1 档案保留。本轮未改生产数据。
- **关闭的验证范围**：已测试正常 signal 和 Supervisor 取消路径；强制等待超时分支及不响应任务取消的真实网络阻塞未单独验证。测试使用与 API 相同的关闭顺序，未以重启整套实际服务代替测试；不宣称所有底层网络情形均有严格关闭时限。

所有者体验建议先保持整理模型关闭：

1. 原聊天保留一个闲聊话题，开始工作，完成多轮工具/附件工作后结束，检查概况真实状态及覆盖范围。
2. 回到工作前话题，确认无需新开聊天；展开目录、分页原文后再收起。分别切换输入原始历史/概况，观察估算差异。
3. 追问概况没有的细节，观察是否目录→片段→有证据回答；再问无证据问题，检查是否明确未知。此项实际模型行为尚未替所有者判通过。
4. 再做第二段工作并回查，检查不串事件；编辑/换支后失效资料不继续使用。
5. 如选择可选整理模型，确认只有显式生成才调用，检查取消、覆盖范围与 usage 缺失提示；实际费用依所选模型另计。
