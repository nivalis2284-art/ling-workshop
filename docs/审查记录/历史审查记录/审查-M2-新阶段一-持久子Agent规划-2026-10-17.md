# M2 新阶段一规划审查（历史版）：持久子 Agent、生命周期与双轴权限

> 日期：2026-10-17。对象：新版 HANDOFF 的产品目标及当时 `main@064bebc` 产品能力。方式：GPT 主 Agent 源码/数据契约核对；DeepSeek Max 分别审计生命周期、权限隔离、UI/开源参考与阶段范围。状态：**研究规划完成，产品实施未授权，所有新能力均未实现或未验收**。**归档补充（2026-10-18）**：本文件中的“新增持久身份 / successor phase / 新 conversation”方案已被所有者对工作分支关系的澄清推翻；历史结论保持原样，当前依据见[当前计划](../../计划/计划.md)与[当前复核](../审查.md)。

## 一、结论

当前实现可让同一灵的独立 conversation 在后台执行受指导的工作，并在终态后形成 outbox、报告与经历；这部分可保留为子 Agent **执行体**。它还不是持久子 Agent：工作分支同时承担身份、阶段、conversation、run 和归档，`archived` 是终态，既不能给休眠身份开后继阶段，也不能靠翻转状态安全唤醒。`paused` 还混合了“本轮正常结束”和“运行在进展点暂停”；执行暂停依赖进程内存，重启后不会自动恢复。指导提交后界面会提前显示“已交给工作分支”，与真实步骤边界消费不一致。

权限当前只有逐 conversation 的 `confirm/full`；`full` 仅跳过聊天命令和 `mcp__*` 确认，不覆盖文件写入、任务、浏览器审批、依赖安装或网络。四档操作与三档网络尚不存在。本地执行档明确没有文件系统与网络隔离；容器可默认断网、只读根和固定挂载，但不是 VM；stdio MCP 是宿主子进程，HTTP MCP 直接访问网络；浏览器 origin 控制适合部分 N1，但不足以证明任意命令/MCP 的 N1。

因此推荐继续复用现有 conversation、ChatRuntime、checkpoint/effects、lease、outbox 与来源系统，新增持久身份和中继阶段；不引入第二套 Harness。阶段一完整交付真实权限，不过只交付“统一策略门”就宣布 N0/N1 已实现。P0 先探明网络隔离能力，无法可靠兑现的组合必须禁用或要求隔离 VM，需所有者确认产品呈现。

## 三、生命周期审计

可复用：独立 conversation、fork 背景、来源 hash/授权、持久 effect、checkpoint、执行租约、发布 outbox、经历分页与派生撤回。

不能复用为“持久身份”的：branch 单一状态、archived 后再 guide、已终结 run 的 checkpoint、TaskRuntime 终态恢复。建议最小模型：

- identity：`active | dormant | retired`，父灵、名称/角色、模型策略、授权策略版本。
- phase：`ready | running | idle | waiting_owner | blocked | closed`；一个身份可有多个 successor phase。
- run：继续使用 `chat_runs` 的 queued/running/paused/completed/failed/interrupted/unknown，并复用原 checkpoint/effect 规则。
- archive/return：outbox 的 pending/published/blocked；归档不销毁身份，不可变报告与来源保留。

唤醒顺序：旧阶段安全关闭、无 pending/inflight/unknown、回归身份与绑定复验通过 → 原子创建 successor phase（引用旧归档/经历）→ 新 conversation + 新 run。旧原生链不重放；若仍可恢复同一中断 run，先走同一 run 的恢复，而不是造阶段假恢复。

指导：持久队列记录 queued/consumed/failed/unknown，只有实际 append 入下一步模型输入后才标 consumed。普通回合完成、运行暂停、中断、阶段关闭显示为不同状态。unknown 不得以任何“继续/唤醒”清空。

## 四、权限审计

四档操作与三档网络必须是服务端事实。推荐统一执行路径：

```text
tool arguments → schema validation → effective policy snapshot
→ ExecutionGate (operation class + L risk gate)
→ environment/network enforcement (container/proxy/VM/command/MCP/browser)
→ effect fence → audit/result → next model step
```

工具元数据至少声明读写、外部副作用、网络方向、风险、未知能力。L2 批准绑定工具、参数、主体、目录、权限版本、网络模式和期限；参数/策略改变须重批。L3 只自动放行明确低风险动作。L4 不等于 OS/VM 越权。子 Agent 的有效策略取自身、父级和真实环境能力交集。

- L1：文件读取可做；不可证只读的命令、写入/发布/fill/click/未知 MCP 禁用。
- L2：拒绝不产生副作用；当前 confirm 只覆盖部分通道，需补齐文件写/任务/依赖/发布。
- L3：当前未实现分类；必须保守，不能把“未识别”自动降为低风险。
- L4：旧 full 只放行命令与 MCP 确认，不能直接提升其他能力。
- N0：无真实出口隔离的通道禁用；模型网关调用属于系统基础网络但与 Agent 自主联网分账，N0 不代表数据不发给模型供应商。
- N1：需真实出口代理/容器网络策略；精确 origin 只适用浏览器，不覆盖任意命令/MCP。绑定协议、主机、端口、方向、重定向、字节和有效期。
- N2：不创造操作授权、外部账号权限或 OS 权。

必须在 P0 实测 Windows 本地命令、容器、stdio/HTTP MCP、浏览器、依赖安装的实际隔离；不满足的组合显示“不支持/需要隔离环境”，不以虚假网络状态通过。旧 confirm/full 迁移保持 legacy 或逐主体确认，禁止静默提权。

## 五、UI 与经历审计

现有 WorkDrawer 是单次执行视图，不是身份管理。新 UI 应分层显示：身份 → 阶段链 → run → 结果与证据；服务端返回 `allowed_actions`、状态原因、revision、进入时间、指导状态和真实来源入口。前端不得自行推断可恢复性或权限。

最小状态/操作：暂停当前运行、继续当前运行、进入下一回合、恢复中断、唤醒休眠身份、人工核对 unknown、停止阶段。普通模型回合结束不能出现“继续当前运行”；unknown 不能出现自动继续；“唤醒”会创建 successor phase。所有 409/RevisionConflict 都应自动刷新并清除先前成功提示。

已确认两个可实施缺陷：归档 UI 用 `archive_id` 打开经历，真实经历 ID 为 `work-live:<branch>`；指导提交后立即显示已交付，但服务端并未证明已消费。两者应纳入 P5 端到端修复。

## 七、工作包与复杂度

| 包 | 主要结果 | 复杂度 | 前置 |
|---|---|---|---|
| P0 | 能力矩阵、网络隔离探针、迁移/回退、伪完成清单 | M | 所有者实施授权；真实网络探针按项目规则 |
| P1 | 身份/阶段/run/归档迁移、旧分支一对一 legacy | M | P0 |
| P2 | 独立执行、指导、暂停、恢复、休眠/后继唤醒、unknown 防护 | L | P1 |
| P3 | unified ExecutionGate、持久审批、四档、主体交集 | L | P1 |

总体复杂度高于上一轮常识编程安全默认，最大未知是 **Windows 本地命令/stdio+HTTP MCP 的 N0/N1**。若凭据/账号、共享文件或网络出口无法在标准环境真实约束，应让所有者确认隔离 VM/容器路径或禁用组合；不能把“UI 显示 N0”当完成。

## 八、验收与尚未验证

正式计划的 S1～S14 必须分别有可重现证据。最关键的负向包括：L1 全通道零写副作用；L2 批准跨参数/重启失效；L3 目录外/发布/未知 MCP 升级；L4+N0 无法从命令/stdio MCP/HTTP MCP 发现/浏览器/依赖出网；L1+N2 可联网读但不可写；子 Agent 无法超过父级；unknown 禁止自动恢复；归档后唤醒不改写旧阶段；指导恰好消费一次；双窗口操作 CAS 失败刷新。

尚未验证：新阶段任何代码路径、身份迁移、真实 Windows 网络隔离、容器实机、正式 provider 接受、真实模型语义质量、耐久跨重启唤醒、所有者体验。上一轮的 N16（性能）、N12（真实语义质量）、N17（真实 provider/owner）仍未关闭；N16 夹具本轮独立运行首轮即因不存在的 `add_source` 失败，发布持锁/并发 runner 仍为 pending，文件随后已原样恢复，不能计为通过。
