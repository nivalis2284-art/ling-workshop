# M2 阶段一实施复核：工作分支子 Agent、任务状态与唤醒

> 日期：2026-10-18。对象：本轮工作分支子 Agent 实现、迁移 037/038、当前工作区源码与自动化测试。方式：主 Agent 实现与真实运行测试、DeepSeek（MAX）独立只读审计、源码契约核对。状态：**P0/P1 主体及 P2 的持久暂停与同 run 恢复已完成离线验证；P3/P4 双轴权限、真实 provider、性能与所有者体验未完成**。

## 一、结论

本轮实现的是**现有工作分支的内部升级**，没有新增外层 subagent identity、父灵独立身份表或强制新 conversation。`continuity_work_branches.id` 仍是稳定子 Agent ID；任务状态版本、episode、run 与归档各自承担不同职责。同 branch 的归档后唤醒会复用工作 conversation，新建后继 episode，并由新 run 读取原目标、关键决策、未完成项、已验证事实、未知项与上次归档经历。

已完成的主要行为：

- 创建 branch 时写入初版任务状态与首 episode；旧库以加性迁移回填 legacy episode、任务状态和归档账，旧 status/archive/report 字段不被改写。
- 普通回合完成只结束本轮并暂停 branch，不冒充任务完成；显式 finish 仍需服务端归档围栏。
- 指导持久化到 branch/episode，只有真实进入原生 payload 后才写 `consumed_at`；进程重启会重投未消费的 delivered 指导。
- archived branch 可通过 `wake` 在同一 ID 下进入后继 episode；旧归档与私有 checkpoint/effect 不改写、不重放。
- 每次归档生成独立 `work-archive:<archive_id>` 经历；UI 使用该真实经历 ID 打开原文，不再用随机 archive id。
- 真实暂停由 `chat_run_controls.intent` 持久化；同 run 恢复会同步 branch/episode，并保留步骤边界暂停，不在启动时静默续跑。

## 五、缺口与风险

- 双轴操作/网络权限仍是产品承诺，不在本轮完成；P3 需要服务端策略门，P4 需要真实出口探针与跨通道负向测试。
- 持久暂停只覆盖步骤边界的运行意图；真实工具进程在暂停请求后仍按既有安全规则收尾，不能被描述为“立即停止”。
- 本轮使用 MockTransport 与真实 SQLite/coordinator 组合，不能替代真实模型语义质量、供应商网络与所有者操作体验。
- 迁移只做了 legacy 结构和归档字段测试；正式运行库的恢复演练仍需所有者环境执行，备份与代码回退保持分离。
- 前端默认并行 Vitest 在本机 Node 运行时出现 worker heap exhaustion；以 `--maxWorkers=1` 复跑后 26 个文件、179 项全部通过。该限制属于测试运行环境，仍需在目标发布环境复核。

运行数据备份位于 `.ling-data/backups/before-m2-phase1-subagent-2026-10-18.db` 及其 `.assets` 清单。迁移是加性的，旧表、原文、归档和私有 checkpoint/effect 保留；若新生命周期需回退，先停止应用，保留旧经历只读，代码回退与数据库恢复分别执行。
