## 结论与附件线索核实

| 线索 | 结论 | 证据及最终行为 |
|---|---|---|
| B1 局部任务状态丢字段 | **当前版本不成立** | 原实现已经合并旧字段；回归确认省略字段保留、显式 `[]` 清空。未按附件猜测改写契约 |
| B2 64/65 条进度 | **复现并修复** | 满 64 条时唤醒会在模型调用前失败；收尾超过上限也会破坏完成事务。自动进度保持最近 64 条，完整旧版本仍保存；模型显式输入 65 条继续拒绝。另修多字节最终文本加 JSON 元数据后超 2048 字节的问题 |
| B3 超量指导 | **复现并修复** | 65 条触发 Pydantic 校验异常。每次最多领取 64 条；未消费指导随安全后继 episode 转移，后继基线使用事务内最新任务状态版本；65 条分两轮消费且不重复建轮 |
| B4 普通工作聊天 | **复现并修复** | 普通请求可生成无 episode 的工作 run。现在直接交流同样原子绑定 branch/episode/run；paused 工作先通过安全唤醒，归档/待核/未知状态保留围栏；三协议直接交流和后继均有回归 |
| B5 前端可操作状态 | **修复确定错误，保留限制** | 活动工作不再提供完成入口，发送指导与暂停入口按真实状态收敛；完成前重新读取运行。未知 effect、关联任务交付等仍由服务端最终裁决，前端未复制整套安全规则，也未新增 P5 allowed_actions |
| B6 历史读取无界 | **确认并治理** | 四个历史 HTTP 接口默认最近 100 项，保持数组格式并支持 `before` 向前分页；域方法省略 limit 保留全量兼容。最新任务状态接口不变，旧记录未删除；完整旧历史暂通过 HTTP 分页回读，UI 展示最近窗口 |

## 额外发现并修复

| 缺陷 | 修复与回归入口 |
|---|---|
| 初始/中途指导在 payload 检查点失败前就标 consumed | 回执与精确原生 payload 检查点同事务提交；故障注入确认保存失败仍未消费，旧检查点没有新指导；拒绝与实际输入不匹配的指导 ID |
| 恢复 model_inflight 时插入新指导改变重试请求 | 新指导仅在 ready 阶段、闭合工具交换后进入输入，正在恢复的原生请求保持原样 |
| 崩溃发生在 starting claim 后、run 提交前，会把 episode 错误关闭 | 重新排队时保留活动 episode；run 与 branch/episode 在 submit 的同一事务绑定，取消协调器事后的重复认领 |
| 协调器处理冲突时会覆盖抢先成功的直接聊天运行 | 独立复核复现交错时序；失败回写以 current_episode_id、run_id 为空及 queued/starting 状态做 CAS，不能回退新运行 |
| paused 工作追加指导可绕过 wake 的安全检查 | 开启后继前执行相同 safe/fork 围栏；pending checkpoint 等负向测试证明普通指导不能解锁 |
| 旧 outbox 发布/阻塞会改写新归档的 return_state | 仅更新相同 archive_id/result_revision 的分支展示；多次归档后逐批发布保持最新状态正确且幂等 |
| 没有主干摘录时，持久任务状态被漏出模型输入 | 即使背景为空仍投影任务状态；补上进度、产物与来源引用；任务包按 UTF-8 字节计上限，三协议实际请求验证 |
| 一个失效 fork 中断整个调度 tick | 单分支进入 pending_review 并保留原因，其他个体及 outbox 继续处理；来源编辑后的跨个体回归证明不饥饿 |
| portable 漏掉来源 epoch/附件关联版本账 | 补全公开版本账，恢复触发器完成后一次性替换并核对覆盖，真实往返验证来源有效性；私有 checkpoint/effect 和运行意图仍只在完整备份中保留 |

核心跨层回归在 `tests/test_work_runtime_maintenance.py`；存储、状态合并、安全后继、分页与查询计数在 `tests/test_work_maintenance.py`；portable/备份真实往返在 `tests/test_maintenance_audit.py`。

## 技术债治理与性能

- 工作列表的最新归档改为单条关联查询；8 个分支的 SQL trace 回归确认归档读取由逐分支查询变为 1 条。返回结构保持一致。
- 前端逐 SSE 事件同步更新内存与订阅者，增量 sessionStorage 写入按 400 ms 合并；开始、终态、断线/离开页面保留即时落盘。60 个文本增量的回归样本在冲刷前至多 1 次写盘；pagehide 后明确核对完整 60 字与 `lastSeq=61`，不通过跳过事件减少写入。
- 会话清理覆盖计时器、请求与页面监听，并保持 StrictMode 清理/重挂载后的会话身份稳定。
- 回归发布使用已有公共 `append_assistant` 服务，删除 `runs[-1] if runs else None` 无效表达式；没有增设平行对话写入协议。
- 本机隔离样本（每项取 5 次读取加 JSON 的中位数）：1001 个任务状态、每版 8 条代表性进度，全量读取 2,933,178 字节 / 36.186 ms；最近 100 项为 293,000 字节 / 14.228 ms。256 个分支的相同列表 JSON 均为 201,450 字节，旧逐分支查询 914.333 ms，关联查询 11.395 ms。原始样本位于被忽略的 `.artifacts/maintenance-2026-10-18/performance.json`，不接触运行库。这些样本只证明局部成本变化，不能替代 M2 N16 正式性能验收。

## 保留的技术债与未验项

- `ChatRuntime` 仍集中处理模型循环及工具恢复。本轮只修复实际事务边界并移除重复认领；大规模拆分/重写会同时扰动三协议、租约和 effect，缺乏额外收益证据，暂不实施。
- 反思与摘要后台作业虽然都使用模型、租约与重试，但冻结快照、日历槽、预算和发布策略不同；未为形式引入通用 Runner。未把静态相似判成 Bug。
- 页面级组件保留职责；仅处理复现的操作与会话成本问题。前端按钮不是全部服务端安全围栏的镜像。
- HTTP 双路径兼容保留；封存第二部分模块、旧迁移、unknown 与历史数据保留。
- P3/P4 双轴权限、真实网络隔离、真实付费 provider、长期语义质量、完整故障矩阵与所有者体验未验；旧 N12/N16/N17 继续开放。
- 本轮未在真实 `.ling-data` 上恢复备份、迁移或改写数据，未进行收费模型测试。完整数据库/附件恢复仍需停应用后独立演练。
- SSE 合并窗口内浏览器被强制终止时，最新内存字节可能尚未写盘；正常 pagehide/断线/终态会冲刷。重连从同一持久快照的文本及游标继续，仍需真实长时间浏览器帧率、存储配额和 provider 场景验证。
