# 0.1.1：密钥缓存、多提供商与图标

用户的新要求替代0.1.0仅内存的日常凭据策略：模型密钥保存到可清理的本地缓存，重启不必再次填写；允许同时保存不同提供商；EXE用上传头像，网页标签用现有叶状logo。没有将用户此前提供的真实测试密钥主动保存，本轮仅使用合成密钥，不调用付费模型。

## 实现

- Windows桌面/API启动时启用cache/model-credentials.bin。使用Windows当前用户DPAPI加密完整内容，写临时加密文件后原子替换；数据库与模型列表不包含密钥。独立业务Application测试默认保持内存模式，可显式启用缓存。
- 每个连接以自身ID绑定服务URL和密钥，多个官方/第三方提供商可以同时保存。修改一条不改其他条，改URL清除旧绑定，不能改回URL复活旧密钥；主备选择可跨提供商。
- 设置→模型连接→清除模型密钥缓存，经确认删除文件并清除进程内密钥，保留模型配置、对话与记忆。已发出的请求可能完成，后续调用需重新填写。退出清除进程内副本，正常重启重新解密缓存。
- 缓存缺失/损坏不会阻止启动，显示缺少可用凭据；GET /api/models/credentials/cache提供静态错误状态。缓存与清除端点需要所有者认证。备份/导出排除缓存，移动到另一Windows用户不承诺可解密。
- 程序、托盘和安装程序使用上传头像。PNG长期资源按512保存，ICO包含16/24/32/48/64/128/256七种分辨率，最终EXE含7个图标资源。网页favicon.svg复用现有Lucide Sprout的叶状路径和界面色彩，随前端静态资源打包。

官方加密机制参考：[CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。没有使用LOCAL_MACHINE范围，也没有存明文或写操作系统凭据库。
