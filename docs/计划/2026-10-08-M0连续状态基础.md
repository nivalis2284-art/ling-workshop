# M0 连续状态基础 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 先实现可持久保存、可演化、可纠正且能够影响下一次上下文的灵的状态基础。

**Architecture:** Python 模块化单体；SQLite 是状态权威来源，领域服务校验变更，ContextBuilder 只读取有效状态。M0 不调用云端模型、不开放终端／网页工具，使用明确标记的测试数据验证状态闭环。

**Tech Stack:** Python 3.12、Pydantic 2、SQLite／sqlite3、FastAPI、Uvicorn、pytest、Ruff、Pyright；实施时锁定兼容补丁版本。

**Spec:** [实现基线](../设计/2026-10-08-实现基线.md)。上层：[01](../../../docs/01-概念与原则.md)、[02](../../../docs/02-抽象需求.md)。

## 全局约束

- 不把初始人设当作永久人格；初始化一次，以后读当前有效版本。
- 普通经验和低风险行为改进自动；身份、关系、价值判断、重大人格／重要能力变化先确认。
- SourceRef 总是包含 id 和 revision；时间使用 UTC；测试显式注入时钟。
- 测试中的改进候选是模拟输入，不证明模型已自动学习；没有真实模型调用不填写缓存／费用实测数字。
- 不安装 Hermes／Letta 全套，不引入向量库、图谱或分布式工作流；不执行用户真实项目文件。
- 代码、测试与迁移只在当前 Ling 工作目录新增；01／02、归档方向 A 保留。先 git init 再建工作分支（原目录非 Git 仓库），不需对空项目建无意义的第二份副本。
- 每任务完成后跑对应语义测试；最终一次运行全部检查。只有结果通过才能提交对应变化；提交不等于推送。

数据契约：

~~~python
class SourceRef(BaseModel):
    id: str
    revision: int

class ProposalInput(BaseModel):
    request_id: str
    agent_id: str
    base_revision: int
    kind: Literal['habit', 'identity', 'relationship', 'value',
                  'major_personality', 'major_capability']
    key: str
    text: str
    sources: list[SourceRef]

class SelfSnapshot(BaseModel):
    agent_id: str
    revision: int
    entries: dict[str, str]

class ContextPacket(BaseModel):
    instructions: str
    evidence: list[dict]
    manifest: dict
~~~

以上为最小对外模式；实际加 strict 校验、UUID／revision／非空验证和枚举定义。kind 不能单靠模型填写决定权限：提交器将用户明确指令与模型提案区分，identity 服务检查目标 key 所属类别；未知类别不能自动应用。M0 自动键仅允许预先注册的低风险 communication.habit.*，不能编辑 owner.*、identity.* 等受保护项。自由文本中是否暗含重大变化属于 M2 的语义审核；在该审核完成前，不自动接受来自外部模型的任意自由文本习惯。

服务接口（同步领域调用，在 API 中使用合适线程边界；不在事件循环直接做长数据库工作）：

~~~python
HistoryService.add(agent_id, content, *, kind, scope, request_id) -> SourceRef
HistoryService.correct(source: SourceRef, content: str) -> SourceRef
MemoryService.save_episode(agent_id, title, summary, sources, *, request_id) -> str
MemoryService.read_episode(episode_id: str) -> dict
MemoryService.read_sources(refs: list[SourceRef]) -> list[dict]
IdentityService.propose(value: ProposalInput) -> dict
IdentityService.decide(proposal_id, decision, *, expected_revision, actor_id) -> dict
IdentityService.current(agent_id: str) -> SelfSnapshot
ContextBuilder.build(agent_id, *, source_refs, purpose='conversation') -> ContextPacket
MaintenanceService.export_to(destination) -> dict
MaintenanceService.restore_from(source, destination_db) -> dict
~~~

所有 service 由相同应用容器创建，消费 UnitOfWork／连接工厂；服务不能自行提交另一个领域的半成品。correct 通过维护协调器在同事务标记依赖失效，单个 HistoryService 不进行模型重算。读失效资料抛 SourceInvalid；审批版本冲突抛 RevisionConflict；API 分别映射为409，未知对象404，校验错误422。

def test_identity_change_waits_for_owner(app, agent_id, source_ref):
    proposal = app.identity.propose(ProposalInput(
        request_id='p1', agent_id=agent_id, base_revision=0,
        kind='identity', key='identity.description',

def test_summary_does_not_replace_source(app, agent_id):
    src = app.history.add(agent_id, '测试记录：约定周五15:30复查',
                          kind='user', scope='test', request_id='detail')

def test_correction_blocks_stale_approval(app, pending_with_source):
    proposal, ref = pending_with_source
    app.history.correct(ref, '测试纠正：原判断不成立')

## 交付判定

M0 完成的证据是上述确定性测试、启动／重启和导出恢复结果；不得以“文件已创建”或“运行没报错”替代。M1 开始时再锁定前端／Pydantic AI 和 SDK 版本并细化三端点适配测试，避免本批无用依赖。

M0 是可以直接开始编码的最小完整基础，不是完整 LingNexus 可用版；M1～M4 在实现基线中保留全部既定需求和对应验收方向。
