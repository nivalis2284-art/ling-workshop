# C 阶段 · 统一 Agent 循环（契约）

> 创建日期：2026-10-11
> 恢复点：tag `post-B-sandbox`（B 提交 `45a3813`）
> 已确认决策：工具集**低层原语为主**；任务**合并进对话**；上下文**只做截断 + 提示**；Hooks **三个事件**
> 目标：让"能说"和"能做"变成同一件事——**对话即循环**

---

## 一、目标

现在这个系统把 Agent 能力切成了两条互不相通的路径：**聊天**（能说不能做，模型一要求调工具就失败）和**任务**（能做但门槛高，要单独建、选目录、审批）。

C 阶段要把它合成**一条循环**：模型可以请求工具 → 系统执行并回传真实结果 → 模型继续 → 直到完成或需要用户介入。

---

## 二、冻结接口

### 2.1 工具接口

单一注册表，所有工具在此声明；**聊天循环与任务循环共用同一个注册表**。

```
ToolSpec
├── name: str
├── description: str
├── parameters: 一个 pydantic 模型（用于生成 JSON Schema）
└── kind: "command" | "file" | "browser" | "meta"

ToolRegistry
├── specs() -> list[ToolSpec]
├── schema() -> list[dict]        # 发给模型的工具声明
└── get(name) -> ToolSpec | None

ToolResult
├── status: "completed" | "failed" | "blocked" | "unknown"
├── content: str | list[dict]     # 回传给模型的内容
├── error_code: str | None
└── effect_id: str | None         # 有现实副作用的调用，用于事后核对
```

### 2.2 工具集（原语为主）

| 工具 | 类别 | 说明 |
| :--- | :--- | :--- |
| `run_command` | 命令 | 经执行沙箱运行（默认本地受限档），参数列表，无 shell |
| `read_file` | 文件 | 读授权目录内文件 |
| `create_file` | 文件 | 新建，不覆盖 |
| `write_file` | 文件 | 覆盖已有文件 |
| **`edit_file`** | 文件 | **新增**：按精确文本片段替换（文本编辑原语） |
| **`search`** | 文件 | **新增**：在授权目录内按模式查找（文件名 + 内容） |
| 浏览器类工具 | 浏览器 | 保留现有 |

**自定义动作大幅精简**：不再新增语义化专用动作，能用原语组合的一律不做成工具。

### 2.3 Hooks 接口

**机制与策略分离**：循环负责推进，钩子负责施加控制。**权限、审计、策略一律通过钩子注入，不写进循环体。**

```
HookEvent
├── BEFORE_TOOL       工具调用前（权限检查、越界拦截）
├── AFTER_TOOL        工具调用后（审计、结果留痕）
└── BEFORE_TURN_END   回合结束前（将来挂回第二部分的挂载位）

HookResult
├── allow: bool
├── reason: str | None
└── replacement: dict | None     # 可选：改写参数或结果

HookRegistry
├── register(event, handler)
└── async run(event, payload) -> HookResult
```

**`BEFORE_TURN_END` 现在就留出来**——它是将来加回第二部分（记录经历、取上下文）的挂载位，留出来以后挂长期记忆时循环体一行都不用动。

### 2.4 循环与事件协议（给前端）

一次对话回合变成带步数预算的循环。事件流新增：

| 事件 | 载荷 |
| :--- | :--- |
| `step_started` | `{run_id, step}` |
| `tool_started` | `{run_id, step, name, call_id, arguments}` |
| `tool_result` | `{run_id, step, name, call_id, status, preview}` |
| `paused` / `resumed` | `{run_id}` |
| `notice` | 已有的截断提示，继续复用 |

保留原有 `started` / `text` / `thinking` / `usage` / `notice` / `model_switch` / `complete` / `error`。

**完成条件**：模型不再请求工具，或步数预算用尽（用尽时如实提示，不谎称完成）。

### 2.5 控制接口（中断与介入）

| 接口 | 作用 |
| :--- | :--- |
| `POST /chat/runs/{run_id}/pause` | 在下一个步边界暂停 |
| `POST /chat/runs/{run_id}/resume` | 继续 |
| `POST /chat/runs/{run_id}/guide` | 提交一条中途指导，在下一个步边界注入循环 |

**暂停发生在步边界，不强杀正在执行的工具。**

### 2.6 任务合并

- 对话成为唯一入口。任务的多步执行能力**下沉为对话循环本身的能力**。
- 旧的"建任务"路径与界面**收进对话**，不再要求用户理解"什么时候该用对话、什么时候建任务"。
- **权限与审批原则不变**：授权范围、重要/不可逆操作确认，从"任务的前置条件"变成"循环中的实时约束"（通过 Hooks 注入）。
- 现实副作用的核对机制（效果确认、写回审阅）保留。

## 四、验收标准

1. **对话内能真的做事**：在对话里让模型读文件、改文件、跑命令，它能真的做，并**如实报告结果**（成功就是成功，失败不许粉饰）。
2. **多步循环**：一个需要多步才能完成的目标，能在**一条对话**里连续完成。
3. **步数预算用尽时如实提示**，不谎称完成。
4. **Hooks 真的在起作用**：权限检查确实通过钩子执行——用一个测试证明"移除钩子后越界操作不再被拦"。
5. **暂停/恢复/中途指导**都能在步边界生效。
6. **任务不再是必经之路**：用户不需要理解"该用对话还是建任务"。
7. **权限与审批不放松**：越界操作在对话循环里同样被拦；重要/不可逆操作仍需确认。
8. **既有测试全绿**；新增循环、工具、钩子、控制的测试。
9. **不回归**：模型不请求工具时，行为与现在一致（纯文字回复照常）。

## 五、禁令

- 不改第二部分模块。
- **不做 F 阶段的事**（技能包、MCP）。
- 不引入新的第三方依赖。
- 不改数据安全相关行为（备份、恢复）。
- **不把策略写进循环体**——一切策略走 Hooks。这是本次的结构性要求。
- 不删除执行沙箱的两档能力（B 阶段成果）。
