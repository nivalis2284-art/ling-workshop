## 一、产品结果

灵能在一条持续主干中直接处理简单任务；对适合独立推进的复杂任务，可创建具有持续身份的子 Agent。子 Agent 在独立上下文中自行规划、调用获准工具、接受中途指导，可暂停、休眠、重启后找回历史，并以同一身份开启后续工作阶段。任务收尾时只向主干回归实际状态、结果和证据入口，完整过程保留且可按需回查。整个过程形成可追溯的共同事件关系。

权限是同一产品闭环的一部分：每个主体同时拥有四档操作权限与三档网络权限；服务端统一执行，无法可靠兑现的组合明确禁用。UI 只展示和执行服务端给出的能力，不能靠按钮制造权限。

阶段二再深化上下文压缩、长期连续性和休眠后的状态延续。阶段一仍须维持正常执行所需的基础上下文、原生协议续接、来源与副作用安全。

## 二、当前事实与复用结论

基线为 `main@064bebc`。以下结论来自本轮源码核对与独立审计，是实施起点而非完成声明。

| 现有能力 | 可复用部分 | 关键限制 |
|---|---|---|
| 工作分支 `continuity_work_branches` | 独立 conversation、目标、fork 背景、owner 与来源快照、当前 run、outbox、经历 | 一个对象同时承担身份/阶段/运行/归档；`archived` 是终态，不能唤醒；同灵只有一个活动工作 |
| `BranchCoordinator` | 排队、运行、指导、终态核验、归档和发布 | 真正运行暂停只在内存；重启后控制丢失；不自动恢复工作 run |
| `ChatRuntime` | 多步原生工具循环、checkpoint、effect、输入守卫、暂停/恢复、指导 | 一次 run 的工作锁是 `agent_id`；运行暂停不是阶段暂停；终端 run 不能恢复 |
| `TaskRuntime` | durable worker、持久指令、pause/resume/cancel、副本与交付围栏 | 不属于子 Agent 身份；终态不能恢复；不能充当第二套统一子 Agent 运行器 |
| conversation/checkpoint/effects/lease | 历史、原编辑树、恢复点、执行安全 | 不能把私有 checkpoint 当公开经历；不能为唤醒而重放副作用 |
| experience/source/dependencies | 索引、分页原文、来源与派生失效 | 前端归档入口使用 `archive_id`，与真实经历标识 `work-live:<branch_id>` 不一致，现有宽容 mock 未证明真实链路 |
| 权限与沙箱 | 文件目录 grants、聊天工具 hook、浏览器 origin、容器无网络、原生 MCP 客户端 | 只有会话级 `confirm/full`；full 仅放行聊天命令和 MCP 确认；本地命令无文件/网络隔离；无统一 L1～L4×N0～N2 |
| 经历与反思基础 | 权威原文、来源版本、依赖账、任务/工具证据 | 阶段一不重做完整长期记忆；新子 Agent 阶段须归入同一经历根，不能另建不可关联流水账 |

四层必须分开，不能用一个新字段代替：

1. **子 Agent 身份**：持续存在；至少 `active | dormant | retired`。
2. **工作阶段**：一个身份可拥有多个阶段，阶段用 predecessor/lineage 关联；至少明确“待开始、执行中、本轮结束待下一步、等待所有者、可恢复中断、阻塞/人工核对、关闭”。
3. **执行 run**：继续使用 `chat_runs` 及其 checkpoint/effects/lease，不复制第二套原生运行器。
4. **归档与回归**：不可变结果、outbox 和经历来源；归档只关闭阶段，不等于销毁身份。

## 三、推荐架构

### 3.1 渐进演进，不重写会话核心

保留现有 conversation 树、原生多步运行器、tool effects、execution leases、来源索引与 outbox。新增持久子 Agent 身份，并给工作分支加性升级为阶段（继续沿用 branch ID 作为 phase ID 可减少迁移风险）；单次 run 仍由 `ChatRuntime` 执行。

首版允许多个身份存在、休眠和排队，但继续限制“一个主干运行 + 一个子 Agent 运行”以控制文件系统双写；更复杂的并发在独立性、隔离和资源证据充分后再扩展。子 Agent 的文件、命令、浏览器、MCP 权限不得因被创建而扩大，有效权限取“自身配置 ∩ 父级上限 ∩ 执行环境实际能力”。

不接入第二套主 Harness。LangGraph/Deep Agents/Letta Code/OpenAI Agents SDK/A2A 等继续作为机制对照：durable run、subgraph 私有状态、agent-as-tool、resume-by-ID、下发指导和非流水账进度值得借鉴；完整框架的依赖、运行时、来源权限、owner 审计与 SQLite 恢复契约必须单独证明，不能以换框架替代产品实现。

### 3.2 生命周期与唤醒

- 一个阶段使用独立 conversation；fork 只带入任务必需、有来源且预算内的背景，不复制灵的全部提示词、记忆或权限。
- 正常模型回合结束与真实运行暂停分开。前者允许“下一回合”，后者才提供“继续当前运行”。
- 重启后：checkpoint、input guard、来源、授权、workspace 版本、命令/session 全部可确认时才恢复同一 run；否则停在可解释的 `interrupted/blocked/pending_review`，保留人工核对。
- 阶段正常关闭后，身份变为 `dormant`。再次唤醒创建 successor phase，引用旧归档与经历，开启新 run；绝不把旧 `archived` 改回 queued，也不重用旧完成 checkpoint 重放原生状态。
- 任一步骤有 pending/inflight 审批、未知命令、未知 effect、未完成交付或无效来源，自动唤醒必须被拒绝。
- 指导必须持久化并暴露 `queued | consumed | failed | unknown`；只有模型循环在步骤边界实际消费后才算送达。`runtime.guide()` 的入队调用不等于已送达。
- 同一工作全部阶段共享 `subagent_id` 和共同经历根；run、阶段归档、指导、回归和产物分别保留 ID，方便按需追溯。

首版不承诺云端跨设备恢复、任意进程迁移或“无缝复活不可见思维链”。承诺的是持久身份、可合法找回的已保存状态、后继阶段的真实连续性，以及不能恢复时如实说明。

### 3.3 统一执行与双轴权限

服务端单一 `ExecutionGate` 在参数校验后裁定所有已启用执行通道；chat、task、子 Agent、后台与工具代理都不能绕开。工具能力声明应至少包含读、写、外部副作用、网络方向、未知能力与风险等级。未知工具和无法验证能力的远程工具 fail closed。审批和网络授权必须持久化并绑定主体、参数摘要、工作目录、权限版本、网络模式与有效期。

| 操作档 | 产品语义 | 关键实施边界 |
|---|---|---|
| L1 只读 | 可查看/分析获准资料 | 文件写、命令写操作、浏览器 fill/click/发布、MCP 外部副作用均拒绝；无可靠只读保证的命令禁用 |
| L2 操作前询问 | 有副作用操作逐次批准 | 拒绝后零副作用；参数/目录/策略变化使旧批准失效；批准不能跨主体复用 |
| L3 自动低风险 | 授权范围内普通读写与测试自动执行 | 发布、外部账号、凭据、敏感/目录外操作升级；高风险分类不能猜 |
| L4 完全放权 | 取消产品内普通审批/风险门 | 不突破 OS、VM、容器、服务账号与网络策略，不自动获得新目录或新网络 |

| 网络档 | 产品语义 | 最低可信实施 |
|---|---|---|
| N0 禁止 | Agent 自主网络访问为零 | 所有保留通道须有真实出口隔离；无法隔离的通道禁用；模型网关系统调用另账，且 N0 不等于上下文不会发往模型供应商 |
| N1 白名单 | 仅所有者允许的目标与方向 | 真实出口代理/网络策略，绑定协议、主机、端口、方向、重定向、字节上限和期限；浏览器 origin 白名单单独不能证明命令/MCP 的 N1 |
| N2 完全网络 | 在操作与环境权限内自主联网 | 不自动获得发布、支付或外部账号动作，仍受 L 档、OS/VM 和凭据边界 |

现有 `confirm/full` 不能无损改名为 L2/L4：`full` 只放行聊天中的命令与 MCP 确认，若直接映射为 L4 会扩大文件、浏览器和任务能力；强制映射也可能改变既有联网行为。迁移需保留明确 legacy 语义，或经所有者逐主体确认新策略，禁止静默提权。新建主体建议从 `L2 + N1（空白名单）` 开始；已隔离 VM 才可显式选择宽权限。

### 3.4 执行环境分级

- **本地执行**：命令参数直传、资源上限与进程清理可复用，但当前不提供文件系统/网络隔离，不能宣称 N0/N1 已兑现。
- **容器执行**：默认无网络、只读根、仅工作副本、非 root，可作为较强边界；它与宿主共享内核，不能称为 VM 级安全。
- **stdio MCP**：宿主子进程；**HTTP MCP**：直接远端请求。二者必须受统一策略与实际网络边界控制，不能只看工具名。
- **浏览器**：宿主 Chrome 中的应用层 origin/重定向/WebSocket 控制对 N1 有价值，但不能抵御浏览器/内核漏洞或所有数据外传形式。
- **隔离 VM**：若标准环境无法可靠兑现通用命令/MCP 的 N0/N1，应明确标为不支持，或在所有者批准的隔离环境中选择宽权限。具体网络实现可在 P0 探针后调整，但不得淡化“真实双轴”。

### 3.5 经历与回归

阶段结果先形成可核验结构化事实：真实运行终态、执行与交付分开、已验证/未验证/未知、产物、来源和后续入口。回归文本在主干无活动 run 时通过 durable outbox 幂等追加；来源、绑定或版本变化则阻塞而非用旧摘要冒充新状态。完整经历保留在工作阶段，身份根关联全部后继阶段。UI 展开与历史页面读取零模型；Agent 按需读取保留分页、来源权限和每 run 预算。

正常收尾报告包含：工作目标、可证实结果、未完成/风险、验证范围、真实交付状态、分支/阶段/经历 ID、发生时间与回忆入口。模型声称“完成”不能覆盖实际 effect 或 verification。

## 四、实施工作包与依赖

以下为研究后的推荐顺序。实施前须由所有者另行授权；工程中可局部调整边界，但不能把阶段一拆成“只有 UI”或删除安全底线。

| 工作包 | 内容 | 进入下一步的证据 |
|---|---|---|
| **P0：契约、迁移与能力探针** | 清点全部执行通道；Windows 本地命令、容器、stdio/HTTP MCP、浏览器、依赖安装的真实网络隔离探针；旧数据迁移/回退；冻结伪完成条件与验收矩阵 | 每种目标组合被判为可兑现/需隔离/不可支持；无产品数据迁移；真实测试预算另行确认 |
| **P1：身份与阶段模型** | 持久子 Agent、父灵、角色/模型策略、权限版本；branch 加性升级为阶段；身份/阶段/run/归档分层；旧分支一对一 legacy 迁移，不猜测合并 | 旧资料 hash 不变；重启后身份/阶段/run 归属正确；归档不再等于身份死亡 |
| **P2：生命周期与恢复闭环** | 创建、指导、暂停、本轮结束、休眠、后继唤醒；run 恢复与后继阶段分离；持久指导状态；unknown 阻断与人工核对；effect-once | 主干并行聊天；真实暂停/普通结束区分；指导恰好一次消费；重启恢复不重复副作用；归档后同身份开新阶段 |
| **P3：统一执行策略** | 工具能力元数据、ExecutionGate、四档风险语义、持久审批/审计、主体与父级权限交集、任务/后台接入 | L1 无写副作用；L2 批准失效；L3 仅低风险；L4 不突破既有边界；未知工具默认严格 |
| **P4：网络策略真实落地** | N0/N1/N2 的真实出口控制，命令/MCP/浏览器/任务覆盖；无法隔离组合禁用；模型基础网络分账 | L4+N0 各旁路零外网；L1+N2 只读；N1 重定向/IP/私网/端口/方向负向通过；无伪造网络状态 |
| **P5：管理与经历体验** | 子 Agent 列表/阶段链/运行与真实状态；服务端 `allowed_actions`；指导状态；结果与证据；休眠/唤醒；权限设置；归档经历键修复；竞争刷新 | 按钮行为与服务端一致；归档原文入口真实可读；409 后刷新且不保留成功；UI 零模型 |
| **P6：最终验收** | 迁移/备份/恢复、协议、权限矩阵、故障注入、性能与成本、所有产品场景；必要真实模型测试与所有者体验 | 自动化证据与人工体验分别记录；未验项明确；不得用旧 M2 结果替代 |

P0 的隔离结论会决定 P4 的承诺；若无法在不降低产品目标的前提下实现某一组合，应向所有者提出可理解的取舍，而不是把 UI 标签写成“已支持”。

## 五、验收矩阵

以下针对新目标，不继承旧 N1～N17 的通过结论。

| 编号 | 场景 | 必须满足 |
|---|---|---|
| S1 直接处理 | 简单问题/小型工作 | 灵直接完成，不强制创建子 Agent |
| S2 独立执行 | 复杂多步任务 | 子 Agent 自主规划、工具执行、失败修复；主干同时可正常聊天；其上下文不代表全灵记忆 |
| S3 中途指导 | 运行中与休眠中补充要求 | 指导持久、单调、绑定阶段；未消费不显示已送达；重启不丢不重；不重放旧副作用 |
| S4 暂停与恢复 | 工具边界暂停、进程重启、checkpoint 有效/失效 | 真实暂停与普通回合结束分开；可恢复时恢复同一 run，不可恢复时如实阻塞；写入次数 exactly once |
| S5 休眠与唤醒 | 阶段归档后再唤醒 | 同一 `subagent_id` 创建后继阶段；旧阶段/归档/经历只读保留；不改写历史或重放已完成原链 |
| S6 失败与未知 | 命令清理未知、effect unknown、交付待审、来源撤回 | 不显示完成、不自动唤醒、不靠普通指导解除；证据/人工核对入口可用 |
| S7 回归与共同经历 | 终结报告、主干追加、多个阶段、原文回读 | 报告有真实状态/时间/来源/入口；回归幂等且不抢写主干；全部阶段可归入同一身份经历根；UI 展开零模型 |
| S8 操作权限 | L1～L4 各工具类别与审批变化 | 服务端实际拦截；未知工具默认严格；旧批准失效；四档语义与计划一致 |
| S9 网络权限 | N0/N1/N2 跨命令、stdio/HTTP MCP、浏览器、任务、依赖 | 无旁路；不支持组合禁用；模型基础网络与 Agent 自主网络可解释；不伪造隔离 |
| S10 子 Agent 权限交集 | 父级降权、子 Agent 配置、环境能力组合 | 子 Agent 永远不得高于父级；降权立即影响后续调用；外部账号/OS 权限仍为硬边界 |
| S11 迁移与回退 | 旧 branch、v4 portable、完整备份、旧 confirm/full | 原文/归属完整；不静默提权；private checkpoint/effect 不进 portable；unknown 保留；代码与数据恢复分离 |
| S12 竞争与可观测性 | 两窗口同操作、状态陈旧、长任务进度 | 服务端 CAS 拒绝旧操作；界面刷新真实状态并说明未执行；进度不伪装工具流水账 |
| S13 性能与资源 | 多身份历史、阶段链、权限审计、回忆分页 | 冻结实测门限；前台准入与事件循环不受后台整理拖垮；不无界扫描、不泄漏；设备/样本可复核 |
| S14 真实模型与体验 | 获授权后的实际 provider 与所有者操作 | 工作连续性、指导接收、归档回归、经历召回与无据拒答分别验证；usage/费用 unknown 不记零；所有者最终体验 |

自动化、真实模型和所有者体验分别记录，不能用结构夹具或前端 mock 代替语义和真实行为。N12/N17 等旧记忆语义与付费测试若需要，仍应单独取得测试费用授权。

## 六、风险与恢复

| 风险 | 防护与退出路径 |
|---|---|
| 身份/阶段/run 混写导致“唤醒”等于重放 | 四层分表/分列；仅后继阶段唤醒；旧归档只读；checkpoint 合法性守卫 |

| 子 Agent 泄漏灵全部记忆/权限 | 显式任务背景、来源、授权交集；不复制系统提示与完整历史 |
| 回归改写主干/历史 | 不可变归档、outbox、CAS/绑定复验；不抢活动 run；原文 hash 不变 |
| 经历入口/UI 键不一致 | 修复真实契约并用端到端 API 断言；禁止宽容 mock 冒充通过 |
| 上下文长任务仍会失败 | 阶段一保留 checkpoints/安全停止/基础压缩；阶段二深化连续压缩；不承诺无限长 run |
| 真实隔离受 Windows/容器/MCP 限制 | P0 明确支持能力与所需 VM；保留本地与容器分级，不称本地为安全沙箱 |

恢复：实施前备份完整数据库、附件、任务与私有效果/checkpoint；迁移只增不删，旧字段/表保留到复验。关闭新功能应回到既有 conversation/工作只读路径，不自动丢弃已回归报告，也不把 portable 导入当副作用可续跑。代码回退与数据恢复分开；不删除 unknown 来“恢复”。
