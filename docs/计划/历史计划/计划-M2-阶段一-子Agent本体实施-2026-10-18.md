## 一、产品结果

灵判断任务适合独立推进时，创建工作分支；这个工作分支在产品语义上就是承担该任务的**子 Agent**。它继承任务必需的主干背景，拥有独立的工作上下文、目标、执行、指导、历史与状态。主干继续交流，并负责委托、监督、追加需求和整合结果。

子 Agent 可以在任务阶段结束时休眠，完整经历保留。需要继续相关工作时应唤醒**原来的子 Agent**，使它基于原目标、关键决策、进度、未完成项、来源和已验证事实继续，而不是只凭 ID、历史引用或一段摘要造出没有任务理解的新 Agent。

阶段一以可观察的工作主体及经历连续性为验收标准，不要求整个生命周期只能使用一条 conversation 或一个 run。branch、task state、episode、run 和归档各有职责，但只有 branch 是稳定的子 Agent 主体。

四档操作权限与三档网络权限仍是已确认的产品目标。权限工程是子 Agent 执行能力的组成，不应把本体开发长期挡在基础设施之后。阶段一最终需真实交付双轴权限；实施可按依赖分批，但不能只做 UI。

阶段二再深化长期上下文压缩、多次休眠后的语义延续和事件组织。阶段一仍须维持正常执行所需的基础上下文、原生协议续接、来源与副作用安全。

基线为 main@ed490e3。下表左列保留既有能力，中列是已落地的本轮实现，右列是仍需工作；所有产品行为以[当前审查](../../审查记录/历史审查记录/审查-M2-阶段一-子Agent本体实施-2026-10-18.md)的实际证据为准。

| 现有能力 | 可直接复用 | 真实断点 |
|---|---|---|
| continuity_work_branches | 稳定 branch ID、独立 conversation、目标、fork 背景、来源/授权快照、当前 run、经历根、outbox；已加任务状态修订、episode 链和归档账 | 旧库迁移、多 episode、归档后后继均已有自动测试；旧 branch 的语义只按迁移规则回填 |
| BranchCoordinator | 后台排队、独立执行、指导、终态核验、恢复 intent、归档与主干发布；唤醒由同一 branch 的后继 episode 完成 | 只按单活动工作执行；跨多 Agent 并发仍未验证 |
| ChatRuntime | 原生多步循环、checkpoint、effect、lease、输入守卫、步骤边界暂停与指导；持久暂停意图、同 run 恢复、episode 绑定与消费回执 | 真实 provider、极端崩溃点与所有交付围栏仍需最终验收 |
| conversation 树 | 独立工作历史、原生协议上下文、编辑分支、附件 | 可以作为 branch 的工作树，但需明确跨 episode 边界与来源失效规则 |
| experience/source/dependencies | 权威原文、分页回读、来源版本、派生失效；归档使用独立 `work-archive:<archive_id>` 经历并修复 UI 入口 | 多归档链的分页与 owner 体验仍需真实场景验收 |
| fork 来源治理 | 创建时冻结有界主干背景；普通 append 保持已选前缀有效；编辑、删除或换支会使相关来源失效 | assert_fork 同时绑定主干 epoch 与授权；唤醒必须区分历史快照有效性与主干持续增长 |
| 权限与沙箱 | 文件 grants、聊天工具 hook、浏览器 origin、容器断网、MCP 客户端；子 Agent 只获得父级已授权能力 | 仅 confirm/full；本地命令无文件/网络隔离；尚无统一 L1～L4 与 N0～N2 |

branch 已经是合适的工作主体底座，不需要再增加外层 subagent_id。新增 episode 只记录一次唤醒阶段，不是新的 Agent；任务状态修订用于保存真实任务理解，也不是另一个主体。

## 三、推荐架构

### 3.1 直接演进现有工作分支

- continuity_work_branches.id 即稳定子 Agent ID。旧 branch 不映射成另一个身份，也不猜测合并。
- branch 保存父灵、任务目标、冻结背景、经历根、生命周期和权限/来源。新增 append-only 任务状态修订，记录关键决策、进度、未完成项、已验证事实、未知/阻塞、产物、来源引用、权限版本及 digest。
- 同一个 branch 继续使用其工作 conversation 作为历史树。多次运行可以在同一树中发生；conversation 不是身份，run 也不是身份。若来源失效需要新上下文，应明确创建新请求或受控新阶段，不能假装连续。
- episode 表示一次持续工作或唤醒阶段，记录 predecessor、起止、任务状态基线、run 关联与归档。后继 episode 归属同一个 branch。
- 单次执行继续使用 chat_runs、checkpoint、effect、lease；run 在 `continuity_work_episodes` 中归属 episode。旧完成 checkpoint 绝不作为新 run 的恢复点。
- 归档是不可变记录。branch 处于 archived/paused 时可显式唤醒，在同一 ID 下开启后继 episode；旧 episode 与归档不改写，不创建新身份冒充唤醒。

| 层 | 含义 | 是否可新增 | 连续性证据 |
|---|---|---|---|
| branch | 子 Agent 主体与当前任务状态 | 否 | 同 branch ID、同工作树、任务状态版本链 |
| task state | 目标、决策、进度、未完成、来源 | 可追加版本 | 后一运行能读到前版并判断哪些事实仍有效 |
| episode | 一次工作或唤醒阶段 | 可新增 | predecessor 链、起止、归档与 run 关联 |
| run | 一次原生执行循环 | 可新增 | 当前 episode 的合法恢复或后继运行 |
| archive/return | 不可变结果、回归、经历 | 只追加 | 原文/hash/来源不变，outbox 幂等 |

正常模型回合结束、真实暂停、进程中断和休眠后唤醒是不同状态。普通结束只结束本轮并让 branch 暂停；显式暂停把 `chat_run_controls.intent` 持久化为 pause，在步骤边界阻塞；重启后先尝试合法恢复同一 run，失败时停在可解释的中断；只有阶段安全关闭后才能唤醒同 branch 的后继 episode。迁移 038 保存运行意图，迁移 037 保存任务状态与 episode，二者都不复制私有 checkpoint。

### 3.2 唤醒与连续性

唤醒同一子 Agent 至少满足：

1. branch、工作 conversation、父灵和任务状态链仍存在；
2. 旧 episode 的 run、审批、未知 effect、命令/session、任务交付已安全结束或有人工核对结果；
3. 历史原文和来源仍可读；主干普通 append 不使已选历史自动失效，主路径编辑、删除、换支、附件版本变化或授权撤销仍使相关来源失效；
4. 新 episode 使用当时有效且不超过父级的权限/网络策略，并记录 predecessor、任务状态基线和来源绑定；
5. 新 run 的输入由 task state 与受控原文构造，携带目标、关键决策、进度、未完成项和必要证据，不能只带 ID 或一段无法核验的摘要。

若同一 run 满足 checkpoint、输入守卫、模型、工作目录和 effect 条件，优先恢复同一 run；否则在同一 branch 下创建后继 episode/run。若关键工作树来源已失效，应保留历史并拒绝声称无缝恢复，提供可解释的新请求路径。

完整经历由 branch 经历根、episode 归档、run 原文和来源索引共同构成。任务的目标、决策、执行、结局与回归保持可追溯；主干只收到必要结果和回忆入口，不接收每次工具调用流水账。

### 3.3 双轴权限与执行边界

子 Agent 创建不能扩大父级授权；有效策略取自身授权、父级上限和执行环境能力的交集。所有实际启用的文件、命令、MCP、浏览器、任务、后台与网络通道都必须经过服务端策略门；未知能力 fail closed。

| 操作档 | 产品语义 | 关键边界 |
|---|---|---|
| L1 只读 | 查看与分析获准资料 | 文件写、命令写、浏览器副作用、外部 MCP 发布均拒绝；无法证明只读的通道禁用 |
| L2 操作前询问 | 有副作用操作逐次批准 | 拒绝零副作用；参数、目录、主体、策略或网络变化使旧批准失效 |
| L3 自动低风险 | 授权范围内普通读写与测试自动执行 | 只放行明确低风险动作；发布、凭据、目录外和未知动作升级 |
| L4 完全放权 | 取消产品内普通审批 | 不突破 OS、VM/容器、外部账号和网络硬边界 |

| 网络档 | 产品语义 | 最低可信实施 |
|---|---|---|
| N0 禁止 | 子 Agent 自主网络访问为零 | 所有启用通道有真实出口隔离；无法隔离的通道禁用；模型网关系统网络另账 |
| N1 白名单 | 仅允许目标与方向 | 真实出口策略绑定协议、主机、端口、方向、重定向、字节和期限；浏览器 origin 不能单独证明 |
| N2 完全网络 | 受操作档与环境限制的自主联网 | 不自动获得发布、支付、外部账号或 OS 权限 |

网络实现可在本体闭环后集中落地；在此之前，无法证明隔离的通道应禁用或明确要求隔离环境。设置项、工具名和 UI 标签不能作为真实网络权限。

### 3.4 经历、回归与安全

- 归档与回归依据真实执行、验证和交付事实，不以模型声称“完成”代替。
- 原文、附件、来源 hash、私有 checkpoint、effect、unknown 和人工核对分别保护；归档不复制私有 checkpoint，也不以删除摘要冒充原文。
- 回归在主干没有活动 run 时通过 durable outbox 幂等追加；来源、绑定或版本变化时阻塞并保留原因。
- 唤醒、指导、暂停、完成和归档携带 revision/CAS；陈旧 UI 刷新真实状态并清除成功提示。
- 旧 confirm/full 不能静默映射为新的 L 档；保留 legacy 或逐主体确认迁移。新建主体的默认档位在实施前冻结。

## 四、实施工作包与依赖

以下按“先完成子 Agent 本体，再集中安全网络，再管理体验与最终验收”组织。普通工程细节可调整，但不能降低连续性、原文、权限和副作用边界。

| 工作包 | 交付 | 退出证据 |
|---|---|---|
| **P0：契约与加性迁移设计** | branch 主体、task state、episode、run 归属、归档/回归、旧数据迁移与回退点；冻结伪完成清单 | **已完成离线验证**：迁移 037/038、legacy 回填、旧归档字段保持、原文 hash 对照；证据见审查 |
| **P1：子 Agent 本体闭环** | 创建→独立 run→实际消费指导→普通结束/暂停→安全休眠→同 branch 后继 episode/run→分阶段归档与回归 | **已完成三协议自动验证**：主干并行聊天、同 branch/工作树/任务状态延续、指导实际消费、归档后原文可唤醒、任务状态进入真实请求 |
| **P2：恢复与连续性加固** | 持久暂停/恢复、同 run recover、unknown/pending/交付围栏、CAS、崩溃重启故障注入、task state digest | 持久暂停、同 run recover 与工作 episode 恢复已通过自动测试；unknown/pending 交付围栏未全部实测，旧 checkpoint 未重放 |
| **P3：统一操作权限** | ExecutionGate、工具能力元数据、L1～L4、持久审批、主体与父级交集、审计 | 各通道服务端拦截；L2 参数/重启失效；L3 未知动作升级；L4 不越 OS/环境边界 |
| **P4：真实网络权限** | Windows、容器、stdio+HTTP MCP、浏览器、依赖安装的能力探针与出口控制；N0/N1/N2 | 各组合正负向探针；L4+N0 无旁路；N1 重定向、私网、端口和方向负向通过；模型基础网络分账 |
| **P5：管理与经历体验** | 子 Agent 列表、episode/run 状态、服务端 allowed_actions、指导状态、休眠/唤醒、权限设置、原文入口修复、竞争刷新 | 本轮已落地任务状态、episode/指导状态、唤醒和真实归档经历入口；权限设置、allowed_actions 与完整竞争刷新仍未验收 |
| **P6：最终验收** | 迁移/备份/恢复、协议、权限矩阵、故障注入、性能成本、真实模型与所有者体验 | 自动化、真实模型和所有者分别记录；旧 M2 未验项不被新结果替代 |

P0 契约不再等待网络探针；网络能力矩阵在 P4 集中执行。阶段一首包的最低硬安全包括原文、来源授权、不扩权、unknown/pending 阻断、完成 run 不重放和单活动执行写锁。高级 L3/L4、跨通道 N1 与多 Agent 并发不得成为子 Agent 本体的首包阻塞。

## 五、验收矩阵

| 编号 | 场景 | 必须满足 |
|---|---|---|
| S1 直接处理 | 简单问题 | 灵直接回答，不形式化创建子 Agent |
| S2 独立执行 | 复杂多步任务 | 子 Agent 自主规划并调用获准工具；主干同时正常交流；上下文不等于全灵记忆 |
| S3 中途指导 | 执行中或休眠中追加需求 | 持久、单调、绑定 branch/episode；实际消费前不显示已送达；重启不丢不重 |
| S4 暂停与恢复 | 普通结束、真实暂停、重启、checkpoint 有效或失效 | 语义分开；可恢复时优先原 run；未知或失效时拒绝自动继续；副作用恰好一次 |
| S5 休眠与唤醒 | 归档后同一 branch 再唤醒 | branch、工作树、任务状态和经历链延续；新 episode 引用前驱；旧归档、原文和 hash 不变 |
| S6 失败与未知 | 命令清理未知、effect unknown、交付待审、来源撤回 | 不显示完成、不自动唤醒、不靠普通指导解除；保留人工核对入口 |
| S7 共同经历 | 委托、指导、执行、回归、多 episode | 完整任务有可追溯 branch/episode/run/来源关系；主干只得到必要回归；原文分页可读 |
| S8 操作权限 | L1～L4 各通道与审批变化 | 服务端实际拦截；未知工具默认严格；旧批准失效；档位语义一致 |
| S9 网络权限 | N0/N1/N2 跨命令、MCP、浏览器、任务和依赖 | 无旁路；无法隔离组合禁用；模型基础网络与自主联网可解释；不伪造隔离 |
| S10 权限交集 | 父级降权、子 Agent 配置、环境能力 | 子 Agent 不高于父级；降权影响后续调用；不获外部账号或 OS 权限 |
| S11 迁移与回退 | 旧 branch、旧 archived、portable、备份 | 原文和归属完整；旧归档不静默改写；私有 checkpoint/effect 不进 portable；代码与数据恢复分开 |
| S12 竞争与可观测性 | 双窗口、陈旧状态、长任务进度 | CAS 拒绝旧操作；刷新真实状态；进度不是无界工具流水账 |
| S13 性能与资源 | 多 episode、历史分页、权限审计 | 前台不被整理或唤醒拖垮；有冻结实测门限和无界扫描防护 |
| S14 真实体验 | 获授权后的 provider 与所有者操作 | 创建、指导、休眠、重启、再唤醒和回归都实际完成；费用或 usage 未知不填零 |

自动化、真实模型和所有者体验分别记录。结构夹具或前端 mock 不能替代真实语义和恢复证据。旧 N12/N16/N17 继续保留；新的付费真实模型测试需另行确认。

## 六、风险与恢复

| 风险 | 防护与退出路径 |
|---|---|
| 仅换 ID 冒充连续子 Agent | 用 branch、工作树、任务状态、前驱 episode 和可读决策共同验收 |
| archived 被改回 queued 或重放旧 checkpoint | 旧 episode/归档只读；后继 episode 新 run；原 run 恢复须 checkpoint、effect、来源全部有效 |
| 主干正常增长被误判为断开 | 区分历史快照合法性与主干当前绑定；编辑、删除、换支和附件变化仍 fail closed |
| 指导被提前显示已交付 | queued→实际消费→consumed；重启不重复副作用 |
| 任务摘要失真 | append-only revisions、来源、digest 与原文回读；摘要不能取代证据 |
| 文件双写或重复副作用 | 保留 lease/effect/交付核对；首版一个主干运行和一个工作执行，其余 branch 休眠排队 |
| 双轴权限只做 UI | 服务端 ExecutionGate、真实出口探针和负向测试；不支持组合禁用 |
| 旧 full 静默提权 | legacy 或逐主体迁移；新主体严格默认并记录权限版本 |
| 迁移破坏旧经历 | 加性迁移、备份、hash 对照和回退；不删除 unknown |

实施前备份完整数据库、附件、任务和私有 checkpoint/effect。迁移只增不删，旧字段和表保留到复核完成。若新生命周期失败，保留现有 branch 和 experience 只读入口，代码回退与数据恢复分开执行。

## 七、待所有者确认的边界

1. 待确认后续是否继续按已实施方向推进 P3/P4：现有工作 branch 就是子 Agent 主体，不新增外层 subagent identity；episode 只表示一次唤醒或阶段。
