# M2 阶段一计划：工作事件折叠与完整经历按需展开

>
> 状态：**正式研究与实施准备计划；尚未实施，后续实施须另行授权**。本轮仅研究、离线探针和文档。

> 需求：[根 HANDOFF](../../HANDOFF.md)；事实、源码位置、开源版本与测量：[研究审查](../审查记录/审查.md)。后续阶段以里程碑为准。

## 一、目标、范围与成功定义

同一聊天中“闲聊 → 工作 → 明确结束并折叠 → 回到闲聊 → 日后回查”。折叠后，**实际模型请求**在工作原来所在的位置只携带短概况，不再发送该事件的详细消息、附件内容或已完成工具交换。人点击展开可以分页看原文；Agent 回想细节时先读目录，再读指定证据，不能把整件工作自动送回模型。

阶段一先做边界可确定的事件：原会话中显式标记的一段工作、人工选择的闭合历史区间，以及有明确来源关联的独立任务。自动理解任意自然聊天、跨会话自动聚类、进行中任务压缩、向量与图召回、完整记忆子 Agent 平台在后续阶段。

阶段一必须交付可用的聊天路径，不能只做独立任务卡片或界面收起。“完整”限定为系统实际观察且按当前安全政策允许保留的记录；工具截断、缺失文件、未存储数据与私有原生对象必须分别标记，不能宣称恢复未观察的内容。

## 二、独立核对后的关键事实

1. 第一部分没有装配旧长期记忆服务。当前消息直接存 `conversation_messages.text`，不能以旧 `history.sources` 作为新聊天的权威历史；旧 `conversation_segments` 也不因表存在就成为可用事件系统。
2. 当前 `build_payload` 不只是纯文本尾部：对完全匹配 profile 的 completed 回合，`RunCheckpoints.completed_items` 会恢复原生输出项、工具调用与工具返回。若只在 `ContextBuilder` 换一段显示文本，详细工具交换仍可能进入请求。
3. 聊天 run 的 completed 是模型回合结束；工作是否完成、测试是否通过、现实副作用是否确定是不同事实。独立任务的执行完成与成果写回也须区分。
4. 运行中的完整工具交换会受请求大小/窗口和检查点大小限制；阶段一结束后折叠不能让当前单次 run 无限继续。大事件可由多个已结束 run 组成，进行中压缩另列 M2 阶段二。
5. 现有公开事件预览、附件文本抽取、命令输出及任务记录各有保留边界。私有原生 checkpoint 不能直接成为公开回读 API；原始消息、语义工具记录、执行证据和私有续接材料须分别处理。
6. 本轮临时探针发现既有删除/恢复缺口：删除一轮后对应失败 run 仍可能被认作可恢复，恢复请求再次携带已删提示词；成功生成孤儿答复尚未证实。旧分段服务还存在与 026 迁移不兼容的查询。前者必须作为后续实施前置修复，后者说明不能直接重装旧分段模块。本轮均未改代码，证据见研究审查。

以上为源码事实；新事件表、投影器、回读接口和交互均为下述**拟议设计**，当前不存在。

## 三、推荐架构与开源融合边界

采用**原始记录 → 事件索引 → 可重建投影**三层，继续使用 SQLite 与现有运行器：

```text
当前分支的消息 + 获准保留的运行/工具/附件/任务记录
                         │
                 事件来源清单与版本
                         │
              可见性检查、摘要版本选择
                         │
           工作区间替换为短概况（输入投影）
                         │
              预算选择 → 原生协议组装
                         │
                    新一轮模型请求

私有检查点 / 副作用围栏 ── 独立保存与恢复
事件目录 → 分页原文读取 ── 共用来源与权限检查
```

投影是一种读取视图，**不能覆盖消息或改写 checkpoint**。一个事件只有一份稳定索引，多份摘要版本；人类界面折叠状态和模型输入折叠状态独立。关闭功能即可重新读取原始历史，仍受窗口预算约束。

| 方向 | 阶段一结论 | 取舍 |
|---|---|---|
| 直接接入 DeepAgents SummarizationMiddleware | 不作为运行时依赖；优先研究其外存、压缩失败保留、工具配对思想 | 它按上下文压力处理 LangChain 消息，不能直接表达本项目事件、分支与三协议原生续接；其历史文件也不能直接替代本项目权威原文 |
| Letta/MemGPT 式内外记忆分层 | 借鉴按需调入与容量有界思想 | 不替换 Harness、权限和恢复体系；不引入第二套主运行器 |
| 自有薄投影层 + 现有 SQLite | **推荐** | 需实现事件闭合、版本与安全回读，但范围可控，便于保留原生对象和来源规则 |
| LangMem、Graphiti、Hindsight、A-MEM、MIRIX 等 | 按后续阶段观察/实验，逐项许可与依赖复核 | 记忆提炼和语义/关系召回不解决阶段一最先缺少的事件边界与原文保留问题 |

外部源码的具体版本、许可、依赖和可复用范围以[研究审查](../审查记录/审查.md)为依据。若以后摘取代码，须固定上游提交、保留许可和版权声明、增加适配契约测试；“借鉴思路”不等于未经评估直接复制模块。

## 四、事件边界、状态与触发

### 4.1 最小事件范围

- 聊天事件绑定 `agent_id + conversation_id`，以当前分支上有序的 message ID 集合和起止锚点确定区间，并关联实际 run ID；时间戳只作显示，不能单独决定成员。最终答复为空、没有 assistant 节点时仍须用 user/run 锚点保留工具经历，不能因缺少最终文本就漏记运行。
- 首版每个分支同一时刻一个活动事件，闭合事件互不重叠、不嵌套。多 run 工作可纳入同一事件；分支共同祖先上的闭合事件可复用，分叉后的事件成员不得跨支合并。
- 界面可在原聊天轻量“开始工作/结束工作”，结束后满足条件自动折叠；历史记录可选一段闭合区间。普通回合有工具调用、模型出现“完成”等词，均不足以自动认定工作边界。
- 独立任务以 task ID 标识，只有记录了发起会话/消息及返回锚点才投影到该聊天；单纯同 agent 或相近时间不构成关联。已有无关联任务只能在任务页查看或人工明确关联。
- 混入工作区间的闲聊和持续约束可在预览中移出；阶段一不在任意交错区间强行自动切分。重要所有者系统规则始终由原配置注入，摘要无权撤销。

**建议体验默认值**：明确工作模式下，关闭工作后自动折叠；未标记的聊天先提供选段收起。是否增加 Agent 的边界提议入口由所有者决定，后端安全判定始终独立。无需另开会话，UI 展开不增加模型输入。

### 4.2 分开记录三个维度

| 维度 | 示例 | 权威依据 |
|---|---|---|
| 事件生命周期 | open / closing / closed / invalidated | 边界版本与关闭操作 |
| 执行与交付结果 | 运行结束、失败、取消、部分交付、结果未知；写回待处理 | run/task/命令/写回的实际状态与验证证据 |
| 投影状态 | raw / pending_summary / folded / stale / unavailable | 来源覆盖、摘要版本与可见性检查 |

“closed”不等于“成功”；“folded”不改变任何执行状态。摘要必须使用实际状态，允许“流程已结束，结果未核验”，不得由摘要模型生成绿色成功标志。

### 4.3 激活折叠的安全闸门

自动激活需同时满足：边界明确且是当前可见分支的闭合区间；相关 run 已终止；无 pending 工具/未决审批/活动命令/unknown 副作用/可恢复中工作；原文来源清单已持久化且覆盖范围明确；摘要版本匹配；事件成员没有变化。

- 成功且验证证据满足：可以按证据描述成功与验证范围；一般聊天没有工具验证时只能说回合结束或已给出答复。
- 失败或取消且清理已确认：可由用户关闭为失败/取消事件后折叠，保留原因和未完成项，不默认按成功处理。
- 暂停、等待确认、可恢复中断：阶段一保留原生执行上下文，不自动折叠输入；UI 可收起预览但须显示待处理。
- unknown、部分写回待处理或残余审阅：不自动折叠输入；保持恢复/核对入口。人工核对也不能仅因收起事件解除围栏。
- 存在不完整历史：允许目录展示缺口；不进入“原文完整已保留”的验收口径。是否允许带明确缺口标记的历史事件折叠，首版默认关闭，待所有者确认。

同一分支和事件版本使用唯一键及 compare-and-swap 激活；旧摘要作业晚到、重复请求和并发关闭只产生一次有效投影。事件关闭与读取快照边界必须可重试；摘要生成不持有长数据库事务。

## 五、来源保留、数据契约与失效

### 5.1 最小拟议数据模型

名称仅为设计建议，实施时核对迁移序号与旧表，避免复用旧 `episodes`/`conversation_segments` 的名字造成“旧记忆已恢复”的误解。

| 拟议实体 | 必要字段/约束 | 不保存什么 |
|---|---|---|
| `work_events` | ID、agent/会话、起止锚点、事件版本、生命周期、执行/交付状态、关闭依据、创建时间 | 不复制海量正文，不把 completed 当成功 |
| `work_event_sources` | event/version、source kind/id、顺序、source revision/digest、可见性范围、coverage、长度与分段游标；成员唯一 | 不接受模型传入任意 SQL、路径或跨会话 ID 列表扩权 |
| `work_event_records` | 获准保留但现有公开记录没有正文的工具结果/中途指导/步骤可见文本；run/step/attempt/call、过滤策略版本、安全正文 hash、覆盖标记 | 不复制整份 checkpoint，不保存 opaque/signature 或凭据 |
| `work_event_task_links` | event/task、agent/会话、发起时分支 head、发起 request ID、返回锚点/插入位置、关联版本；显式校验归属 | 不按时间或同 agent 自动关联；不伪造原本不存在的用户消息 |
| `work_event_summaries` | event/version、来源 digest、文本、结构化状态、生成方式/model 配置引用、策略版本、candidate/active/stale、失败原因 | 不存凭据；不将模型解释写成权威执行证据 |
| 最小摘要作业 | event/version + policy 唯一、queued/running/retry/failed、尝试与取消信息 | 不建设完整记忆 Agent 平台；不无上限重试 |
| `event_read_receipts` | agent/会话、回读 run ID、event/source 版本与范围、读取总量、最终答复锚点、凭条版本 | 不复制原文；不持有扩大权限的永久授权 |

优先引用现有稳定消息、工具结果和附件记录；只有现有公开安全记录缺少正文时，才增加**经过现行过滤的持久语义记录**，采用 run/step/call ID 定位。私有 provider continuation 保留原位，绝不直接导出给模型回读或 UI。敏感过滤与权限检查须覆盖参数、返回、错误和附件，不额外长期复制凭据。

权威来源明确如下：消息引用 `conversation_messages`；附件引用内容服务及固定 hash；任务引用经安全投影的 task 记录；新采集的工具全文、指导和步骤可见文本以 `work_event_records` 为安全回读权威。`chat_tool_effects`/checkpoint 只继续承担私有恢复、审计与覆盖核对，不能作为通用原文接口的底层透传。若以后接纳单个旧事件，可在所有者明确操作后将获准字段导入安全记录，标明来源、过滤与缺口；本轮及首版默认不做批量回填。A4 的逐字/hash 比较对象是该允许保留的安全正文，不能冒充与整个原生响应逐字等同。

任务关联由新入口显式写入 links，旧任务无链接则不进入聊天投影。若任务原来没有聊天工作区间，返回时只在绑定锚点插入事件概况，不宣称从聊天请求里删除了本不存在的工具详情；真正的输入折叠仍以原聊天工作路径验收。P1 提供关联存储/API 契约，P3 接入发起/返回界面。

新记录应覆盖：所有者可见消息、步骤中的可见答复、运行中指导、工具名/获准参数/获准结果、验证证据、附件版本和内容位置、任务事件和交付记录。当前运行中指导只进入 payload，P1 须增加稳定来源，不能漏掉所有者改变工作方向的指令。私有 reasoning/encrypted/signature 数据不伪造为可读经历；其原生保存只服务既有协议恢复。

捕获点在安全过滤后、公开预览截断前；按 run/step/attempt/call 去重。现有 `BEFORE_TURN_END` 发生在最终答复/终态落库之前，只适合准备候选或登记待处理信息；事件关闭和成功摘要激活必须等实际完成事务提交并复验来源，不能在该钩子提前认定成功。

### 5.2 覆盖范围与资源生命周期

每个来源标明 `retained / bounded / redacted / missing / revoked`，并说明工具本身截断与存储层缺失的区别。工具在返回前已截断、而实际返回内容被完整保留，属于“观测完整但外部覆盖有界”，可以带 bounded 标记折叠；曾经进入模型/界面却未被保留的记录属于 capture gap，不得称完整，默认不自动折叠。能全读的正文分页全读；命令大输出沿已有 artifact 安全接口读取；二进制/图片/PDF 返回文件信息或获准片段，绝不自动转成无限文本。

检查点超过 8 MiB 后的异常路径需由 P0 最小夹具确认（当前仅源码推断可能成为 runtime_error）。增加独立的 `replay_coverage`/失败原因：安全语义记录完整而 checkpoint 失败时，经历正文可标 retained，但不能宣称可原生续跑；安全记录也未成功捕获时标 missing/capture_gap。原生恢复状态、副作用 unknown 与事件安全关闭继续分别判断，不能把失败冒充普通截断。

事件引用不是越权凭证。查询必须同时校验当前 agent、会话/选中分支、任务归属、工作区/来源授权与撤回状态。权限指纹变化后先使摘要和缓存失效，重新校验可见来源再生成；不能只挡原文回读而继续发送泄漏信息的旧摘要。所有者如需查看历史分支，应通过明确的历史/分支选择操作进入；所有者 UI 可查看的资料不自动成为当前模型分支可检索的资料。

撤回的线性化边界是授权变更提交：此后新获准的来源读取、摘要激活及每一步模型 HTTP 请求都须校验新版本，不能继续用旧缓存。已发给供应商的请求无法追溯收回；活动 run 不原地改写 native payload，而应请求取消当前调用、阻止后续步骤提交，并沿现有取消/命令清理路径保留 unknown 围栏。A7/A9 的零泄漏统计限定于撤回提交后新准入的请求与返回，既已发送内容单独记为先前披露，不声称已擦除。该守卫属于阶段一来源接入，尚未实现。

首次进入折叠前确认依赖记录的持久化与保留策略：事件存在期间所需 artifact 不被普通清理默默删除；用户明确删除、撤回或安全脱敏始终优先，删除后使摘要、索引、缓存和派生搜索同步失效。不能用“保留经历”阻止所有者删除敏感内容。

### 5.3 分支与版本失效规则

- 只根据当前 ancestry 判断可见成员，不能按同 conversation 或时间范围加载兄弟分支。
- 选到事件内部、编辑/重生成事件成员、删回合、附件更换或任务来源变动：对应投影立即失效或在新分支保持 raw；旧版本留作内部历史，普通回读不得绕过当前可见性。
- 删除锚点还必须阻断对应 run 的恢复与原生回放，即使 checkpoint 仍因审计/副作用围栏而私有保留；不能只把事件概况标成 stale。恢复前要求原用户锚点仍存在、归属正确且在允许分支，空指针相等不构成通过。
- 选回仍满足同一来源快照的原分支可复用旧摘要；不要求每次纯 head 前进都重算。使用成员 digest，不只用全局 head ID。
- 请求组装、摘要激活与工具回读均携带来源版本；事务外完成计算后重新校验。失配返回 stale/cursor_invalid，不能静默返回另一版本的记录。

### 5.4 备份、导出与恢复

数据库备份、可移植导出和任务/附件资产是不同路径。新增表纳入相应清单与格式版本；事件所引用资产进入资产清单及校验。当前可移植导出不能被视为包含全部私有 checkpoint 和运行证据。

恢复后重建来源索引并校验 digest/资产；缺失来源的事件降为 unavailable/raw，不可凭摘要重造原文。兼容旧备份时没有事件表的资料保持普通历史。升级前在静止点备份，迁移失败可退回；降级保留新表，不删除原始资料。

## 六、模型输入投影与原生协议

### 6.1 正确的挂载顺序

在 `runtime/payload.py::build_payload` 的**原生回放选择与附件载入之前**，读取当前可见事件，把完整事件区间替换为类型明确的 event-summary 项；再交给预算选择、附件装配与三协议渲染。折叠项没有被替换 assistant message 的 ID，禁止走 `completed_items` 恢复详细工具交换。

事件短概况示例（仅示意，不表示当前真实工作）：

```text
经历 E42：修复了导出文件命名；流程已结束，离线用例通过。
证据范围：运行 R9 的验证记录；需要细节时查看 E42 目录。
```

元数据留在清单，不全部注入模型。概况是带来源的历史资料，使用普通历史消息/数据块表达，**不得提升为 system/developer 指令**。摘要中的文本和后续回读结果均按不可信数据处理，不能自行授权工具、修改所有者规则或宣称副作用完成。

`context_manifest` 增加事件 ID/版本、被替换来源数、原始/投影估算字节、预算截断与折叠的分别统计、coverage、策略版本、实际选择结果。内容不进入普通诊断日志。输出预算、动态工具 schema、环境、技能、附件和原生对象统一计量；本轮已确认的附件重复上报须在 P0 校准，统计最终工具声明与 gateway 字段加入后的完整请求，不能沿用中间候选大小声称实际发送或收益。

### 6.2 协议契约

| 协议 | 保持的原生对象 | 折叠边界要求 |
|---|---|---|
| Chat Completions | assistant.tool_calls、tool_call_id、供应商实际返回的兼容扩展 | 整个闭合交换被投影，不能只删 tool 结果或调用声明 |
| Responses | output items、call_id/item_id、opaque reasoning/encrypted_content | 新回合输入由投影重新组装；当前聊天采用 `store=false`，不以远端 `previous_response_id` 暗中携带旧历史。网关支持该字段不等于当前聊天正在使用 |
| Anthropic Messages | thinking/signature/redacted blocks、tool_use/tool_result | 未折叠交换保持原样；禁止在未闭合原生 turn 中用摘要替换某个块 |

阶段一只在后续新请求组装投影。进行中的 state.payload、pending 工具、profile/grants/workspace 校验及副作用表不改写。fallback 模型切换需走现有配置/续接规则，不能把上一协议 checkpoint 强转后发送。

### 6.3 回到原来闲聊与缓存

先投影再选预算，使事件前后的闲聊重新有机会进入最新连续尾部；最新用户消息和最近非工作对话优先保留。验收专门放置工作前话题哨兵，证明它在实际请求中存在。若仅凭尾部算法仍不能保留所需话题，再增加有界的事件前锚点保留策略，不能无预算地“全部置顶”。

事件很大且被旧算法整段截掉时，简单比较请求长度可能看似“没有节省”；应同时比较工作细节占用、非工作话题保留和回答证据。折叠点后的 cache prefix 可能变化，缓存命中不作保证；仅使用 provider 实际 usage 记录缓存与费用，缺失保持 unknown。

## 七、短概况生成、超长事件与异常降级

**推荐混合方案**：执行状态、验证与交付字段由确定性代码填充；简短自然语言可由可配置整理模型生成，或由用户编辑。初始无模型/失败时提供确定性概况：“处理了用户要求 X；流程结束/失败/取消，结果未核验；见事件目录”。用户原始目标需限长并作为引用，不能据它推断完成内容。

模型只提出 candidate；校验来源版本、输出结构、大小、敏感材料与状态冲突后才激活。模型给出的原因/结论若没有来源支持，不进入已核验字段；不可核验的解释须明确标注。人工编辑也保留来源与修订记录。

来源 ID/digest 有效只证明“引用了这份记录”，不能自动证明一句自然语言因果判断正确。阶段一不宣称自动语义核验：已核验事实限于确定性执行/验证字段或可逐字定位的证据；模型润色标明生成概况，推断原因保留未核验标签。若候选把推断混写为已证实结果，拒绝候选并回到规则骨架，不能靠另一个模型投票变成事实。

数十万 Token 的事件不能一次送给廉价小窗口模型。按来源目录分批读取，在单作业输入限额内先生成有引用的局部候选，再生成事件概况；局部片段不能作为完整原文替代品。保留确定性状态骨架和覆盖清单，任何未处理部分显示未覆盖。阶段一无需等全部层级提炼才能继续聊天。

先持久化来源并关闭事件，摘要计算在事务外/后台执行；新请求只读已提交版本。未能满足来源完整性或版本校验时保持 raw；仅自然语言生成失败且确定性骨架足够准确时可激活骨架。取消/重启/超时可重试，旧版本作业不得覆盖新版本。

整理模型配置显式选择，复用现有 profile/gateway 的安全调用；不能假定 DeepSeek 开发子代理就是产品可用模型。未经所有者选择配置和费用策略，不自动新增出网请求或付费测试。记录请求输入/输出用量、重试与缓存；缺失费用不记零。阶段一仅做有界、可恢复摘要作业，复杂队列与多 Agent 反思归阶段六。

P4 的宿主采用**第一部分专用的可选摘要 runner**，通过 API/application 生命周期启动和停止，并给现有 background Supervisor 增加可选驱动入口；不导入旧 learning/activities worker。作业在 SQLite 中去重、带租约和有限重试，默认并发 1；前台聊天/任务忙时不领取新作业，已领作业在有界批次间让步，关闭时取消调用并留可恢复状态。启用后同步更新 Supervisor 的“目前仅备份”说明及装配边界测试。没有整理模型配置时只用规则骨架，不启动模型作业。

## 八、人类展开与 Agent 回读

### 8.1 两条独立路径

UI 事件卡显示标题、真实状态、覆盖范围、是否已用于输入折叠、短概况与“查看记录”。展开只请求分页记录，不触发模型、不改变后续输入策略。提供恢复原始输入视图/重算概况操作；实际发送前显示预算影响，不能将“全部给模型”作为默认展开行为。

Agent 最小只读能力（名称待实现时确定）：

1. `event_records(event_id, cursor, limit)`：列目录，返回消息/步骤/工具/附件位置、coverage 与不透明下一页游标。
2. `event_read(event_id, source_id, cursor, max_bytes)`：读取该目录的指定来源片段，返回版本、原文、准确定位、截断/缺失说明与下一页游标。

摘要包含事件 ID 和入口提示；阶段一可按当前可见事件 ID/标题列出，不必先引入全库语义检索。回读返回是原文引用，不能根据摘要重新生成“原文”。UI 支持按同一定位跳转，不要求两者共用同一返回大小。

### 8.2 有界读取与重新膨胀控制

原型建议值：概况正文目标不超过 1 KiB、可配置硬上限 2 KiB，超限拒绝候选并回到准确骨架，不能机械截断语义；Agent 目录每页最多 20 项，正文默认 8 KiB、硬上限 16 KiB。**这是待基线调整的资源上限建议，不是已测最优值或固定摘要行数**。实际返回还必须取剩余模型预算的更小值，为工具 schema、原生交换和最终答复留余量；不足返回预算提示/目录，不发送超大结果。

Agent 连续回查同样会积累原生工具交换。阶段一每个回读 run 设置总读取预算和最大页数，重复同版本片段不重复读取；达到上限明确请求缩小范围或另起一轮继续。**已经回填当前 run 的工具结果保持原生完整**；下一轮须识别“回查回合”产生的重复原文，采用事件关联的有界回查凭条/短答投影，避免永久把被折叠的细节再次全部回放。其凭条也有来源、版本和覆盖范围，不能删原始答复。这项防重新膨胀属于阶段一必测范围。

具体约束：仅对已结束、全部工具均为只读回查、没有 pending/unknown 的 run 激活凭条；保留用户问题，后续输入以“回查了 E42 的记录 S1～S3，已回答关于原因的问题”及有界短答替换其原生工具后缀。原答复和原工具结果仍可从 UI/来源目录读取。凭条投影与事件投影共用版本、分支及权限校验，优先级明确且同一 run 只应用一次；它引用原事件，不能把后来的回读消息插入原事件时间区间。混有写操作或其他未完成工作的 run 不适用此捷径，仍保留原生状态并受总读取预算约束，待工作事件明确结束或阶段二处理。

凭条资格采用新回读工具的显式白名单/能力声明，不复用当前仅用于并发调度的只读工具集合。已被闭合工作事件覆盖的 run 优先应用事件投影，跳过其凭条；其他 run 才可应用凭条，避免双重替换。回查时的指导同样必须保留来源，空最终答复以 user/run 锚点定位。

禁止任意路径/SQL 查询、任意跨 agent source ID、无上限 `expand_all`。游标绑定事件/来源版本与作用域，权限每页重查；输出提供引用锚点，旧游标失效不悄悄续到新记录。

## 十一、风险、恢复与待确认事项

| 风险 | 应对与恢复 |
|---|---|
| 自动边界错误，把仍需讨论的内容隐藏 | 阶段一先用明确边界与可见预览，提供恢复 raw/调整区间；后续再评估自动识别 |
| 摘要幻觉或成功状态夸大 | 确定性状态与来源、候选校验、未核验标签、可重算版本；拒绝候选不损坏历史 |
| 历史保存不完整、artifact 被清理 | 折叠前检查 coverage 与资产保留；历史缺口如实标记；不承诺补回从未保存的内容 |
| 摘要泄漏撤回来源、跨分支污染 | 统一来源可见性、版本与权限指纹；读取时复验、派生缓存失效、负向攻击用例 |
| 原生协议回放/恢复被破坏 | 仅投影后续新请求；whole exchange 契约；checkpoint 和 effects 不变更；关闭特性恢复原路径 |
| 回查再次填满窗口、摘要模型费用失控 | 有界目录/片段、每 run 累计限额、后续回合凭条；分批摘要、有限重试、显式模型配置 |
