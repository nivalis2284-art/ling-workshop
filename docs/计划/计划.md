## 一、产品结果与范围

同一个灵拥有一条用户可感知的常驻主干，日常聊天继续在其中发生。需要处理工作时，创建同一灵的独立工作分支，继承必要背景，独立执行与管理窗口；结束后，主干只收到带事件时间、真实结果和回忆入口的短报告，完整过程留在分支。主干普通旧历史则按定时计划、最短年龄和规模闸门整理为多个独立事件，原文始终可追溯。

新版第一阶段完整覆盖两套机制：

- **A：工作分支**。自主工具、自然语言、显式入口三种触发；独立上下文、运行中安全压缩、暂停/恢复/失败/交付状态、归档与摘要回归。
- **B：主干反思**。可配置时间/时区/年龄/阈值/模型/预算；先确定性闸门，再异步识别多个事件并分别摘要，支持纠正与撤回。

原文、分支、来源权限、原生协议材料、执行与 unknown 围栏是共同底线。唯一主干是产品连续性，不限制数据库只能有一条 conversation；“反思”在本阶段指有来源的事件整理，不恢复人格反思、自动改系统提示词或完整知识图谱。

## 二、当前事实、两条路线与推荐

基线以本轮 fetch 后 HEAD 为准，详细证据见[研究审查](../审查记录/审查.md)。当前 `conversations` 的 parent/head 是编辑与重生成分支；修改选中 head 会改变同一会话可见路径。`ChatRuntime.submit/recover` 仍按 agent_id 限制一个 running chat，独立 conversation 当前也不能让同一灵并行聊天。`work_events` 只处理同会话明确关闭区间，不能原样用于进行中压缩或跨会话回忆。

| 路线 | 做法 | 收益 | 代价及判断 |
|---|---|---|---|
| **渐进演进（推荐）** | 保留消息树、conversation、原生运行器与原文存储；增加主干绑定、独立工作 conversation 元数据、上下文代际、归档回归和通用经历索引 | 继承分支/恢复/工具/备份的已有边界，允许逐批开启与回退 | 仍需实质调整并发准入、来源解析和投影；不是简单添加标签 |
| 重定义会话核心 | 把主干、工作区、编辑路径、事件投影统一到新的分支图与事件日志 | 长期概念统一，复杂多父合流可扩展 | 重写所有读写、检查点、前端与导入兼容，迁移和回归面最大；当前需求不需要多父代码合并，暂不选 |

### 2.1 既有成果处置

| 分类 | 对象与动作 |
|---|---|
| 保留 | 原始消息、编辑树、权限、检查点/effects、命令会话、M1 任务写回/核对、安全分块与 UTF-8 分页；旧接口继续可读 |
| 适配 | `runtime/input_guard.py`、投影、回读预算/凭条、附件、维护导出；扩展为主干与显式关联工作分支的来源依赖 |
| 局部重构 | agent 级聊天锁；`work_events/service.py` 的同会话/手动区间假设；摘要 runner 中可复用的租约/调用账与来源读取分离 |
| 新增 | 主干绑定、工作生命周期、fork 背景引用、回归 outbox、压缩 epoch、通用经历目录、反思策略/日历、分割候选及发布事务、相应 UI |
| 延后 | 向量/图召回、跨个体记忆、自动人格/提示词修改、多层自主反思；不导入隔离的旧 history/memory/learning 服务 |

不报无依据的“复用百分比”。原文与执行基础复用高；编排和产品界面需要较多新增；进行中协议压缩是风险最高的一项。

### 2.2 开源复用策略

固定版本、许可、源码与局限见[研究审查](../审查记录/审查.md)。推荐第一阶段继续使用现有 Harness、SQLite 与 gateway，不接入第二套主运行器。

| 候选 | 采用方式 |
|---|---|
| DeepAgents / LangChain summarization | 借鉴外存、压力触发和完整工具交换切点；不直接安装中间件。上游外存失败仍可继续摘要，本项目必须保留原文或拒绝激活，不能照搬 |
| Agents SDK 的 agent-as-tool、LangGraph 私有 subgraph | 借鉴子上下文隔离和结构化结果返回；不把它们当已实现的分支归档、主干事务回归或本项目权限控制 |
| Letta / MemGPT | 借鉴分层与按需调入；当前 Letta 已有独立 Bun/TypeScript Harness，不替换本项目执行及恢复体系 |
| LangMem ReflectionExecutor | 借鉴去抖、专用整理模型与后台调用；本地队列不等于持久日历/覆盖账，需由本项目作业层实现 |
| APScheduler 3.x / zoneinfo / tzdata | APScheduler 可选用日历触发组件；即使采用也不能代替来源/发布事务。首版仅每日可配置时间，优先现有 Supervisor + SQLite due-slot + zoneinfo，Windows 打包时补时区数据 |
| Graphiti / Hindsight / MIRIX / A-MEM / sqlite-vec | 作为事件时间/分层/关联召回的对照，延后实际引入；它们不直接完成本阶段 A/B 的安全编排 |

本轮未安装这些框架、未运行上游全套测试；只下载时区数据 fixture 和发行元数据供探针使用。若实施时摘取代码，固定 commit、保留许可并验证传递依赖，不能把“借鉴机制”说成已完成集成。

## 三、总体架构与数据契约

```text
同一 agent 的常驻主干
  ├─ 工作请求 → work_branch（独立 conversation / 背景快照）
  │                 ├─ 原生运行 + 独立预算 + context epoch
  │                 └─ 真实终态 → 归档 → durable return outbox
  │                                          └─ 安全边界追加主干报告
  └─ 定时扫描 → 年龄/排除规则 → 本地规模闸门
                                   └─ 有界整理 Agent → 多事件候选 → 复验发布

工作归档 / 主干事件 / 旧 work_event
              └─ 统一经历目录 + 来源解析 + 分页回忆 + 失效依赖
原消息 / 安全工具记录 / 附件 / 私有 continuation 与 effects 分别保存
```

下列表名是设计建议，最终迁移编号须在实施时重新核对；本轮不创建迁移。

| 数据域 | 必要内容/约束 |
|---|---|
| 主干绑定 | 每 agent 一份有效 main_conversation 绑定、绑定修订；服务器持久化，独立于浏览器当前选择；旧会话保持历史可访问 |
| work_branches | 同一 agent、独立 conversation、主干 conversation/锚点/成员 digest、背景来源清单、授权快照、执行/交付/归档三种状态、版本、幂等发起键 |
| context_epochs | branch/run、epoch、全局 step、切点清单、来源 digest、协议/模型能力版本、可读交接状态及私有原生快照；当前代际 CAS，不覆盖旧代际 |
| branch_returns | 唯一 branch/revision 结果、目标主干与发起锚点、候选报告、ready/blocked/published、主干落点与发布顺序；事务 outbox 与追加原子化 |
| experiences 与来源关联 | kind=work_branch/main_event/legacy_work_event，来源集合引用、实际发生时间、coverage、摘要版本、依赖修订；复用现有安全正文，不复制整份工具/消息 |
| reflection_policies/runs/batches | 时间/时区/年龄/规模/模型/预算、配置版本、应执行时刻、幂等键、租约、候选快照、精确分割、调用账、发布状态；扫描位置不等于已反思覆盖 |

原 `work_event_*` 资料不原地改成不兼容的新含义；旧 API 通过适配器继续工作。新增通用经历入口负责不同 kind，普通闲聊事件不伪装成有执行成功状态的工作任务。一个事实正文尽量只有一份权威记录，索引引用它。

归档身份固定 `archive_id + conversation_id + head_id + members_digest + archive_version`；执行生命周期 revision、摘要/结果 revision 与发布身份分开。回归去重使用归档结果修订及目标主干绑定，不能因暂停/指导等生命周期更新重复回归。消息/摘要的来源依赖另存持久表，不依赖私有 checkpoint 才能恢复；portable 资料也须保留这份依赖账。

## 四、机制 A：工作分支与回归

### 4.1 主干、fork 与触发

1. 首次启用时，如已有多个会话，由所有者选择主干；没有会话则创建。既有 default_conversation 只作候选，不默默拼接历史、不删除其他会话。其他旧会话进入可访问的历史区。跨浏览器共享同一服务器绑定；跨设备云同步不在本轮承诺内。
2. 工作使用独立 conversation，保持原编辑/重生成树语义。fork 引用主干某一稳定锚点及必要背景，不自动复制全主干；给模型的背景有明确来源和预算。主干后续追加不改变冻结背景，编辑/删除其来源或撤权则使依赖失效。
3. 增加窄工具 `work_branch_start/status/guide/finish` 与说明 Skill。自然语言由主 Agent 通过同一工具路由；显式 UI/命令走同一事务入口。创建按发起 request/锚点去重，默认不递归开分支；模型不能借创建分支获取新文件/网络/执行授权。
4. 独立工作仍属于同一 agent。产品工作子执行器使用所有者配置的模型 profile；开发期间 Codex 接入的 DeepSeek 子代理及凭据不是产品模型配置。

### 4.2 并发、状态与执行安全

推荐首版允许“主干聊天 + 一个执行中工作分支”，其他工作可排队，数据库不限制永远只有一个分支。聊天准入锁改到执行上下文；写工作区、任务应用、命令进程仍受共享资源围栏。独立上下文不代表文件系统隔离。

- 有副作用工作优先复用任务副本/写回证据；同一真实目录写入串行化，主干写请求与分支写入冲突要排队、使用独立副本或沿既有核对入口处理。unknown 时不能解锁假称已安全结束。
- 分支可 queued/running/paused/awaiting_approval/interrupted/review_required/closed；执行结果与交付状态另存，不能用单个 completed 代替三者。
- `finish` 仅在运行、未决工具、命令和交付围栏均满足时关闭并生成终态报告；失败/主动放弃可安全关闭并明确未完成项。部分应用与 unknown 保留恢复和核对入口，可向主干报告待处理，但不发“成功归档”通知。
- 取消/崩溃恢复仍定位原 run/step/call/effect，不能因压缩或切换模型重新执行已确认副作用。全局步数/时间/费用预算跨 epoch 累计，不因新代际重置。

### 4.3 回归主干的发布契约

工作完成先保存完整分支及带时间的报告，再写 durable outbox。报告包含实际发生时间范围、工作目标、可证实结果、验证范围、未完成/风险、交付状态、branch/experience ID；生成文字与结构化事实分开。

- **追加到当前主干末端，不把 head 改回 fork 点。** 以主干修订 CAS、发布唯一键和落点记录保证重试恰好一个有效报告。
- 主干有活动 run/未决用户锚点时先排队，等安全边界发布，不能中途追加破坏 input_guard；新请求准入与已就绪回归发布用短事务排序，不等待后台模型。
- 多分支按实际发布序号追加，另显示各自发生/完成时间；不倒插历史，不为了时间排序重接消息树。
- 发起锚点不在当前主干允许 ancestry 时标 blocked，供所有者选择返回位置；不悄悄把旧分支结果附到另一条编辑路径。
- 回归消息本身带来源依赖。之后撤回、删来源或授权变更时，它及其派生回答/缓存也必须失效，不能只挡原文而继续发送固化摘要。
- “合并”是摘要回归，不是把工作分支全部消息或代码自动合并到主干；文件应用沿原任务写回权限和核对机制。

发布还要校验目标主干绑定修订、发起 ancestry 与归档身份，不能只有 head CAS。报告更正产生独立结果修订并按相同 outbox 追加一次“更正”记录，不重发为一项新工作；旧修订留作历史并在模型投影中按失效/更正依赖处理。默认不静默改写已发布消息。

并发控制须同时修改运行器准入和 SQLite `chat_one_running_per_agent` 的部分唯一索引，不能只删 Python 判断。新索引/租约应绑定执行上下文，并保留同上下文唯一运行和共享资源写锁；恢复路径也必须使用相同规则。

## 五、机制 A：进行中压缩及协议边界

压缩发生在**工作分支内部**，与 B 的年龄/定时无关；不写主干原文、主干 head 或主干投影。先压缩已安全结束的旧回合，再评估同一长 run 中完整闭合的旧步骤。一次工作可跨多个 run/epoch，不许以“只支持已结束工作”代替本节。

### 5.1 安全切点与双层材料

仅在模型流结束、工具调用及结果完整配对、旧效果均可确认、无 pending/inflight/审批/活动命令/unknown 的边界建立新代际。整个工具交换、并行工具组及其必需原生块是不可拆单元。

保留：当前目标/所有者约束、已验证进展、未完成计划、文件与证据入口、当前授权、资源账、最近完整交换。压缩内容是有来源的普通历史资料，不能替代系统规则、原生续接对象或效果围栏。原工具全文、指导与分支历史继续归档。

新 epoch 在事务外生成和校验候选，在事务内复验来源/租约/旧 epoch/全局 step，再原子发布。崩溃发生在发布前继续旧 epoch，发布后只恢复新 epoch；旧私有快照不可覆盖，工具 effect 键不重编号。候选失败保持旧状态；如果旧输入已不适合窗口，则暂停并解释，不能静默剪掉未完成工具。

需改造“运行完成后下一轮”的原生回放元数据。当前 `completed_items()` 按 `payload[initial_length:]` 取后缀，不能将压缩前的 `initial_length` 沿用到新 payload。每 epoch 独立记录 prefix/suffix 边界与适用 profile/来源/签名，最终 completed run 明确引用最后代际；后续回放只取被当前来源和能力允许的后缀，不恢复已被压缩的旧详情。两次压缩、继续工具、完成、重启、下一聊天回合必须连在一起验收。

### 5.2 不能假定三协议通用剪切

| 通路 | 设计约束与启用门槛 |
|---|---|
| Chat Completions | 保留尾部完整 assistant/tool_call/tool result 配对。可在安全点以语义交接创建新上下文代际；若供应商有额外私有状态则须另测 |
| Responses | 原生 compaction 可返回私有 encrypted compaction item；完整按官方续接规则保留，不能当可读经历。独立 compact 输出不能随意再裁剪；非原生适配不能假装保留原 reasoning chain |
| Anthropic Messages | 修改早期 prefix 可能使后续 thinking/signature 无效；“尾块字节相同”不足以证明可续接。优先评估原生 context management/compaction；或在安全点开启明确的新原生会话代际，不重放失效签名 |

每 profile 显式声明经验证的能力：disabled、safe_epoch_restart 或 native_compaction；不能只按协议名字自动认定支持。未压缩/未决对象保持原样；新 epoch 是可审计的语义续做，不能伪称供应商同一私有推理链。原生 compaction 属可选优化，不让它成为跨提供商唯一依赖。原生工具清除还可能只减少服务端上下文而不减少本地请求/检查点，须分别计量。

**前置退出门槛**：R0 必须形成三协议离线切点/崩溃/恢复证据；后续真实供应商启用需实际通路通过。能力不明时保持安全停止及明确不支持，不以删 signature/清 effects/换模型掩盖失败。若所有者要求全部现有 profile 都自动续跑，此承诺须在 R0 后重新评估，不能当前保证。

### 5.3 压力与资源建议

暂建议在最终原生请求的保守估算（含输出/工具余量）达到配置窗口 70%，或私有检查点接近 6 MiB 时提前准备压缩，目标回到约 45%；均为待 R0 基线校准的参数，不是已测最优值。触发比例必须大于目标比例，给一次工具返回留预留量。仍保留 8 MiB 等硬上限；一个超大未决工具结果、不可压缩的必需尾部或摘要无法腾出空间时允许安全停机。不能承诺无限长 run。

## 六、机制 B：确定性闸门、定时与多事件整理

### 6.1 候选与计量

只取当前主干 ancestry 中安全结束、最后来源时间 **≤ cutoff**、未被有效经历覆盖的原始回合单元；排除已折叠事件、工作分支原文、工作回归摘要、待审批/可恢复/unknown 单元、最近保护尾部与来源缺口。等于 cutoff 也合格，与本轮探针保持一致。返回的工作摘要仍保留在主干，但不拿它再摘要制造重复记忆。原事件失效或所有者撤回后，相应来源是否重新进入候选由显式重整状态决定。

最低年龄按 `now_utc - age_days×24h`，判断一个完整单元的最后原始时间；时区只负责日历调度和展示。事件时间取源消息/任务的可信 UTC 时间及范围，另存整理/修订时间。缺失或历史导入不可靠时标不确定，不让模型猜日期。

推荐门槛用**候选安全正文 UTF-8 字节数**，UI 明确显示单位；默认建议 32 KiB（待基线测量），并允许配置。仅本地元数据/长度统计，包含将被替换的安全消息、工具记录与可读附件正文，同一来源去重；不把私有 opaque、二进制附件大小或最终 HTTP 包装混入“可读历史规模”。这是整理价值闸门，不是 Token、窗口或账单估计。模型输入仍按实际最终请求预算另行限额。

低于阈值：零模型调用、零新增事件、零反思覆盖推进，下一次扫描继续累计。不能把扫描 high-watermark 当作已反思标记。大候选集按有界工作批次处理，超出本次预算部分保持 raw，避免一个巨型来源迫使整库读入内存。

规模必须跨目录页累计（可达到阈值即停止继续计数），不能只看第一页；单页不足而候选总量足够时仍应触发。先区分符合年龄的总候选与本策略可处理候选：首个原子单元超过作业硬限额时标明 `oversize/deferred`，保持 raw 和可回读，允许后续合格连续岛独立推进，不能越过它拼成假连续事件。该不可处理单元不反复触发收费调用，UI 展示延期原因，需调整策略/预算或明确分段后重整；不能因为覆盖不足而永久标已反思。

### 6.3 分割、摘要与发布

1. 冻结可见来源 ID、顺序、hash、时间与授权，按完整回合/工具交换构成 atomic units；已有折叠/回归等排除单元形成边界，不能跨洞拼接一段假连续原文。
2. 专用整理 Agent 权限仅限这个快照的目录与有界读取。提出连续事件范围和摘要候选，无文件写入、执行、任意 SQL 或自主扩大资料范围能力。
3. 分割必须精确覆盖本批候选：无重复、无遗漏、顺序合法、不能引用快照外来源。每事件独立摘要、时间、引用、coverage；同一主题跨天可形成多个相邻事件，交错话题可标相关但不任意抽走消息。单回合混合话题可保留复合事件；不为语义整齐拆断工具协议。
4. 长候选按模型窗口分块，边缘保留待合并候选；局部提炼不能冒充完整事件。调用/输入/输出达上限时停止，未完成分割/摘要保持 raw 或草稿，不标已反思。不存在通过重试重置调用账来突破预算的路径。
5. 每个发布批次的分割、所有有效摘要、来源覆盖和投影版本同事务提交；不完整批次不部分标覆盖。模型计算在事务外，按来源成员版本复验；单纯主干末尾追加不应令无关旧前缀失效，编辑/删除/撤权必须拒绝旧候选。
6. 主干有活动 run 时不改其在途 payload，不取消日常聊天；候选留待安全发布边界，下一轮才采用新投影。发布/新聊天准入用短事务排序。
7. 所有者可以撤销/纠正边界和摘要，旧修订留存；撤销原子释放相应有效覆盖、停用派生缓存并回到 raw，不覆盖原文。后台不得马上重复处理刚撤销事件，需显式重整或冷却状态。

初始单作业建议上限：读取安全正文 128 KiB、最多 6 个发布事件、最多 8 次模型调用（含分割、摘要和修复）、最多三次尝试、并发 1。输入仍受所选 profile 窗口与整体预算的更小值约束；不能保证 8 次调用必能处理完 128 KiB。用量缺失保留 unknown；日预算达到上限暂停，不在错误重试中自动涨额。默认参数须在 R0 冻结后进入验收。

本机探针已确认当前 `.venv` 没有可用 IANA 数据；用下载并校验 SHA-256 的 tzdata 2026.5 TZif 只作为研究 fixture，DST gap/fold 规则可以验证，但产品安装/打包仍未修复。

当前数据库封装连读取也采用进程 RLock 与 `BEGIN IMMEDIATE`；WAL 不代表这些调用能并行。实施时将后台候选扫描/正文 hash 分页且在模型调用前释放事务，最终发布只做有界版本复验和写入；不能持整个历史扫描或网络请求的写锁。R0 需测前台准入 p95 和事件循环滞后，冻结新阈值，发现超限再决定读连接/版本缓存等局部调整，不先重写数据库。

短事务需有可信快照 token：主干绑定/选中 ancestry 修订、成员内容版本或事务维护的 digest、授权失效 epoch、资产快照版本及策略/租约。捕获和正文/附件重 hash 在有界扫描阶段完成，发布只比较这些版本；不可直接调用当前会遍历全 ancestry/附件的旧 `_state/_sources_valid` 来声称常数时间发布。外部资产须引用已验证的不可变快照，不能只相信文件 mtime；无法证明未变则拒绝候选、重新捕获。失效入口与版本维护须先经故障/删除/撤回测试，不能为降低锁时延绕过来源核验。放到 worker thread 本身不消除 SQLite 锁等待。

### 6.4 调用与费用估算

一个有 k 个事件的批次通常需要分割调用 + k 次摘要，长输入分块和修复另计；8 次是硬上限，不能声称恒定两次。日整理建议先设独立的 24 次模型调用上限，同时要求用户填写可接受的日输入/输出或费用预算；工作分支压缩使用独立工作预算，不能被后台反思耗尽。没有可靠单价/usage 时展示 unknown，以请求及输入/输出上限保证资源有界，不能伪称执行了精确美元封顶。

日资源账按固定 UTC 日桶归属 agent/用途，不能因时区/策略修订、重启、重试或新 job ID 清零；新的调用先预留额度、结束后结算。原生 compaction 也计入对应工作预算，未知用量仍占保守预留，直到核实或人工调整。日历时区与预算日桶在 UI 分开说明。

真实净收益需比较同工作完成度下：主干/工作请求用量 + 压缩/分割/摘要/回忆额外用量 + 缓存失效/写入费用，并记录延迟与失败率。客户端换前缀可能降低缓存收益；原始数据继续保留会增加磁盘占用。当前没有真实调用成本或质量测量，不能把旧 40.34% 请求字节减少外推为本方案的 Token/费用节省。

## 七、共同回忆、权限与维护

统一经历目录先提供类型、时间、目标/话题和来源清单，再按需读片段；UI 查看零模型调用，Agent 读取保留当前 16 KiB 单页、32 KiB/8 页每 run 上限作为基线，按真实预算收缩。上下文代际不能绕过同一逻辑工作的读取/费用账。

当前回读强绑定同 conversation，不能简单改成“同 agent 全部可读”。新来源解析器须同时证明：当前主干/工作运行归属、显式 fork/return 关系、允许的 ancestry、原始授权与当前授权、来源版本及完整性。跨 agent、无关联工作、旧授权不明任务仍拒绝；摘要、回归消息、凭条、原生缓存均进入反向依赖失效。受撤回影响的原始回退也不得泄漏。

来源依赖须传递到后续**没有调用回读工具**的派生回答：例如回归报告→回答 A→回答 B，按该轮实际选入的历史/经历依赖做保守并集，记录在独立的消息/运行来源表。撤回时连同普通回答的投影、原生回放及缓存一起失效；导出/导入后仍可复验。不能让私有 checkpoint 缺失或清理后丢掉这层依赖，也不能只保护回读当轮。

导出拟新增格式版本，兼容现有 v1/v2/v3；保存主干绑定、关系、经历、时间、覆盖、作业和调用账。完整 SQLite 备份保留私有 epoch/checkpoints/effects；portable export 不保证原生续跑，恢复后不能复制执行租约或重新执行副作用。缺资产/来源时明确 unavailable；旧工作事件原样适配，不批量自动反思旧授权不明历史。

## 十、风险、迁移与恢复

| 风险 | 防护及退出路径 |
|---|---|
| 原生压缩不兼容，供应商私有链失效 | profile 能力分级与 R0 前置证明；新 epoch 明确语义；无法安全处理则暂停，不删私有状态 |
| 主干被回归/反思打断 | durable outbox、安全发布边界、短事务排序；禁后台写 head 回 fork |
| 后台双写工作区或凭摘要重跑效果 | 复用副本与应用证据、资源写锁、全局 step/effect 围栏；unknown 必须核对 |
| 旧授权经跨会话索引泄漏 | 显式来源关系、原始/当前授权交集、反向失效至回归文本/缓存；不把同 agent 当全局读取许可 |
| 错误事件边界/摘要损失连续性 | 精确分割校验、原文永留、候选审计/撤销、质量不达标不自动发布 |
| 调度或模型预算失控 | 本地闸门、日历/来源双重去重、跨重试调用总账、并发 1、unknown 用量不当零 |
| 历史迁移/导出缺依赖 | 加性迁移、旧版样本往返、完整资料静止点备份；资料缺失降级，不由摘要重造 |

实施前备份完整 DB、附件与任务资产；独立 feature flag 按 R 批次启用。关闭新机制应能回到既有会话/历史读取，但不得自动丢弃已归档结果或回放旧副作用。每批按逻辑单元提交与推送；回退代码与恢复数据分开，不改 migration ledger、不覆盖历史审查。

## 十一、已批准的产品决策与建议

所有者已认可整体规划及以下四项推荐方案，并正式授权实施；默认参数仍允许在安全边界内按实际证据优化：

1. **旧会话与主干入口**：推荐首次选择一个已有主干，其他会话保留历史；日常导航只突出主干与工作抽屉，不自动融合旧会话。
2. **自主分支与并发**：推荐三种入口都保留，自主创建可见且可取消；首版主干 + 一个执行工作，更多排队，同目录写入串行。是否需要首版多个工作同时执行，决定更大的写入/资源并发范围。
3. **反思的自动发布与模型开销**：推荐默认禁用，配置模型/日预算后启用；04:00、3 天、32 KiB 只是可改初值。通过结构、安全和预先冻结的质量门槛后自动发布，否则保留候选待更正；需确认是否所有新事件一律先人工预览。
4. **兼容与交付承诺**：推荐按 profile 实测能力开启自动进行中压缩；不支持时安全暂停。若要求所有现有中转/profile 都必须连续压缩，需要额外兼容实验和真实模型预算，R0 后再确定范围。

本轮进入完整实施：DeepSeek Max 优先独立完成模块设计、代码、测试及修复，GPT 主 Agent 负责架构、协调、关键决策和风险复核。上游429时保留状态并适度退避重试，不因暂时不可用立即改由GPT执行全部工作。按逻辑单元验证、记录、提交推送；未验证的真实模型及所有者体验不提前通过。
