# 阶段计划：开场白优化与工具并发执行

> 2026-10-14 ｜ 状态：待确认 ｜ 所属里程碑：M1「继续优化地基」阶段1

## 目标

让模型在开工前直接掌握运行环境（不再自行摸索），并让同一回合内相邻的只读工具调用并发执行——两处改动均以「行为有测试证据、既有安全属性不回归、动态信息不损害前缀缓存」为完成线。

## 依据

- 所有者指令（2026-10-14）：M1 第一阶段先处理「优化开场白（给模型的系统指令）」与「多个工具同时请求」两项；并明确「当前时间插在用户消息末尾，不放进开场白（保护前缀缓存）」。
- 同日骨架质量评估结论（见当日会话与工作日志）：开场白缺环境事实（业界研究显示开工前交代环境可省 2–5 轮探索）；同回合多个工具严格顺序执行，只读批读白白变慢。
- 缓存设计依据（2026-10-14 查证）：
  - 前缀缓存按「从开头到第一个不同处」复用；任何动态内容越靠前，作废范围越大。行业一致规范：静态在前、动态在尾。OpenAI 为自动前缀缓存（≥1024 tokens）；Anthropic 以显式断点标记被缓存块（本项目已有此机制，可选开启）。
  - Claude Code 的做法（业界成熟方案）：系统提示内设「动态边界」——边界之上为全局静态、边界之下为会话级环境信息（工作目录 / 日期 / git 状态）；另提供选项将这些信息整体挪进第一条用户消息；当轮才需要的信息（技能提示等）以 system-reminder 挂在消息流中。
  - 映射到本项目：环境事实低频变化（权限 / 档位变更才变）→ 放开场；时间高频变化 → 放用户消息末尾；并采用「每条用户消息各挂其发送时间（由库内 `created_at` 确定性推导）」——该字节永不变化，跨回合前缀可逐字节对齐（优于「仅最新一条」，后者每轮会作废上一条消息所在区段）。
- 复用既有机制：目录授权取自 `permissions`；执行档位与边界取自 `SandboxService.info()`；消息时间戳已在 `conversation_messages.created_at`（`messages()` 已返回）；前端事件消费按 `call_id` 逐条处理（已核实），成组并发不破坏呈现。
- 取向说明：环境块是「事实陈述」，不是行为约束；行为引导只作为默认规则的可选增补（见文末待确认问题）。

## 不改什么（边界）

- `models/` 三个协议族的原生拼装与网关不改；
- 权限模型与确认闸门不改（`run_command`、MCP 仍逐条确认、顺序执行，只保证并发不绕过它们）；
- 技能索引、附件流程、事件格式与前端不改（已核实按 `call_id` 消费）；
- 时间戳只上线格式；对话记录、界面显示与既有数据不改；
- 不扩大并发范围到写操作 / 命令 / 浏览器（保持现状；后期如要扩大，另行立计划）；
- 不碰 `part2_retired/`；不做打包发布；不改 `start.bat`。

## 执行步骤

### 任务 1：环境事实块（A1 / A2）

- 文件：`src/lingnexus/context/builder.py`、`src/lingnexus/runtime/payload.py`
- 做法：开场新增「运行环境」段：平台；可写目录与可读目录（来自权限授权，无授权时如实说明）；命令执行可用性与档位边界（来自沙箱描述：本地档＝无 shell、有超时与资源上限、非文件系统 / 网络隔离）。全部取自既有来源，不新设配置项；每项一句；不含时间。
- 验证：`pytest tests/ -q` 全过；新增断言：mock 请求体中系统开场含「运行环境」段与工作目录信息；未授权场景含「命令不可用」字样的如实说明。
- 完成标准：任一聊天请求的开场均含环境段；两类场景（有授权 / 无授权）文字如实；既有测试无回归。

### 任务 2：用户消息发送时间戳（B1 / B2）

- 文件：`src/lingnexus/runtime/payload.py`、`tests/test_chat_loop.py`
- 做法：构造发给模型的用户消息时，末尾附一行「（发送时间：YYYY-MM-DD HH:MM）」：格式取本地时间、来源取该消息 `created_at`（确定性、跨回合不变）；仅线格式，不写入对话记录。最新一条的发送时间即「现在」（到分钟）。
- 验证：全量测试；新增用例：请求体中用户消息含时间戳；同一对话连发两轮，第二轮请求体中历史消息的时间戳与第一轮逐字节一致（两次请求体比对）。
- 完成标准：每条发给模型的用户消息末尾含稳定时间戳；对话记录与界面无变化。

### 任务 3：默认规则增补（A3，待确认后实施）

- 文件：`src/lingnexus/configuration/instructions.py`
- 做法：默认规则增补 1 条工作方式条目（例：「完成任务前先验证结果；多步任务逐步推进，失败如实报告」）。`reset()` 语义不变；已自定义规则的个体不受影响。
- 验证：相关测试全过；设置页「默认」列表随接口自动呈现（无前端改动）。
- 完成标准：新装 / 重置后的默认规则含该条；已自定义者不受影响。

### 任务 4：只读调用并发执行（C1 / C2）

- 文件：`src/lingnexus/runtime/service.py`、`src/lingnexus/runtime/scope.py`
- 做法：回合内扫描调用序列，相邻只读调用（`read_file`、`search`）合为一组并发执行（文件 IO 让出事件循环、真正重叠）；组间与其余调用保持原顺序；结果与事件（started / result）按请求顺序落账（重放确定性）；每次调用独立绑定效果编号。
- 验证：全量测试；新增用例：一回合含「读A、读B、写C」→ 前两条并发执行、结果齐全且顺序不变；并发性以探针验证（两条读取彼此进入后才放行）；含 `run_command` 的回合确认交互不变。
- 完成标准：并发组行为可重复、事件顺序确定；确认与权限拒绝行为逐条不回归。
