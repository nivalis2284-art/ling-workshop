# 阶段计划：完全访问开关（按对话的免确认模式）

> 2026-10-14 ｜ 状态：待确认 ｜ 所属里程碑：M1「继续优化地基」阶段2

## 目标

给所有者一个**按对话**生效的「完全访问」开关：开启后 `run_command` 与远程工具（`mcp__*`）不再逐条等待确认、直接执行；**沙箱限制、审计记录、目录授权一律不变**；新对话默认保持「逐条确认」。

## 依据

- 所有者指令（2026-10-14）：命令逐条确认造成点击疲劳；参照成熟 harness 的权限档位增加可选「完全访问」开关。三点设计已由所有者确认：① 按对话；② 覆盖命令 + 远程工具；③ 开启时提供醒目警示条与一键关闭。
- 现状与机制：确认逻辑位于 `BEFORE_TOOL` 钩子（`runtime/confirmations.py`；`DEFAULT_GATED = {run_command}`，且全部 `mcp__*` 视为有副作用）；批准按 (run, fingerprint) 记忆、换回合重新询问。钩子是策略件——**扩展为"可配置策略"不触碰循环体**（机制与策略分离）。
- 设计取舍（已呈报；建议值待过目）：
  - 模式按对话**持久保存**（重启仍有效，直至手动关闭；新对话默认「逐条确认」）；
  - 开关只影响「是否等待确认」：沙箱档位、超时与资源限制、审计、目录授权、浏览器点击审批**全部不变**；
  - 因完全访问放行的调用在事件与审计里可辨别（`tool_result` 增加 `access: "full"` 字段）。
- 复用既有机制：按对话独立表（参照 `chat_conversation_failover` 先例）；API 沿用 `api/conversations.py` 风格；界面入口放对话「⋯」菜单、警示条常驻对话顶部。

## 执行步骤（任务四要素）

### 任务 1：访问模式服务与迁移（范围 #1 / #2 / #5）

- 文件：`src/lingnexus/storage/migrations/028_conversation_access.sql`、`src/lingnexus/runtime/access.py`、`src/lingnexus/app.py`
- 做法：读写某对话的访问模式（`confirm` / `full`），缺省读回 `confirm`；值域校验；组合根装配为 `app.access`。
- 验证：单元测试（缺省值、读写往返、非法值拒绝、对话间隔离）；`pytest` 全过。
- 完成标准：任意对话可独立读写模式；未设置读回 `confirm`；非法值被拒。

### 任务 2：确认钩子接线与标注（范围 #3 / #4）

- 文件：`src/lingnexus/runtime/confirmations.py`、`src/lingnexus/runtime/service.py`
- 做法：BEFORE_TOOL 上下文携带 conversation_id；钩子对 gated 调用先查该对话模式——`full` 则直接放行（不产生等待、不发 `confirmation_required` 通知），并通过放行标记告知循环；循环把该标记写进 `tool_result`（`access: "full"`）。策略判断留在钩子，循环只携带标记。
- 验证：集成测试——full 对话：`run_command` 无确认直接完成、事件带 `access: "full"`、无确认通知；confirm 对话：仍等待→批准/拒绝如旧；MCP echo 工具同规则；两对话互不影响。
- 完成标准：两种模式行为均可复现且有测试；缺省路径零回归。

### 任务 3：接口（范围 #6）

- 文件：`src/lingnexus/api/conversations.py`
- 做法：`GET /conversations/{id}/access` 返回 `{conversation_id, mode}`；`POST /conversations/{id}/access`（body `{mode}`）幂等设置；沿用现有鉴权与错误风格。
- 验证：`client` 夹具测两个端点（读缺省、设置后读回、非法值被拒、未知对话 404）。
- 完成标准：端点行为如上并入测试。

### 任务 4：前端（范围 #7）
