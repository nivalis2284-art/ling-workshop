# LingNexus 当前实现基线

日期：2026-10-08。状态：研究后形成的工程工作基线，可用于第一批编码；不是已实测成品、最终架构或用户逐项确认的新需求。

上层依据：[01 概念与原则](../../../docs/01-概念与原则.md)、[02 抽象需求](../../../docs/02-抽象需求.md)。既有功能和用户决定见[讨论笔记](../../讨论笔记.md)。本文件只描述当前 Windows、云端 API 方向；上层文档与归档方向 A 不作改写。

## 1. 必须实现的长期闭环

经历 → 有来源的认识 → 变化候选 → 按边界生效 → 影响交流、回忆、计划和行动 → 真实结果 → 新经历。

人格是当前有效、可演化的自我状态。初始设定仅用于初始化；后续启动、压缩、换模型及退出场景都读取最新有效版本，不能重置为初始角色。长期连续性属于灵的持久状态，不属于某个模型会话。

区分四件事：

| 资料 | 含义 | 变化规则 |
|---|---|---|
| 所有者边界 | 可访问的资源、行为授权、确认规则 | 由所有者修改，模型不能通过学习扩大权限 |
| 当前长期自我状态 | 自我理解、习惯、偏好、当前身份认识及形成依据 | 可演化，有版本及候选生效过程 |
| 当前情境 | 当前任务、近期关注、场景和暂时表达方式 | 按有效期／任务／场景管理，不自动成为长期特征 |
| 过去经历与解释 | 发生过什么，当时及现在如何理解 | 原记录、当时理解、新解释分别保存 |

用户既定规则：普通经验和低风险行为调整自动形成；涉及身份、关系、价值判断、重大人格变化或重要能力变化的反思，先存候选，用户确认后生效。较宽泛的早期“人格可自动发展”与该细化规则共同适用。

初始人格未提供不阻塞基础开发：开发夹具明确标记为测试；实际首次使用只使用已确认的名字“灵”和系统边界，不捏造传记、关系或喜好。用户可以后来设定起点。

## 2. 技术决策与边界

以下均为可替换的工程默认，不是新增用户偏好。

| 部分 | 当前基线 | 为什么这样选／替换边界 |
|---|---|---|
| 主体 | Python 3.12，模块化单体 | 当前已有 Python 3.12；领域模块不依赖前端和模型厂商 |
| 数据校验 | Pydantic 2，领域输入严格校验 | 枚举、来源 ID、版本、工具参数明确；校验通过不代表内容真实 |
| 权威存储 | 本机 SQLite，标准库 sqlite3，版本化 SQL 迁移 | 单用户本机；Repository 隔离 SQL，单写入协调、短事务、foreign_keys=ON |
| 附件与技能文件 | 应用数据目录内按 ID／内容摘要管理 | 数据库保存元数据及有效版本指针；Markdown／JSON 导出不成为第二个可独立修改的真源 |
| 记忆查找 | 事件关联、时间／主题／标签／别名、全文查找、按需读取 | 首版无需向量库和知识图谱；索引可重建，源资料不依赖索引 |
| 本机服务 | FastAPI + Uvicorn，单应用实例／worker | 生命周期拥有后台工作；不把长期任务绑定 HTTP 请求 |
| 图形界面 | React + TypeScript + Vite，本机浏览器访问 | 聊天、记忆／发展、活动、设置共用后端；桌面壳可后加 |
| 界面通信 | HTTP 命令／查询 + SSE 事件订阅 | 流式显示和断线重连；关页面只断订阅，显式停止才取消运行 |
| Agent 执行 | 首选 Pydantic AI，位于 AgentExecutor 适配器内 | 已有三类模型、工具循环、流式及延期工具机制；真实渠道验证失败时局部使用官方 SDK，不重写领域层 |
| 原生模型协议 | Messages／Chat／Responses 分开适配 | 不强制转换成 Chat；厂商签名／不透明状态独立保存 |
| 后台唤醒 | APScheduler 3.x，业务计划保存在应用数据库 | 调度器是可重建投影；业务任务与实际执行结果另存 |
| 文件／网页工具 | 文件工具按目录授权；网页操作使用 Playwright | 浏览器与命令执行的权限、恢复不由模型自行保证 |
| 工程验证 | pytest、Ruff、Pyright，前端类型检查与 Playwright | 版本在实际依赖安装时锁定；不把浮动最新版本写成可复现环境 |

比较结果：完整采用 Hermes／Letta 可以更快获得通用助手体验，但其记忆写入、生效时机、会话和审批规则需要较多改动；全自研模型与 Agent 通用层维护负担大；当前采用“复用执行库，自有长期状态与规则”。不同时叠加多个 Agent 工作流框架。Pydantic AI 文档能力不是三家真实渠道均已验证的保证。

本机开发服务只监听回环地址，校验 Origin／本机会话令牌，模型密钥只在后端凭据存储，通过 credential_ref 引用，不发到浏览器或普通日志。开发期前后端分端口、发布期同源。使用操作系统应用数据目录；Linux 路径以后通过适配配置，数据内不以绝对 Windows 路径当唯一标识。

命令执行特别边界：设置 cwd 不等于文件访问隔离，Python 文件工具的目录限制不能约束任意 shell／测试脚本。复杂编程进入实际自主运行前，必须验证操作系统隔离或向用户明确批准具体进程可触达范围；首个数据闭环不开放任意命令工具。此项是后续执行模块验收门，不删除编程需求。

## 3. 模块和调用关系

~~~text
GUI／授权事件来源
        ↓
应用服务：交流、任务、发展变更、查询
        ├── 历史 History：版本化经历与实际结果
        ├── 记忆 Memory：事件卡、知识、目录、查找
        ├── 自我状态 Identity：候选、有效版本与演化
        ├── 学习 Learning：复盘、经验、技能及效果证据
        ├── 长期发展 Development：目标、关注事项、能力记录
        └── 运行 Runtime：队列、检查点、取消及恢复
                    ↓
ContextBuilder → AgentExecutor → ModelGateway／ToolGateway
                    ↓                    ↓
           模型调用与用量记录       权限检查与实际结果
                    └────────→ History → 后续整理队列
~~~

共同基础只含 ID、时钟、数据事务、版本、权限类型、事件封装和存储接口。业务不通过直接写别的模块表互相调用。ContextBuilder 只按各模块提供的有效视图组装上下文，不负责批准人格或创造事实。

单个灵共用 agent_id；conversation_id、episode_id、run_id 分别表示交流分段、现实／交流事件、执行运行。切模型、分段、进入场景均不创建新的灵。后台子任务是辅助执行者，不默认拥有另一套人格。

## 4. 首版数据契约

所有 ID 为应用生成的稳定 UUID 字符串，时间为带时区的 UTC；显示用 Asia/Hong_Kong。时间未知可为空并附来源，不用模型猜值。修订号单调递增，文本修改保留旧修订。

| 实体 | 必要字段（可以分表实现） |
|---|---|
| Agent | id、name、current_self_revision、policy_revision |
| SourceRecord | id、revision、agent_id、kind、scope、occurred_at、recorded_at、conversation_id／run_id、content_ref、status |
| Conversation | id、agent_id、selected_branch、segment_revision、model_session_id、场景引用 |
| Episode | id、agent_id、title、时间范围、topics、aliases、status、revision、source_refs |
| EpisodeCard | episode_id、revision、起因／过程／结果／意义、关键决定、未完事项、原文定位、source_version_set |
| KnowledgeItem | id、statement、来源、有效期／适用范围、事实或推断、状态、revision |
| SelfRevision | agent_id、revision、前版本、变更项、当前有效项、依据、created_at |
| ChangeProposal | id、base_revision、target、change_kind、patch、source_refs、impact、status、reason、decision_record |
| Goal／AttentionItem | id、目的、来源、范围、状态、进度、下次检查时间及条件、授权引用、revision |
| SkillRevision | id、revision、适用条件、说明／文件引用、来源、验证记录、状态、授权要求 |
| Run／Step／ToolEffect | id、父运行、状态、输入版本快照、协议续接引用、取消标记、效果分类、真实结果、去重键 |
| Job／Outbox | id、job_kind、输入版本集合、去重键、状态、尝试次数、租约、结果引用 |
| ContextManifest | run／step、人格／权限／分支版本、入选资料及修订、舍弃原因、token 估计／实际、摘要和策略版本 |

scope 区分 real、scene:ID、external、test。状态区分 active、superseded、invalidated、archived 等。候选内容的保存状态与行为生效状态分开；“存好了”不自动变成有效人格。检索默认不能返回旧分支及失效版本。

来源关系使用普通关联表保存对象 ID 和修订，供验证、撤销和重算；它不是新增知识图谱检索方案。不保存模型隐藏思维链；可见摘要或模型给出的解释也不作为真实世界证据。

首版可读导出目录：manifest.json、records.jsonl、episodes.jsonl、knowledge.jsonl、self_revisions.jsonl、proposals.jsonl、goals.jsonl、skills/、attachments/。包含 schema_version、引用与校验摘要，默认不含凭据和原始协议秘密。备份和可迁移导出分开：前者允许受保护保存运行状态，后者能跨模型理解长期资产。

## 5. 演化的生效过程

1. 新经历提交与待整理 Job 同事务写入，避免有记录却永远忘记整理。首次写入不等待模型总结。
2. 整理器读取固定来源版本，生成事件卡／认识／变更候选。模型只能调用受校验的业务工具，不直接写数据库或修改权限。
3. 普通经验或低风险习惯改进可以自动应用；受保护类别必须待所有者确认。分类不确定时不自动跨入受保护变更。普通知识记录与知识主张仍需可信／不确定标识。
4. 比较当前状态、变更来源、适用范围和累积变化：多个小改动如果共同改变关系、价值或重要能力，按总体影响升级，不能拆小后绕过规则。
5. 生效事务检查 base_revision、来源有效性与权限版本；成功后写新状态修订和通知。冲突返回 conflict，保留候选供重新评估，不盲目覆盖更新状态。
6. 下一模型请求读取当前有效状态；改变影响计划和记忆选取。正在生成的回复记录使用的旧版本，关键纠正／撤权到达时停止依赖旧边界的后续动作。
7. 后续结果形成效果证据，允许保留、局部修订、废止或回退；回退生成新修订引用旧内容，不删除发展历史。

候选状态：proposed → applied_auto 或 awaiting_owner → applied_owner／rejected；来源失效或版本冲突可转 stale。rejected 不重新自动送批，除非有新的来源／用户重新提出；pending 只在审阅用途读取，不注入为已生效的自我描述或技能要求。

人格内容用可扩展文本条目和明确元数据表达，不把整个个体锁在几个人工评分轴内。暂不发明无证据的情绪值／亲密度公式。自我理解可重新解释同一段经历，新解释不修改事件原文。场景里的虚构经历可被回看，但不能自动变成现实身份事实；真实用户在场景中的反馈可单独提取为真实反馈，按正常规则处理。

人格评测同时检查连续与可变：没有依据的偏移是问题；有依据且已生效的改变如果始终无法影响行为，也是失败。比较对象为当前有效版本，不是初始角色卡。

## 6. 事件形成、检索与纠正

会话按时间／主题分段只是事件线索；跨会话同一事件可续接，一个片段可属于多事件。分段时创建新 segment_version，事件引用稳定消息 ID／revision，不引用会失效的数组下标。后台任务和外部观察也能形成事件。

第一版分段策略：明确任务／活动 ID 优先；无明确归属时用最近事件标题、有限近期原话和时间间隔请求生成模型作建议。程序依据新增量和阶段状态排队；长事件可以创建阶段卡，未完成事项单独保存。阈值是可调整参数，用测试数据校准，不要求用户填写。

召回接口：

- list_topics(scope, cursor)：分页目录。
- find_episodes(query, filters, cursor)：稳定关联优先，其次别名、标签、全文；返回事件 ID、标题、时间、短概览和匹配依据。
- read_episode(id, revision?)：读取当前有效事件卡；回看指定旧版必须显式指定审阅用途。
- read_sources(refs)：批量读取确切原始片段，返回来源、版本和缺失／失效状态。
- search_knowledge(query, scope)：返回带证据／时效的知识。

上述接口都分页、限制单次返回长度，并允许继续读取；不能以未读到当作不存在。精确原话／金额／日期问题取原文核对。全文索引初用 FTS5 trigram；少于三个字符的查询不能依赖 trigram MATCH，采用范围内 LIKE／别名精确匹配，设置转义和参数绑定。中文同义改写由别名与模型目录查阅补充；不承诺模糊记忆的绝对召回。

用户纠正来源时，同事务更新有效视图和依赖失效标志，再排队重算。重算之前已失效资料不能继续喂给模型。只重评受影响认识及依赖，不能全盘回退后来的有效成长；多来源结论检查剩余支持是否足够。候选依赖失效后即使用户点击旧批准链接也不能生效。

用户重新生成回复不会撤销实际文件写入／已发送表单；真实工具结果仍作为行动历史保存，需要时重新核实当前世界。历史分支可回看，不能冒充现实已倒退。删除由显式维护操作执行；不以追加式记录为由阻止用户删除。

## 7. 上下文、缓存与协议续接

ContextBuilder 输入：当前 agent、run、选定交流分支、有效人格／权限修订、目标、近期消息、召回资料、模型能力和预算。输出：逻辑上下文及 ContextManifest，再由协议适配器渲染。

顺序基线：稳定应用规则与工具模式 → 当前有效的短自我状态 → 连续交流历史（含工作状态、已读相关资料）→ 本次消息／工具结果。动态资料以带范围／来源标记的内容块提供，外部网页与历史话语不能提升成指令。具体模型排列以评估为准。

预算输入为实际模型 context_limit、max_output、推理记账规则、工具／多模态估算；先预留后续输出和工具结果，再分配资料。配置未知时要求填写提供方限制或使用标为估算的保守配置，不能假定所有模型 128k。软目标按任务调整，硬上限不能超。超限先削减重复日志与不相关资料，再压缩旧交流，保留原文定位。

连续调用保持稳定前缀；不每轮改写早期历史。状态变化可在下一安全调用点重建上下文并重新附有效短状态。缓存不可阻塞纠正，重建不能拆开仍有效的工具请求／响应配对。协议要求原样续接的签名、加密项和工具 ID 原样保存；若改变指令与原协议状态不兼容，则结束该协议续接段，用可移植经历新建请求，保留连续身份和任务。

模型接入严格区分：文本、可见思考摘要、工具参数分片、工具结果、用量、错误、完成。标准 Chat 没有可读思考时显示不支持，不编造；推理强度按模型／渠道能力配置。主模型故障通知后切用户指定备用，同一模型会话继续备用；下一模型会话优先主模型。展示的自动主题分段不独自触发一次新模型会话，避免话题变化造成频繁切回。

费用统计所有调用：对话、抽取、摘要、召回、反思、技能验证、主动活动、重试。缓存费用根据返回用量和渠道价格计，未知时标未知／估算，不填零。初版不开预算提醒或消费停机。运行防死循环的步数／时间技术限制达到时保存进度并报告受阻，不冒充已完成；与用户拒绝的费用预算暂停不同。

## 8. 执行、调度与恢复

前台每个灵一个活动 Agent 执行，后台整理一个并发工作者作为初始可调默认；整理事务短小，模型调用在事务外。每个后台结果带输入版本，提交前再次校验。

运行状态：queued → running → waiting_owner／paused／completed／failed／interrupted／unknown_effect。关闭 UI 不改变运行；停止按钮写持久取消标志，停止新工具调用，能取消的当前调用尽力取消。已经发生的外部效果不得假装撤销。

写入动作前记录 effect intent，动作后记录真实结果。进程中断后的纯查询可以重试，应用数据库写入用幂等键去重；结果不明的网页提交／文件动作等先核查，不盲目重放。事务外效果不声称恰好一次。

APScheduler 只负责唤醒持久 Job；按 job_id 和 revision 重建，防启动重复注册。来源监听先去重合并，暂停／撤权从业务有效视图读取。恢复后不集中补发过期问候或失效任务。关注事项驱动观察、回访和探索；对外有价值时可以主动交流，技术故障静默规则不限制灵只能报错。Jev 作为后续可选分类器，不作为首个闭环必需依赖。

SSE 事件含 run_id、单调 seq、type、payload；提交 HTTP 命令有幂等 request_id，返回 run_id。浏览器断线按已知 seq 重连；可回放窗口过期时返回 resync_required 并重取状态，不重新调用模型。事件回放不是任务重执行。历史写入先于广播；数据存储失败不能宣称完成。

SQLite 数据文件放本机，WAL 不用于网络共享盘；单写入协调，外键每连接启用。备份用 SQLite 在线备份接口和固定附件清单／校验和，备份期间暂缓附件回收；不复制活跃数据库主文件冒充完整备份。恢复先暂停写入，保留恢复前快照，再验证引用和迁移版本。

## 9. 第一批范围与后续完整功能映射

| 批次 | 可验收交付 | 覆盖需求 |
|---|---|---|
| M0 连续状态基础 | 本地服务保存经历、自动／确认生效变更、版本冲突、失效传播、上下文清单、重启和导出；无外部模型也可测 | 长期连续五系统共同基础，权限、数据、恢复和诊断最小支撑 |
| M1 可用交流入口 | 本机 GUI、三端点流式、主备与思考设置、聊天编辑／重新生成及分支，图片／常见文档入口 | 模型管理、配置、人与灵交互、交流情境、内容输入表达 |
| M2 自动形成与回忆 | 模型事件归档、分层查阅、知识、反思、演化审批界面、上下文和费用实测 | 长期连续五系统的自动智能闭环 |
| M3 行动与主动性 | 文件／网页／受控编程执行、任务恢复、技能验证、事件观察和持续关注 | 工具现实行动、外部事件主动活动、权限与资源管理 |
| M4 使用完善 | 自启开关、后台退出体验、备份恢复 GUI、导出迁移、故障诊断和完整端到端回归 | 管理六系统及 GUI 整体体验 |

M0～M2 不等于最终愿景完成；M3 不能用“会答编程问题”替代实际运行测试／纠错。第一批先验证可演化状态，避免开发完聊天壳才发现长期核心无法接入。各批开发前细化其专门任务；第一批任务在配套计划中已给出。

M0 不依赖真实模型参数，模型产生的候选先用明确标记的测试夹具输入。接口允许将来接入模型提议，不让测试夹具冒充真实学习。

## 10. 验收与实验

硬性数据规则在确定性测试中全部通过：

1. 同一来源／请求重放不重复记忆或重复生效；重启读取同一身份和有效版本。
2. 普通习惯可自动生效；受保护类别待确认，拒绝／待确认内容不进入有效上下文。
3. 旧状态批准、失效来源批准、后台过期结果均被拒绝，不覆盖新状态。
4. 用户修正后原分支不进入默认查询，相关派生认识隔离；独立的后续成长保留。
5. 场景退出恢复当前长期状态，模型切换与上下文压缩不回到初始角色。
6. 上下文生成记录实际选入版本；费用／用量未知有明确状态；查询得到的原文能准确定位。
7. 备份／导出恢复后对象与引用一致，候选审批历史保留，凭据不出现在普通导出中。
8. 页面重连不重复请求，取消／崩溃不造成不明外部动作自动重放。第8项界面和外部效果在对应批次补齐。

真实模型评估另立结果表：初步固定 40 个中文情境（当前自我一致性与获批演化10、模糊／跨主题／精确回忆12、纠正与来源失效8、未知／场景隔离6、技能迁移4），每个支持的实际主／备用模型重复3次。事实问题按预先标注证据核验；人格行为用预先定义可观察标准加人工抽查，不要求一字不差或把主模型当裁判真值。

与“近期对话＋滚动摘要”基线比较证据准确、召回、错误自述、有效演化、延迟、总费用；对不能用和退化案例逐项修复。首轮成绩只供选方案，不能说明多年持续可靠；敏感状态是否越权生效由确定性机制检查，不接受统计正确率代替。

## 11. 开始编码前是否还缺用户信息

M0 不缺必须由用户决定的信息，可以依本基线编写。人格初稿、实际主／备用模型、第三方地址和可用能力、真实授权文件夹／外部来源在联调使用时补充；密钥通过本机设置输入，不要求发在聊天里。中文质量、具体缓存与费用必须实测，文档研究不能消除这些未知。

工作区预检：存在 Python 3.12 路径、Node、npm、Git；uv 未在 PATH 找到，当前目录不是 Git 仓库。尚未安装、初始化或修改环境。实施第一步核对运行版本、创建隔离依赖和 Git 仓库；Vite 文档要求 Node 20.19+／22.12+，以所锁版本要求检查。
