## 一、背景与设计理念纠偏

根据所有者对系统本质的最新明确，对早期过度复杂、防御过度的系统设计进行根本性纠偏：

1. **不存在虚构，所有交互皆为事实**
   - 灵不是在一个封闭舞台里角色扮演，而是一个伴随交流真实迭代进化的个体。
   - 人机之间的每一句讨论、每一个指令都是现实中确凿发生的事实。所谓的“防止虚构变成真实经历”属于不必要的过度防御。
   - 灵允许说错话，系统的无黑盒设计以及允许用户编辑/删除消息的功能，就是给人类提供显式纠错的途径。

2. **相信接入的大模型（LLM）的原生理解力**
   - LLM 具备足够的能力区分“人类说的话”与“工具/代码执行抓回来的资料”，因为系统本就有清晰的结构化工具调用记录。
   - 不需要靠代码算法硬生生划定 `real`（现实）、`external`（外部资料）、`scene`（情境）等死板闸门来隔离数据。

3. **拒绝算法死板联动：从“实时级联作废”走向“定期反省沉淀”**
   - **现状弊端**：当前只要用户修改或删除一轮历史对话，底层算法就会启动庞大繁琐的级联追溯链条，强行把以前所有由它生成的记忆、知识、人格全部作废或重算，机制极其臃肿死板。
   - **纠偏逻辑**：长期记忆与人格并不是每说一句话就实时剧烈波动的。真正需要纠偏的，只有当前发给大模型的**即时上下文窗口（Context Window）**。
   - **新范式**：已沉淀的长期记忆和人格允许用户在面板上直接手动纠错；后续的沉淀应当建立在**“定期反省思考”**的基础上，而非实时的算法强级联。

## 二、清洗目标与改造边界

本轮架构清洗的目标是：**砍掉多余机制，让系统变轻、变薄、更直观、更可控。**

| 改造模块 | 当前过度设计现状 | 目标精简方案 |
| :--- | :--- | :--- |
| **交流情境 (Scope)** | 模型提示词强塞 `当前交流情境：real`；数据库和校验到处写死 real，非 real 直接报错。 | **彻底拔除**。提示词移除标签，会话不再做情境校验，检索不再按情境过滤。 |
| **消息编辑与删除** | 删除/编辑一轮消息后，底层触发 `set_visible` 联动回调，把派生的记忆、知识、人格级联置为失效。 | **只管理上下文**。编辑更新当前节点，删除重新连线；仅确保下次发给模型的内容干净，**不再联动搞坏旧记忆**。 |
| **长期记忆与知识** | 必须由 `real` 产生，记忆与原文版本硬绑定，原文变动即报错或作废。 | **解绑级联作废**。记忆成为独立的思考沉淀，支持手动查看与纠偏；不设多余来源情境门槛。 |
| **人格与自我演化** | 严格限制修改来源，仅限 `real` 且通过死板算法过滤。 | **由 LLM 与人工共同维护**。废除情境防线，尊重 LLM 在反省时的自我迭代，配合所有者确认。 |
| **前端界面展示** | 记忆页面下拉框区分“真实经历”与“外部资料”。 | **移除冗余分类**。还原为一体化的记忆列表与直观编辑。 |

## 三、分阶段实施路线规划

### 阶段一：交流情境（Scope / Scene / Real）彻底除名
1. **提示词清洗**：
   - 彻底删除向大模型请求中拼接的 `当前交流情境：real（现实交流）。` 指令。
2. **会话逻辑解耦**：
   - 移除启动对话、获取默认对话时对 `scope != "real"` 的拦截报错。
   - 会话创建与管理直接基于纯粹的会话标识，不携带情境模式。
3. **记忆与档案检索放开**：
   - 移除记忆检索（Recall / Search）中对 `scope` 的强制过滤条件，所有有效记忆按相关性全局检索。
4. **底层与数据兼容**：
   - 内部服务接口不再强制要求提供 `scope`；数据库中的既有列设为可选或平滑过渡，确保老数据无损兼容。

### 阶段二：切断编辑/删除时的过度级联作废机制
1. **纯粹化上下文窗口调整**：
   - 当用户在聊天界面“编辑消息”或“删除某一轮”时，系统职责收缩为：**重新整理对话链条，保证当前处于激活状态的上下文窗口正确反映修改后的结果**。
2. **剥离自动失效回调**：
   - 拔除历史修改对派生记忆、知识卡片的级联失效（`invalidate_derived` / `SourceInvalid`）触发链。
   - 避免因改动一条历史聊天，导致后台一大批记忆突然显示为“依据已失效”或在对话时抛错拒绝生成。
3. **确立人工手动纠错优先**：
   - 如果用户认为某条长期记忆不准确，直接在记忆页面进行编辑或删除；系统算法不代劳进行死板的连带清除。

### 阶段三：重构记忆与人格演化架构（走向定期反省）
1. **确立“定期思考沉淀”机制**：
   - 取消“每收到一条消息就排队进行即时级联提取”的紧耦合模型。
   - 设计轻量级的“定期反省/复盘”机制，由灵在合适的节点（如空闲时、或按用户设定周期）由 LLM 对近期对话与工具调用进行通盘总结，提炼真正的长期记忆。
2. **消除代码层的人格防线桎梏**：
   - 移除人格策略中“必须来自现实、绝不能来自场景”的代码硬校验规则。
   - 相信 LLM 结合结构化工具日志（Tool Calls）本身就能分清客观事实与交流过程。

### 阶段四：前端界面与看板精简
1. **记忆管理面板净化**：
   - 移除 MemoryPage、SourceViewer 等界面上的 `real` / `external` 下拉选择框与标签胶囊。
   - 简化记忆项的展示，突出标题、总结与修改操作。
2. **清理僵尸样式与配置项**：
   - 清理所有遗留的情境相关前端代码、测试 Mock 及废弃文本。

### 阶段五：测试用例重构与工程基准回归
1. **清理陈旧的假想防御测试**：
   - 移除原本用于验证“虚构情境严禁进入记忆”、“非 real 拒绝聊天”的遗留自动化测试。
2. **补充精简架构的核心用例**：
   - 验证：发给模型的 Prompt 干净无情境杂质。
   - 验证：删除/编辑对话后，模型发出的上下文准确更新，且不破坏既有历史记忆。
   - 验证：全量前后端测试通过，确保系统精简后依然稳定健壮。
