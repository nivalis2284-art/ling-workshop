# 开发验证记录

本记录是阶段性证据，不表示完整首版已交付。所有真实模型测试只发送专用短提示；凭据仅在联调进程内通过 stdin 传递，未写入项目或凭据库。

## 核心基础

历史、候选变化、纠正失效、状态回退、上下文、导出恢复、本机 API、知识、目标、模型配置均已有行为测试。各组先观察缺失功能／回归失败，再实现修复。静态检查选择项目虚拟环境。

独立审查发现：已有状态增长后，旧 pending 候选不能拒绝。回归测试复现后修正为审批须比较候选基准、拒绝仅比较当前版本；复核4个相关用例通过。

## 真实模型端点

测试渠道：用户提供的 cf.hetune.top；模型 glm-5.3-flash。没有以模拟协议通过替代真实连接测试。

| 项目 | 结果 | 限制 |
|---|---|---|
| /v1/models | HTTP 200，目录包含目标模型 | 不能由此推断所有能力 |
| Chat 原始流与项目 ModelGateway | complete，正文 OK，收到 reasoning_content | 工具续接／强度档位尚未真实验证 |
| Messages 原始流与项目 ModelGateway | complete/end_turn，正文 OK，可见思考 | 兼容服务的 billing_usage 与计数按原样保留 |
| Responses 原始流 | HTTP 200、completed | 有省略 item_id 的分片 |
| Responses 初版项目适配器 | malformed_stream | 如实保留失败证据，没有冒充成功 |
| Responses 修复后项目适配器 | complete/completed，正文 OK | 仅从已建立 output_index 映射恢复缺失 ID；显式冲突仍拒绝 |

Responses 修复加入15个正反向回归用例，修复前观察6失败9通过，修复后全部通过。三协议夹具测试共77项通过，覆盖分包／UTF-8／工具参数／签名／错误／取消等；夹具测试不证明现实提供方所有能力。

输出预算观察：一次128-token测试几乎全部用于思考，没有正文；扩大至512后短回复完成。这是该任务观测，不是通用的固定最佳预算。

计费观察：服务返回过 prompt=10、completion=164、total=233 等不一致计数；适配器保留原值。没有价格依据，不填写实际金额或凭空纠正账单。缓存命中尚未验证。

有一批三端点脚本因外层观察工具的60秒限制丢失结果；已检查其进程不再存在后改为保留子进程句柄并分批读取，不能把该批记为通过或计入可证明的准确调用费用。
