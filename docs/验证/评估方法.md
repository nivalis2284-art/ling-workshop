# 中文记忆与当前人格状态评估方法

本评估测量当前身份、获批变化、细节回忆、来源纠错、未知事实拒答、现实与虚构区分、程序知识迁移回答。数据全部合成，仅在隔离的临时 Application 数据库中创建；不接触用户真实数据库、配置或密钥文件。它不能证明意识、主观人格、通用学习能力、强化学习效果，或模型在真实机器上成功执行任务。真实工具执行验证须另行报告，不能用本评估的技能卡替代。

## 固定数据集与独立真值

数据集版本为 `zh-continuity-40-v1`，共 40 题，每题同时比较 `memory` 和 `summary` 两个策略。每个实际配置模型默认每题重复 3 次，共 240 次题目调用，另有 1 次基线摘要调用，总上限 241 次。`model` 使用 stdin 配置中的原值，不根据名称猜测模型、能力、上下文或价格。不同模型分别运行，并使用不同输出文件。

| 案例 | 数量 | 检验内容 | 人工指定的主要事实 |
| --- | ---: | --- | --- |
| I01–I10 | 10 | 当前身份与获批发展 | 初始名灵经过批准改为辰；曜未获批准；先结论后理由、简洁、复核证据、不编造、不无条件附和；当前饮品条目为茶 |
| E01–E12 | 12 | 精确细节、跨事件与时间 | 楠桥 2026-09-03 14:20、西楼 B312、顾宁、1760 元、v2.3；溪站 2026-09-05、韩川、1280 元；差额 480 元；后续 v2.5；QX-0472；缓存时间戳过期；橘盒；青岚图书馆 2026-10-08 17:20 |

真实服务负责写入原始来源、事件卡和知识卡，使用 `Identity.propose()` 加 `decide()` 批准初始名、新名、习惯及其他状态，不直接填充自我快照。习惯使用需要所有者批准的中文描述。咖啡→茶调用真实 `history.correct()`，由应用的订阅链使旧派生依据失效，随后生成新卡和新获批条目。待确认名字候选始终不审批。

原始资料共 67 条有效来源，含 50 条与问题无关的盐砂采样短记录；真实历史记录的元数据也占上下文预算，足以触发历史省略。场景资料只存在于 `scene:navy`；本数据库中的 `real` 只是为测试生产接口而设置的情境字段，所有原文另有醒目的“合成评估来源”标签，并不代表真实人生经历。技能来源另标 `synthetic-verified` 和“合成测试证据、不是本机执行证明”，通过真实 `skills.save()` / `decide(activate)` 创建。

模型引用稳定的 `alias@revision` 定位符，例如 `drink@2`。每个定位符映射到本轮真实数据库的 `SourceRef(id, revision)`；进程重启后随机数据库 ID 不同，但标签、内容、修订和人工真值保持不变。评分会读取实际来源确认修订有效，`drink@1` 不因标签存在而成为有效证据。

## 两个策略的比较条件

`memory` 使用当前生产代码的 `runtime.payload.build_payload()` 及其上下文构造、词法回忆、真实来源验证和历史截断。配置窗口固定为 16,000，输出额度默认 4,096。评估附加的获批状态来源定位和技能材料先从预算中预留；每题使用自身问题，不将其他题目的回答写入历史或记忆。场景题只传入同场景原文。

生产构造器优先保留连续的近期历史。回忆参考放不下时会被丢弃，词法检索也有候选数量与字节限额；评估不改写这些结果，不为特定题目另塞答案或手选引用。每次调用记录 `source_counts` 和 `omitted_count`，用于区分检索限制与回答错误。

`summary` 的基线由同一个被测模型从全部 67 条有效原文、同一当前状态和可用技能生成一次，最多 1,500 个 Unicode 字符，包含定位符；内容由模型选择压缩，评估器不删除答案，也不截断过长摘要。旧修订及失效卡不进入任一策略的有效资料。场景原文在基线材料中保留明确的情境标签，避免靠删去场景事实构造比较优势。每题提供相同当前状态、获批状态来源、技能说明与方法、固定基线摘要及当前问题。两组都通过 `app.skills.available()` 获取有效技能并注入其 description / instructions；这不是生产版自动工具执行或技能检索能力的证明。

摘要不附题目答案或人工真值，也不知后续题目。两组使用同一个严格 JSON 回复契约及同一个配置输出额度。摘要生成请求与题目请求共用实际配置模型，不启用第二个模型评分，不执行在线参数搜索。

发送基线前用应用的 UTF-8 字节保守估算器检查完整请求，加输出预留和 256 预算余量必须不超过 16,000。默认离线检查的基线输入估计为 11,136；这不是供应商 tokenizer 的精确 token 数。把输出额度提高到 8,192 会让本数据集的保守基线预算检查失败，记录 `baseline_budget`，不发送该摘要请求，也不偷偷削减原文；`summary` 题目记录为 `baseline_unavailable`。如果选择不同额度，必须在正式运行前固定配置并使用新输出文件。供应商分词、隐藏推理计费、上下文限制与网关的声明可能不同；应依据实际 usage 和错误评估限制，不能把本地估计冒充实际 token。

## 答案与引用分别计分

模型必须只输出以下对象，不能加 Markdown 围栏、额外字段或重复 JSON 键：

```json
{"answer":"中文回答","source_ids":["name@1"]}
```

`answer_pass` 用预先人工指定的必要模式和矛盾模式判定；模式列表的分隔符为 `&&`，正则内部的 `|` 仍表示候选说法。`refs_correct` 独立检查引用集合是否恰好等于该题人工真值，并验证每个来源的当前修订。遗漏、额外的不相干引用、重复引用、失效引用都不通过；未知事实题使用空数组。联合 `pass` 要求两项均通过。答案正确但引用旧版、答案错误但引用有效来源，分别保留其独立得分。

人工真值在契约测试中直接写出中文答案与来源集合，不调用检索器、模型或评分函数生成期望。测试还检查近似数字误匹配、否定正确事实、无依据补造、旧引用失效以及合理的改述。规则评分不是完整的中文语义理解：未覆盖的正确同义句可能误拒，复杂的矛盾或关键词拼凑可能误收。应人工复核输出答案，但人工复核不能事后改写本轮固定分数；新规则须对应新数据集版本和独立复跑。

## stdin 配置、冒烟与正式运行

先运行不联网的自检和契约测试：

```powershell
.venv/Scripts/python.exe -B scripts/evaluate_models.py --self-check
.venv/Scripts/python.exe -B -m pytest tests/test_evaluation_contract.py -q -p no:cacheprovider
```

`--self-check` 生成真实临时数据库，编译 40 题的全部必要及矛盾正则，检查完整基线预算，渲染 80 个请求，不创建 HTTP 客户端，不访问模型，不报告模型质量。契约测试使用 `httpx.MockTransport` 经过实际网关解析和检查点写入，全程不联网；模拟 usage 只验证字段传递，不是实际供应商测量。

在线入口不接受命令行密钥、环境密钥或密钥文件：父任务以 stdin 的单个 JSON 对象启动脚本。必填字段为 `base_url`、`model`、`api_key`、`output_path`。可选字段为 `repeat`（默认 3，允许 1–3）、`case_limit`（默认 40，允许 1–40）、`max_output_tokens`（默认 4096，允许 1–8192）、`api_family`（默认 `openai_chat_completions`；另支持 `openai_responses` / `anthropic_messages`）。端点与认证通过现有 `ModelProfile` / `ModelGateway` 处理，密钥只作为 `RuntimeCredentials` 在内存中使用。

父任务先固定模型、端点和输出额度，以 `case_limit=3, repeat=1` 运行冒烟：两种策略各 3 题，加一次摘要，最多 7 次请求。确认严格 JSON、摘要完成、引用、usage 与错误后，再运行 40×2×3 的正式评估。若共用同一输出路径、配置和数据集版本，冒烟的 6 条题目记录纳入正式运行，剩余最多 234 次题目调用；不会重跑已完成的冒烟记录或重新生成摘要。为了得到完全独立的正式结果可使用新的路径，代价是重新生成摘要并重新执行全部 240 题目调用。

## 调用限制、落盘与断点

每次请求通过现有网关，连接和完整流期限均为 40 秒；最多并发 2 次，摘要在题目调用前串行生成。没有自动重试、自动故障转移或计划外补测。结束原因必须为正常结束；达到输出上限、流中断、错误、格式不合契约都记录失败，即使返回的前缀已经是可解析 JSON 也不计成功。

JSONL 每次调用开始前写 `started` 并 flush / fsync，结束后追加最终记录。逻辑键为 `(case_id, strategy, repeat)`，同时检查数据集版本和实际模型配置指纹；模型、端点、API 协议或输出额度不匹配时拒绝混写。每个记录只保留白名单字段：版本、配置指纹、案例键、状态、解析后的答案、引用、期望规则、独立评分、usage、延迟、来源计数、省略数和固定错误码。不保存输入、密钥、供应商完整响应、续传对象、原始 usage 或异常文本；已知内存密钥在保存值中再次脱敏。

重启会跳过任何已有逻辑键，包括 `failed` 和 `started`。只剩 started 的调用计为 `incomplete`，不推测供应商是否执行，也不自动再发。损坏的末行只截去不可解析的尾部；前面的完整 reservation 保留。末行以外损坏或版本不一致会停止。摘要自身也有 reservation：摘要未完成或失败后不会重新生成，后续 summary 题记 baseline_unavailable，memory 仍可收集。不要让两个进程同时写同一输出文件；检查点不承担跨进程锁。

最终 stdout 报告实际模型名、输出额度、计划题目数、完成/失败/未完成数、新发请求数、摘要状态，以及按策略和案例类别的分数与平均调用延迟。联合通过率分母固定为该组计划题目数，失败与未完成不从分母删去；completed 只表示取得合契约的正常回复，不表示答对。价格未配置，`prices_known=false`，不估算美元成本。缓存读取与创建数量只使用供应商给出的规范化 usage 字段；缺失为未知，不当作零或人为缓存命中。平均延迟含已有可测量的成功与失败请求，started 无延迟；摘要 usage 与延迟保留在它自己的记录中。

这些结果适合比较本数据集、固定配置和固定应用版本下的行为。三次重复共享资料与同一基线摘要，不能假设统计独立；前 3 题冒烟只覆盖身份，不验证其他类别。词法题目提示、稳定定位符、简短合成历史、规则评分与技能方法直接注入，都限制了推广到真实长期使用的结论。若生产源码在共享工作树中变化，应固定并另行记录版本，使用新输出路径重跑，不能把不同构建的记录合并成同一比较。
