# 安全地批量修改文件

同一处改动落在很多文件里时，最大的风险不是改错，而是**改了不该改的**或**漏改**。
按下面的顺序做，每一步都能被看见。

## 1. 先摸清范围，不要先动手

- 用 `search` 查要改的字符串（`match: "content"`），必要时开 `regex`。
- 记下命中总数。如果结果被截断（返回里有 `truncated`），说明范围比看到的更大，
  先缩小查询（加上目录或更长的上下文），不要凭部分结果开改。
- 对不确定的文件，先用 `read_file` 看命中处附近的原文。

## 2. 一次一个文件地改

- 用 `edit_file` 改。它要求原文片段**恰好出现一次**，这正是你要的保险：
  - 报 `text_not_unique` → 说明片段太短，补上更多上下文再试；
  - 报 `text_not_found` → 说明文件内容和你的预期不一致，回头重新读。
- 只有在确认同一片段在本文件里重复且**每一处都该改**时，才用 `replace_all: true`。

## 3. 改完必须复核

- 再跑一次第 1 步的 `search`，期望命中数降到 0（或降到预期的剩余数）。
- 抽查 2–3 个改动过的文件，用 `read_file` 确认结果。
- 有测试就运行测试；能跑校验命令就用 `run_command` 并设 `purpose: "verify"`。

## 不要做

- 不要在没搜出全部命中的情况下开改。
- 不要用一条命令直接覆盖式重写多个文件。
- 不要把"没报错"当成"改对了"——复核是这一步的一部分。
